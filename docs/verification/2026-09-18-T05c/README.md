## 1 · 这张卡做了什么

T05a 已经把库存的**约束**测通（重复 SN 拒绝、未知成本为 NULL、客户财产边界、数量守恒），但那些是 SQL 与测试代码，读不到、也用不到界面上。本卡把这些约束落成 `contracts/v1/fixtures.json` 的 **V5 数据集**，让两端界面和后续业务卡有一份共同依据。

**一句话：约束从「只有测试知道」变成「契约里写着的样本」。**

## 3 · 关键判断（后续卡必须遵守）

### 3.1 样本不得发明契约外字段 —— 本卡已自我纠正一次

初稿在 `stockItems` 里加了 `acquiredAt`（入库时间），用来支撑 02 §5 要求的「库龄」列。这是**错的**：`fixtures.rules` 第 2 条写明「本文件只提供数值与期望，不重复定义字段类型」，而 `objects.json` 的 `StockItem` 没有这个字段 —— 样本发明契约外字段，等于用样本给契约加字段，两端生成器也不会产出它。

已移除，并把「库龄没有契约字段支撑」登记为 **G-18**（OPEN-ITEMS §2）。T05b 的库存表因此**不画库龄列**。

### 3.2 数量守恒写成了可机械重算的门禁

`fixtures.rules` 第 5 条要求「逐项核算由校验脚本机械重算，禁止只在文档里声称已核对」。故新增的检查不是「读一遍对不对」，而是真的按 `to_bucket +qty / from_bucket −qty` 把 8 条流水聚合一遍，逐商品逐桶与余额比对。
