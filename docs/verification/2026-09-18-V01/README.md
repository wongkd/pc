## 1. 本卡做了什么、没做什么

**做了**：统计条从「五张独立白卡片」改成紧凑横栏；待办行加 45×53 缩略图并压缩行高；详情设备图从 88×88 放大到规格要求的 220–244px 并与处理区并列；金额与主动作从横跨整宽移入处理区；页头补日期块。

- 设备看板改成 3 列大图网格 —— 设计稿 `hybrid-devices-desktop.png` 确实是 3 列大图，但那是**结构性改造**（tab 切换要重排整页网格），不属视觉对齐。
- 顶部品牌块（`AppShell` 的 PC 标识 / 门店副标题）—— 改动会波及库存页与落地页。
- 冻结契约、后端、两端金额口径、任何业务计算。

## 2. 一个前置事实更正：本机可以做浏览器视觉验收

`docs/OPEN-ITEMS.md` §6 此前把「浏览器视觉验收」记为**未运行，理由是本机无 Playwright 等浏览器自动化**。这条理由不成立：

- 仓库根 `node_modules/` 里**已装 puppeteer**（上一轮 `docs/design/2026-09-18-assets/verify.cjs` 与 v3 原型的 `verify.cjs` 都真的跑过截图）；
- 本机有 Microsoft Edge，`puppeteer.launch({ executablePath: '…/msedge.exe', headless: true })` 可用；
- 截屏走的是 `page.screenshot()`，**不受**本机安全策略对 `Add-Type` / 反射 / COM 三种 Windows 截屏途径的限制（那是小程序截图的问题，与网页无关）。

所以本轮补上了这条通道：`verify-desktop-today.cjs` 是**可重复运行的**验收脚本（不登录、不连生产，只挂本地组件 + 本地图片 + 演示样本），改前 / 改后同口径各跑一次。

⚠️ 证据等级：它证明的是**本地隔离演示页在 Edge 下的渲染**，不等于微信开发者工具、真机、或生产登录后的页面。

| 命令 | 结果 |

改后 45 项含：5 个视口 ×（无横向溢出 / 统计 5 格 / 统计格不裁切 / 待收款金额完整渲染 / 设备图加载 / 待办行不横向溢出）、4 个视口 × 主动作首屏可见、看板 7 张卡与 7 张缩略图、图片失败降级（占位 + 仍标「AI 示意 · 非实拍」+ 设备名仍在）、搜索无结果空状态与清空详情、键盘焦点、点击统计格仍筛选、禁用主动作仍显示阻断原因、无 JS 错误。

「点击统计格仍筛选」这一项在**改前基线里曾误报失败**：脚本在同一次 `page.evaluate` 里 `click()` 后立刻读 DOM，而 React 在微任务里 flush —— 属脚本缺陷，已改成点击后 `waitForFunction` 等待。记在这里，避免下次误判成应用 bug。

截图（同尺寸、同口径，改前 / 改后各 7 张）：`screenshots/`。原始回执：`logs/before-report.json`、`logs/after-report.json`。

⚠️ `logs/` 里还留有 `after-run.log`（23:57:26），那是**脚本修正前的中间运行**（47 项、2 项失败）：当时「主动作首屏可见」这一条还没有 `width >= 1366` 的判定守卫，1024×768 被错误套用了 02 §65 的桌面主验收要求。脚本于 23:58:05 修正后重跑，结果即 `after-run-2.log` / `after-run-3.log` / `after-report.json`（45 项、0 失败）。**以 `after-report.json` 为准**，中间那份保留只为追溯，不要当成当前结论。

## 6. 仍缺什么、为什么没画

| 项 | 为什么没做 | 归属 |
|---|---|---|
| 待办行高 123px（设计稿 81px） | 设计稿列表行只有 3 行（客户·设备 / 卡点 / 时间+动作）且**不显示单号与金额**；本实现按要求额外保留「单号 + 金额方向」两类信息，5 行是这个信息量的物理结果。左栏文案区仅约 226px，放不下「单号 + 期限 + 金额」一行（实测会把单号拆成两行、期限挤成「今天 1…」），已改为金额与标签同排、底行只留单号与期限 | **D-K 已裁定「维持现状」**（2026-09-19，留档 OPEN-ITEMS §7 R-19）：常驻「单号 + 金额方向」，**接受 123px**。设计稿 81px **不再作为缺口或未达成项** |
| 期限在长文案时仍被省略（如「预计 17:30 到货（…」） | 同上宽度约束。完整值由 `title` 与详情页提供，不靠截断藏信息 | 随 D-K 维持现状，不再单独处理 |
| 横向阶段条（设计稿有勾选式 stepper） | 现状是**硬编码销售三步**且靠「有没有卡点」推测状态；`visual-gap` 明确「有明确数据依据才画业务进度，否则保留诚实占位」，且 v3 README 指出「不能给所有设备显示同一张交付检查表」 | **D-G / T08 / T12 / T14** |
| 可勾选检查清单 | 不能从「2/3」文案反推检查项 | 详情读模型 + 业务动作 |
| 配置 / 客户资料 / 照片 / 处理记录入口 | 缺数据记录依赖，不造空壳成功提示 | T07 / T08 |
| 「查件 / SN」入口（02 §78 第五项） | 需真实目标页；本卡不新增业务入口 | T18（全局搜索）/ 待定 |
| 设备看板 3 列大图网格 | 结构性改造，非视觉对齐 | 另开子卡 |
| 顶部品牌块与导航密度 | 改 `AppShell` 会波及库存页与落地页 | 另开子卡（需先确认影响范围） |
| 1024×768 主动作不在首屏 | 详情在该宽度转单栏，内容天然超屏；02 §65 的「首屏可见」是 1366×768 主验收尺寸的要求 | 无（判定口径已写入脚本） |
