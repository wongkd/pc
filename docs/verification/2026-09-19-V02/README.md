## 3. 发现并修复的真实缺陷：表头与数据行整列错位

### 症状

库存表格的表头标签**每一列都比数据偏右**，越靠左偏得越多。1440 下「管理」压在型号列上、与「逐件管理」错开 40px。这不是审美问题 —— 表头与数据不对齐会让整张表读串列。

### 实测（同一脚本，改前 → 改后，1440×1000）

| 列 | 表头 left（改前） | 数据 left（改前） | 错位 | 改后 |
|---|---|---|---|---|
| 型号 | 49 | 49 | 0 | 49 / 49 ✅ |
| 管理 | 833 | 793 | **40px** | 793 / 793 ✅ |
| 可卖 | 943 | 911 | 32px | 911 / 911 ✅ |
| 已订 | 1011 | 987 | 24px | 987 / 987 ✅ |
| 待处理 | 1079 | 1063 | 16px | 1063 / 1063 ✅ |
| 位置 | 1163 | 1155 | 8px | 1155 / 1155 ✅ |
| 成本 | 1259 | 1259 | 0 | 1259 / 1259 ✅ |

错位量从 40 递减到 0，每次减 8px —— 这正好等于 `--wb-s2`。

7 个视口**全部复现**（改前 7×2 = 14 项失败）。

### 根因

```css
.wb-inv-head,
.wb-inv-row {
  display: grid;
  grid-template-columns: minmax(220px, 1.6fr) 110px 68px 68px 84px 96px 132px;
  /* ← 这里没有 gap */
}
.wb-inv-row {
  gap: var(--wb-s2);   /* ← gap 只写在行上 */
}
```

表头与行**共用同一份列定义**，但间距只有行有。grid 解析时，行要先扣掉 6 个 gap（6×8=48px）再分配第一列的 `1.6fr`，于是：

- 表头第一列 = 784px
- 行第一列 = 736px

差 48px 被逐列均摊递减，到最后一列（固定宽、右边界相同）归零。

### 修法（根因级，不是补丁）

把 `gap` 提升到**共用规则**，并移除行上的重复声明 —— 让「列定义 + 间距」由同一条规则管，而不是两处各写一份（这正是缺陷的成因）：

```css
.wb-inv-head,
.wb-inv-row {
  display: grid;
  grid-template-columns: minmax(220px, 1.6fr) 110px 68px 68px 84px 96px 132px;
  gap: var(--wb-s2);
}
```

只让表头也加一份 `gap` 也能修好当下，但两份定义仍会再次漂移 —— 所以选择并轨。同一条注释已写在 CSS 里，避免后人再把 gap 写回单独规则。

### 验证

| | 改前 | 改后 |
|---|---|---|
| 表头 grid 解析值 | `784px 110px 68px …` | `736px 110px 68px …` |
| 行 grid 解析值 | `736px 110px 68px …` | `736px 110px 68px …` |
| 逐列错位 | `[0,40,32,24,16,8,0]` | `[0,0,0,0,0,0,0]` ✅ |
| 验收失败项 | 14 | **0** ✅ |

### 顺带澄清一个曾被怀疑的区间

`.wb-inv-head/.wb-inv-row` 的 7 列最小宽约 858px，而收敛到 5 列的断点只在 `max-width: 1024px` —— 事先怀疑 **1025–1100 区间会横向溢出**。**实测不成立**：1100×800 下表格 `overflowX = 0`，型号列收到 412px、列宽合计 1018px，容器仍容得下。故本卡**没有**新增中间断点（避免为一个不存在的问题加规则）。

### 环境坑（新记录）

**不要在同一个仓库并行跑 `frontend run test` 与 `frontend run build`**：两者争用 vite / rolldown 缓存，构建会以 `unwrapBindingResult` 堆栈失败；单独重跑即成功（`✓ built in 1.01s`）。首次并行失败曾被我误当成 CSS 语法问题，实际与代码无关。
