# 员工邀请与逐域权限复验

- 日期：2026-09-25
- 状态：**本地真实 Worker / 内存 D1 的员工邀请、接受、单独登录和 HTTP 权限矩阵通过；发布候选整体验收仍未通过。**
- 目标：核清未指定角色时的 409 前置条件，再按真实路由复验员工会话与域权限。
- 入口：本目录；本地预览角色种子在 `backend/scripts/dev-server.mjs`，可重复验收脚本在 `backend/scripts/verify-staff-invitation.mjs`。

## 原因与修复

`/api/auth/accept-invitation` 在邀请没有 `roleId` 时，按邀请所属门店查找 `roles.code='sales'`；查不到才返回 409。`0001` 只创建 `roles` / `permissions` 等表，没有角色或权限数据种子；测试夹具通常逐测试按需插入角色。此前 `dev-server.mjs` 只创建店主和业务演示数据，临时内存库没有 `sales` 角色。因此旧回执的 409 与**临时库缺少默认角色数据**一致，不能单独证明接受邀请代码有缺陷。

本次仅给本地预览播种一条 `sales` 角色及其显式权限行，保持邀请省略 `roleId` 的既有行为。销售演示角色可看/编辑报价和销售、访问客户，并可读库存与采购；不获库存写入、销售收款、财务、售后、回收、置换或成员/角色管理权限。该集合是本地验收夹具，**不代表生产或 Cloudflare 预览的角色政策**；未改迁移、契约、权限判定或远端数据。

## 复验环境与命令

- 环境：`127.0.0.1:8878`，Miniflare 跑当前真实 Worker 入口和全量本地迁移，D1 为内存库，不连接远端。
- 启动：`$env:PORT='8878'; node backend/scripts/dev-server.mjs`
- 复验：`node backend/scripts/verify-staff-invitation.mjs`
- 结果：**30 项断言通过**。员工邮箱由脚本随机生成；邀请请求不含 `roleId`；接受会话和接受后独立登录均成功，`/api/auth/me` 两次均返回 `sales` 角色及相同权限集合。
- 测试建立的员工账号、邀请和会话只在该内存库中；关闭 Worker 即清空。本轮结束时停止了自启服务。

## 权限矩阵

| 域 | 只读结果 | 写入边界 | 结论 |
|---|---|---|---|
| 报价 / 销售 | 报价、销售单 GET 均为 200 | 空载荷报价/销售单 POST 到业务校验后为 400；销售收款 POST 为 403 | 可访问授权销售能力，未取得收款权 |
| 客户 | `GET /api/customers` 为 200 | 空载荷 POST 到业务校验后为 400 | 客户读写授权命中；未创建记录 |
| 库存 | `GET /api/v2/inventory` 为 200，响应不含逐件/汇总成本键 | 商品、期初写入均为 403 | 可读库存，不可写库存或成本 |
| 采购 | 采购列表 GET 为 200 | 创建采购 POST 为 403 | 可读采购，不可创建 |
| 售后 | 工单列表 GET 为 403 | 接修 POST 为 403 | 无售后权限 |
| 回收 | 回收单列表 GET 为 403 | 新建 POST 为 403 | 无回收权限 |
| 置换 | 创建 POST 为 403；当前列表 GET 返回 405（路由不支持 GET） | 创建 POST 为 403 | 以真实受保护写动作确认拒绝；405 不作为权限结论 |
| 财务 | 汇总 GET 为 403 | 付款 POST 为 403 | 无财务权限 |
| 成员 / 角色 | 成员列表与角色列表 GET 均为 403 | — | 无平台管理权限 |

空载荷的三个已授权 POST 都在业务校验阶段返回 400，没有创建报价、销售单或客户。八个未授权写动作均在权限守卫返回 403。

## 未验证范围与下一步

- 本轮是 HTTP 路由级验收，没有做员工登录后的浏览器逐页显示/隐藏检查；也没有连接 Cloudflare 预览或生产去检查其实际角色种子。
- 发布候选旧回执中的销售到交付、售后/回收完整浏览器主链、客户保存、刷新与错误恢复等缺口仍在；继续按[整体验收矩阵](../2026-09-25-release-candidate-acceptance/README.md)完成后再判断放行。
- 若另一个隔离 D1 仍无 `sales` 角色，应先在该环境补齐经确认的角色数据，再重试邀请接受；本地演示种子不会自动修复远端环境。
