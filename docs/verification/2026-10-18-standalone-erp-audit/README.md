## 结论与独立运行边界

**网页 ERP 可以脱离小程序运行，不必等小程序完成后才继续建设和验收。**

网页使用自己的账号密码、员工邀请、门店与权限链；报价、销售、采购、库存、交付、售后、回收和账本通过网页直接调用后端。报价可以记录线下确认，收款可以登记已实际核实的线下到账。小程序登录、微信线上支付和顾客自助查单未完成，不构成上述人工经营路径的运行依赖。

独立于小程序仍需要后端、数据库和附件存储。当前有两种宿主：Workers / D1，以及测试用途的 Node / SQLite / 本地附件适配器。默认 `dev:local` 是进程退出即清空的内存演示库，不适合作为正式账本；Node 宿主也还需要正式化收口。

本轮从 `frontend` 独立执行测试和构建，未启动、构建或配置小程序。判断依据：

- [网页路由](../../../frontend/src/App.tsx)、[账号登录](../../../frontend/src/components/LoginPanel.tsx)、[开发代理](../../../frontend/vite.config.ts)。
- [报价页面](../../../frontend/src/features/workbench/WorkbenchQuotePage.tsx)：确认来源默认 `offline`，支持记录顾客确认并转销售单。
- [后端入口](../../../backend/src/index.ts)、[报价接口](../../../backend/src/routes/quote-v2.ts)及 [Node 宿主](../../../backend/scripts/node-host.mjs)。

本轮还在独立回环端口启动真实后端入口的 Node 宿主，使用新建隔离 SQLite 文件和附件目录：匿名工作台返回 401；账号登录及鉴权工作台返回 200；新建合成客户后读回成功；关闭宿主、沿用同一数据库重启、重新登录后仍可读回同一客户。全程未启动小程序、未连远端。结果见 [本轮摘要](standalone-smoke-report.json)。这只证明本地 HTTP 登录与一条客户数据的重启持久性，不覆盖浏览器、资金库存全链、附件重启或生产验收。

## 独立 ERP 剩余工作

优先级是本次核查建议；不表示已授权部署或要求把所有暂缓功能塞入首发。直接衔接缺口已定位源码；批次追溯、成本报表等长期待办结合现行状态与专项方案核对，本轮未逐一重跑其专项验收。

| 优先级 | 事项 | 本轮确认的状态 / 影响 | 下一步 |

| P0 | 正式运行环境与数据持久化 | 默认本地库是内存演示库。[国内站历史回执](../2026-09-29-zhuangji-domestic-deploy/README.md)也明确其为演示站、域名与证书入口未闭环。本轮未访问远端，不据此断言线上现状 | 明确正式使用 Workers 还是国内宿主，重新核对持久化库、附件、合法可用的访问入口及目标版本 |
| P0 | Node 宿主正式化 | 当前 `buildEnv` 固定使用测试 JWT 配置和 `preview` 库存模式；只有新库才调用 `applyMigrations`，已有 SQLite 文件不会因重启获得新迁移 | 如采用国内宿主，先改为受控环境配置、缺失即拒启，并补有版本记录的增量迁移与回滚/备份流程；不能用重建业务库升级 |
| P0 | 员工与经营主链验收 | 既有本地浏览器证据覆盖部分主链；当前正式版本的员工菜单/页面权限、完整失败恢复和生产只读验收未闭环 | 在隔离持久化环境，用老板和普通员工跑报价→收款→采购/到货→交付→售后/退款；核对刷新与重启后回读 |

## 两个源码确认的衔接缺口

1. 欠款交付：销售页 [WorkbenchSalesPage](../../../frontend/src/features/workbench/WorkbenchSalesPage.tsx) 能审批；后端 [sales-v2](../../../backend/src/routes/sales-v2.ts) 和 [assembly](../../../backend/src/domains/assembly.ts) 支持有效欠款批准引用；网页 [fulfillment-api](../../../frontend/src/features/workbench/fulfillment-api.ts) 的交付载荷没有该引用，[fulfillment-view](../../../frontend/src/features/workbench/fulfillment-view.ts) 仍只按尾款结清判断资金闸门。后端具备能力，网页操作尚未闭环。
2. 检测照片：`assembly.ts` 检测输入明确拒绝非空 `resultEvidence`。接修/回收能上传附件，不能作为装机检测照片可用的证明。

另外，`recovery-api.ts` 等文件仍有“采购付款尚未实现”的旧注释；已有采购付款代码与测试，不将该旧注释重复列为功能缺失。
