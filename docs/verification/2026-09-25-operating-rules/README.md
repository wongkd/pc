# 经营规则 D01–D10 实现与守卫核验

日期：2026-09-25  
状态：本地源码与定向回归已核验；未进行生产操作、部署或顾客端验收。

## 目标与范围

按已确认的经营口径逐项检查首发实现和服务端守卫，并把尚未开放的动作明确标为暂缓。规则原文及费率以[老板确认规则 R1](../../plans/2026-09-23-owner-decisions/README.md)和[D07 R1.2](../../plans/2026-09-23-owner-decisions/d07-warranty.md)为准；本回执记录实现状态，不改写经营口径。

## 逐项结论

| 规则/动作 | 首发结论 | 已核实现状与边界 |
|---|---|---|
| B39 报损（D01） | **暂缓** | 操作仍未开放。B16 盘点批准若实盘少于锁存账面数，服务端拒绝，不写库存调整；不能以盘点下降绕过报损流程。 |
| B40 改价（D02） | **暂缓** | 已有商品的默认售价不能经库存 v2、旧 `/api/products/:id` 或旧 `/api/library/:id` 通用编辑修改。建档时录入初始售价，以及报价版本中的报价金额，仍是各自业务动作，不等于改商品主数据售价。 |
| 供应商真实退款/贷项（D03） | **暂缓** | 没有接通供应商退款到账、供应商留存贷项或差额核销。B34 仅是纠正误录账务的反向分录，不能代表真实退款，也不能冲账凑零。 |
| 自动配送计费（D05） | **暂缓** | 不做距离自动计费或自动收款；报价条款不能藏正配送费。人工明确报价行仍由员工逐单录入，不代表距离阶梯、距离证据、改址补退差或配送履约已实现。 |
| 15%预付款与库存预留（D06） | **首发实现：订单规则** | 应付大于零时，门槛固定按最终应付金额的 15% 计算，分向上取整；旧报价里的自定义比例不能改门槛。已人工核实的净收款加同客户、同销售单的有效折抵达到门槛后，才能确认并尝试预留库存；折抵不冒充现金。未核实款项和纯客供零金额单不能占库存。**此前置换折抵仅允许关联已成交订单，会让“折抵计门槛”陷入循环依赖；现已允许草稿先建立折抵，确认前仍不预留。**已存在折抵的销售单须先按 B32 撤销，再取消并结算，防止把非现金折抵误计为现金应退。当前没有接通真实支付渠道，到账核实仍由员工手动确认。 |
| 顾客销售退款登记（B18） | **首发实现：老板人工核实后登记** | 退货获批后，登记按钮要求老板重新勾选“已核实实际退款付出/到账”；申请中、处理中或结果未知时界面不可提交。B18 是完成退款后的登记动作，只写已核实退款流水，不支持申请中/未知状态。权限为老板专属；系统没有支付渠道查询，B18 记账本身不独立证明银行/支付渠道结果。后端把每次获准的 B18 调用作为“实际退款已核实”的人工记账，前端复选框是人工守卫，调用者要对外部实际退款结果负责；外部结果未知时不得调用 B18。若 B18 接口响应未知，页面要求先查操作结果，不重复提交。 |
| 基础质保文案与快照（D07） | **首发实现：报价/订单留档** | 报价版本保存适用规则文本，成交转单校验并将同一版本条款保存到销售订单；销售详情只返回基础质保字段白名单。旧数据缺快照时显示缺失提示，不补写新规则，也不覆盖历史更优承诺。 |
| 延保购买、收费及订单履约（D07） | **暂缓** | 延保费率文案已采纳，但首发不提供延保选购、收费或履约。报价和零售建单守卫拒绝把延保作为已承诺的收费项目；不能仅因报价显示费率就登记为已购或收款。 |
| 顾客查看订单质保 | **尚未实现** | 当前销售详情是员工侧读路径。B36 的顾客安全 HTML 是报价快照文件，下载仍限内部权限且不会自动发送；目前没有顾客身份约束的销售订单详情/质保读取入口。因此已确认订单里的质保规则尚不能由顾客端直接查看。 |
| 正式期初成本放行（D10） | **本地正式流程已实现并验收；生产未放行** | 成本四分类、唯一盘点行引用、1–7 天单次窗口、首笔经营流水关窗已在隔离 HTTP 与浏览器验证。详见[D10 正式期初回执](../2026-09-25-d10-formal-opening/README.md)。生产尚未部署或验收；未知成本销售例外、估值毛利单列报表和关窗后追加调整仍未实现。 |
