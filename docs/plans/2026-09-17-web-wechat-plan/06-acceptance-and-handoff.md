## 5. 性能与可用性目标

这些是试用目标，不是当前结果，也不把网络差造成的时延掩盖成“必达 SLA”。

- 店内网络 / 普通移动网络分别测 20 次冷启动、待办读取、详情和写动作：记录 p50 / p95、失败率；目标首屏主要可用内容约 2 秒内，普通操作反馈立即出现，服务响应目标 p95 不超过 2 秒。
- 500 条历史任务用分页，单页 20；图片先缩略图，主图按需取。超过目标先定位网络 / 查询 / setData / 图片，再优化，避免先引入大缓存和全新框架。
- 常用模板配置争取 2 分钟内形成报价，简单零售约 30 秒，SN / 手机号定位约 10 秒；找 3–5 次真实任务观察，不由开发者只演最快路径。
- 检查主包、分包、未使用资源和代码体积，实际限额以当时官方规则及工具扫描为准，不在此预写“低于某阈值已通过”。
- 存储 / API 网络不可达或不稳定时，先记录域名、网络、失败环节。不能靠关闭合法域名校验宣布可上线，也不擅自更换生产云服务。

## 8. 迁移与生产切换预案

1. 盘点本地 / 真实来源、迁移追踪、现有权限和外部服务，脱敏副本先跑通。
2. 备份数据库和文件引用清单，验证哈希及本地恢复；确认旧单只读 / 未结单迁入边界。
3. 实盘新品数量、二手逐件、客户送修 / 暂存、已收 / 待收、回收待付；未知项进入人工核对，不制造数据。
4. 老板完成脱敏真实业务试用与单据核对，形成具体发布范围和回退触发条件。
5. 获后续发布授权后才安排停止旧写入、末次增量、迁移、兼容服务与双端发布；小程序审核和体验版按实际平台流程。
6. 回退优先关新写入口、保留数据和日志、恢复兼容代码；导出切换后增量核对，不能用旧备份直接覆盖新交易。
7. 原单据 / 旧系统保留只读直到对账完成；代码回滚、数据库恢复、现金 / 实物修正三者分开处理。
