# 02 · 双端页面与视觉规格

日期：2026-09-17。状态：拟实施规格。入口：[方案总览](./README.md)。

## 1. 视觉必须保留什么

参考[电脑图](./references/desktop-reference.png)和[手机流程图](./references/wechat-flow-reference.png)。保留暖纸色、森林绿、自然设备照片、衬线大标题、细分隔线、低圆角、宽松但有信息密度的布局。只在页标题、设备名和少量大金额使用衬线；表单、列表、操作和 SN 用清晰无衬线字体。

不要增加大面积渐变、悬浮玻璃、多彩统计卡、复杂阴影、大圆角胶囊或满屏图标。原型中的 9–11px 小字需要提升可读性；视觉相似不等于照搬过小字号。“示例数据”“A+B 手机操作”“打开可操作原型”属于评审环境，不是生产页面内容。

### 设计变量

| 变量 | 目标值 | 用途 |
|---|---|---|
| paper | #F8F6EF | 全局底色 |
| ink / primary | #334B42 | 正文、主按钮、选中强调 |
| muted | #687365 | 次要信息，不能用于关键操作的极小字号 |
| line | #D9DDD0 | 分隔线；输入边框 / 焦点需要更明显 |
| sage | #E8EDDE | 选中任务、完成检查区域 |
| photo | #ECE9DE | 照片占位 |
| surface | #FFFEF9 | 弹层、输入背景 |
| warning / warning-bg | #826021 / #F1E9D2 | 缺货、延误、待核实 |
| danger / danger-bg | #9B3C32 / #F5E6E2 | 失败、不可逆后果，新增语义色，需实测对比度 |
| spacing | 4、8、12、16、20、24、32、40、48px | 网页与小程序的共同节奏 |
| radius | 4px；对话框最多 8px | 避免所有内容卡片化 |
| touch target | 最小 44×44px，主动作 48px 高 | 包括图标、勾选整行、关闭和扫码 |

桌面正文 14–16px、次要 12–13px、页标题 28–32px、金额 28–32px。小程序正文 / 输入 16px、辅助 13–14px、主标题 22–26px。金额和编号尽量等宽数字；金额小数保留规则见业务文档，不能为了“好看”掩盖分。

网页使用本地中文字体栈，衬线可回退至宋体。小程序优先系统字体，标题衬线在不同系统可能回退；先验证实际设备，再决定是否引入获授权的子集字体。首版不依赖远程中文字体保证页面可用。

字体放大、长文本和金额位数超过样图时允许布局增长；不固定卡片高度截断业务事实。

## 3. 电脑工作台

### 布局规格

| 视口 | 结构 |
|---|---|
| 1440×1000 参考 | 顶栏 76px；两侧 44px；左待办约 302px；中设备摘要与右流程区并列，间距 24–30px |
| 1366×768 主验收 | 顶栏可压到 66px，缩短日期区和照片高度约 220–244px；保留正文可读性，主动作首屏可见 |
| 1280×800 | 左列约 280px；详情宽度不足时照片缩为紧凑摘要，处理区优先 |
| 1024×768 / 平板窗口 | 左列约 260px，右详情单栏；不挤成三列，不隐藏交期；照片退为缩略图 |
| 1920×1080 | 内容最大约 1600px 居中或按列表内容适当扩展；不无限放大图片和行距 |

低于 1024px 的网页窗口只做基本可用保护：列表与详情切换、无横向崩溃；不投入第二套手机 H5 产品或验收。真正手机交付对象是小程序。

页面尽量一条主滚动轴；桌面长待办区可独立滚动，处理区不再嵌套多重固定高度滚动。窄高变化和浏览器放大时优先切布局，不通过缩小字体硬塞。

### 首页信息顺序

1. 顶部品牌、六导航、全局搜索、账号。
2. 日期 / 今天 / 门店工作台标题与“＋开单”。
3. 待交机、缺货订单、维修待办、待收款和查件 / SN；数值均可点开来源。
4. “待办事项”数量与“订单处理 / 设备看板”切换。正式用“事项”涵盖销售、维修、回收；不能统称都是销售订单。
5. 左侧：当前列表搜索、全部 / 交付 / 缺货 / 维修 / 回收、结果数量、任务行、接收维修 / 到货入库快捷入口。
6. 右侧：单号与状态、客户与设备、约定时间；设备图 / 配置摘要；当前步骤、检查 / 缺件 / 方案；金额与当前动作；最近事件与完整记录。

按服务端任务主键选中。切换筛选后旧任务若不在结果内，清空详情并在桌面选择首条有效任务；结果为空则显示对应空状态。后台更新导致已选任务完成时显示“此事项已完成”，由用户选择下一条，不能操作中突然跳单。

设备看板与列表是同一查询结果的两种视图，筛选、数量、权限、选中对象共用；小程序可以切看板但默认竖向任务列表，照片不是唯一识别依据。

## 4. 微信首页与详情

### 原生框架

首版采用系统导航栏和原生 tabBar，降低胶囊、返回和安全区实现错误。顶部系统栏使用暖色底、清晰标题；应用品牌与＋开单置于下方紧凑行。不可再画一个假的微信右上胶囊。详情由系统返回承担主要返回动作，页面中不重复放两套返回箭头。

原生 tabBar 使用今天、开单、库存、更多，选中森林绿。列表页有 tabBar；详情页只显示底部业务操作条。每页只有一个固定底部区域，避免导航、提交和金额条堆三层。

### 今天页

顺序：品牌和开单 → 四项统计 → 待办标题 / 视图 → 搜索与扫码 → 事项筛选 → 竖向列表。取消大日期展示和首屏大设备摄影。

以 375px 设计宽度制定尺寸，用 rpx 做弹性布局、px 保证触控最小尺寸；同时验证 320、375、390、430。正常字体下 390×844 在真实系统导航和 tabBar 之间争取显示 3–4 条完整待办；字体放大时以可读性优先，不硬保四条。

任务行：约 56–64px 缩略图，右侧客户 / 设备，下一行当前卡点，再下一行时间与动作。整行可点；动作文字不是唯一小触点。长设备名最多两行，电话与 SN 进入详情；逾期明确写“已逾期”，不能只变红。

统计在宽屏四列，320px 或大金额时允许两行两列；不把 ¥128,000.50 缩成极小字号或省略成无法核账的数。

### 详情页

顺序：单号 / 状态 / 交期 → 客户与事项 → 紧凑设备摘要（约 88–104px 图）→ 阶段 → 当前处理内容 → 下一步提示 → 最近事件 / 历史 → 底部固定金额与动作。

点击照片查看原图 / 图片列表，标记“型号示意”或“实物照片”。点击配置进入只读配置页，可从那里查看 SN、来源和质保；当前处理页不强塞八行配置。

交付单底部显示待收尾款、总额 / 已收 / 折抵摘要和“办理交付”；维修显示当前已确认收费，未定费用写“待确认”；回收显示最终收购金额或“估价待确认”。不得把所有详情底部套成“¥0 办理交付”。

底部区域高度由内容决定，包含安全区。正文预留同等空间，最后一条记录可滚到操作条上方。输入时键盘不能覆盖焦点字段或提交；必要时转到专门结算页，收起键盘后再确认。授权弹窗、来电、切后台恢复后先刷新状态再写入。

### 返回和跨端状态

- 列表→详情→返回，保留搜索、筛选、视图、已加载页和滚动位置。
- 页面之间只传 ID；详情重新取最新数据，不能把列表旧对象当可提交依据。
- 从分享路径或扫码直接进入详情：登录后恢复目标；无权限显示原因；无列表历史时“回到今天”。
- 电脑改了订单，手机再次显示页面时校验版本；有本地未保存输入先提示差异，不覆盖用户输入。
- 权限变化 / 账号退出后清除缓存和界面选择，不能让后一位员工看见前一位成本与客户资料。

## 5. 各业务页的具体表单与动作

| 页面 | 必要字段与默认行为 | 电脑操作 | 微信操作 |
|---|---|---|---|
| 新建装机报价 | 客户称呼、用途可选、至少一行配置；预算 / 电话 / 交期按需补；报价阶段不锁货 | 模板起步，表格行内数量 / 售价 / 来源 / 质保 | 分步“客户→配置→确认”，每行进入编辑页，底部总价 |
| 选件 | 新品 / 二手现货 / 客供 / 服务；名称、数量、价格，二手必须选实物 ID | 侧栏搜索与比较；成本按权限展开 | 全屏搜索与筛选，逐项添加，返回保留草稿 |
| 确认成交 | 最终版本、客户承诺、交期、缺货清单、可选定金 | 单次核对后成交，再登记款项 | 独立确认页；缺货允许接单，已被占用的指定二手件必须换件或取消该行 |
| 新建零售 | 商品与数量、售价；散客无需电话，服务行允许直接输入 | 扫码枪连续录入 | 相机扫码 / 搜索；完成结算后交货，不显示装机测试 |
| 缺件处理 | 应需 / 已订 / 缺口、供应商 / 在途、预计到货 | 合并采购、部分到货、差异 | 本订单缺件清单→实到数量 / SN→确认入库，不能用勾选“到货”直接放行 |
| 入库 | 来源单 / 快速采购、商品、数量、成本、日期；序列化实物逐件 SN | 批量粘贴、预检重复后提交 | 逐件扫描，显示已录 / 重复 / 不匹配；提交前核对数量 |
| 装机检测 | 领料位置、实物绑定、检测模板及结果、异常说明 | 多行配置与测试信息并列 | 顺序核对、拍照 / 写结果；失败项目禁止自动打勾 |
| 办理交付 | 配置 / SN、测试结果、附件清单、最终款项、交接方式 / 时间 | 对话框或专页列全部阻断项 | 独立结算与交付确认页；尾款为 0 显示“已结清”仍需确认实物交出 |
| 库存 | 型号、新旧、数量分组、位置、库龄 | 表格；点数量查看构成；导入 / 盘点 | 搜索为主，卡片显示可卖 / 已订 / 待处理，详情查来源去向 |
| 接修 | 客户称呼、联系方式、设备、故障、附件、外观；无电话需替代联系说明 | 可从旧订单 / SN 带入 | 拍照优先；外店设备可新建，原销售可空 |
| 维修方案 | 检测结论、处理方式、配件 / 服务费用、质保处理依据、客户确认记录 | 方案版本与费用明细 | 查看方案→记录确认时间 / 方式→执行；“记录已联系”不代替真实联系 |
| 换件 / 返厂 | 新旧件、所有权 / 去向、费用归属；寄出 / 返回物流与状态 | 并排对比配置历史 | 扫描新件、核对旧件，逐步提交 |
| 回收 | 卖方称呼 / 联系、设备 / 实物、附件、初估、检测、最终价、接收确认 | 逐件与批量分项评估 | 拍照 / 验机 / 最终价确认；谈不成走归还 |
| 管理员数据清理 | 门店管理员；只列出未发出报价草稿和没有业务引用的商品档案；逐项显示删除范围 | 系统设置入口；删除前明确影响并二次确认 | 不适用（仅内部网页 ERP 管理工具） |
| 整备 / 上架 | 检测结果、已知缺陷、整备成本归属、质保、标价 | 成本明细、实物待售列表 | 填结果和实物照片；成本填写按权限 |
| 置换 | 新销售单、已确认回收单、可折抵额、已收款、应收 / 应付差额 | 双单对照，分步确认 | 一项一项核对，总结页明确资金方向；最终价未定不能结算 |
| 退货 / 退款 | 原订单行、数量 / 实物、原因、附件、退款金额、资金方式 | 先收货待检，再退款；可只退款无实物，须选原因 | 扫码原件、拍照、显示退款上限；老板权限提交 |
| 账本 | 时间、资金方向、类别、关联单、方式、操作人、核对状态 | 筛选与导出、对账、毛利 | 简明汇总→明细→单据；禁止在汇总卡直接改数字 |
| 盘点 | 盘点范围 / 时点、账面、实盘、差异原因 | 批量核对后老板调整 | 逐件扫描 / 数量输入；差异保存不自动改变库存 |

额外说明：列表不强制所有模块使用同一“订单”布局；共享的只是任务行、详情摘要、事件、金额和反馈组件。维修有维修方案，回收有检测与估价，缺货有实到记录，各自根据状态呈现真实内容。

## 6. 主动作规则与组件清单

| 组件 | 输入 | 必须处理 |
|---|---|---|
| AppShell / MiniShell | 当前页、身份、权限 | 网页六导航；微信原生导航与 tabBar，无重复胶囊 |
| MetricStrip | 指标、作用范围、生成时间、筛选链接 | 点击能解释数字；受权限控制；大金额自适应 |
| TaskList / TaskRow | taskId、entity、期限、卡点、primaryAction | 加载 / 空 / 失败 / 长文本 / 完成移出，选中与焦点 |
| DeviceSummary | 型号图 / 实物照片类型、配置摘要、关联入口 | 无图、加载失败、尺寸稳定；不暴露内部图片 |
| ProgressSteps | 阶段序列与当前阶段 | 只是呈现，不可点击任意改状态；零售可跳过装机 |
| ActionChecklist | 模板版本、每项状态、修改时间、阻断原因 | 保存中 / 保存失败；不能勾中就假装已经服务器保存 |
| AmountActionBar | 应收应付方向、金额、allowedActions | 欠款 / 结清 / 未定价 / 无权限 / 正在核实，不把应付显示成负尾款 |
| EventTimeline | 操作人、时间、事件、关联单 | 新旧状态、冲销引用、空记录；不展示技术堆栈 |
| FormFeedback | 字段错误、业务冲突、请求结果 | 保留输入、定位字段、重新查询，不泛化成“操作失败” |
| PhotoPicker / ScanInput | 用途、所属单据、允许类型 | 取消不算错误、拒绝可替代、重复扫描不重复加入 |
| CustomerDocument | 客户可见快照 | 后端白名单 DTO；两端输出一致，不含成本 / 供应商 / 原卖方 |

服务器返回允许动作和阻断原因，客户端用固定动作代码映射中文标题；按钮能否点只是提示，后端仍重新校验。关键提交前显示具体后果一次，普通保存 / 搜索 / 切换筛选不反复确认。

## 7. 统一界面状态

| 状态 | 表现 | 操作 |
|---|---|---|
| 首次加载 | 结构占位，固定图片尺寸 | 保留导航，不显示 ¥0 / 0 单伪装真实结果 |
| 首次无数据 | “还没有待办”，附开单 / 接修入口 | 与筛选无结果区分 |
| 筛选无结果 | 显示当前关键词、清空筛选 | 不保留上一次详情 |
| 部分读取失败 | 明确哪个区域失败，其他数据可看 | 区域重试；受影响正式提交暂不可用 |
| 写入中 | 当前动作显示进行中 | 防连点，但不把禁用按钮当后端幂等 |
| 网络超时 / 结果未知 | “正在核实是否已保存” | 用原 requestId 查询；查明失败才允许新的业务操作 |
| 冲突 | 展示已变更事实，例如“U-017 已由其他订单预留” | 刷新 / 换件 / 保留草稿 |
| 断网 | 顶部未连接提示，本地草稿可编辑 | 正式库存和资金操作禁用，不排队偷偷补交 |
| 登录过期 | 保留非敏感编辑上下文，引导登录 | 登录后先刷新单据；不自动重放写请求 |
| 无权限 | 原因和联系老板入口 | 不加载成本等受限字段，不依赖前端隐藏 |
| 图片失败 | 保持占位和设备名称 | 不影响查单；提交证据必需时提示补传 |

常规过渡可用 120–180ms 淡入；不加拖拽、弹跳和依赖动画完成才可操作的逻辑。网页支持键盘 / Tab / Escape / Ctrl或Cmd+K；微信触控面积、屏幕阅读、系统字体放大和原生返回单独验收。

## 8. 视觉验收优先级

第一优先：信息不丢、业务状态准确、主动作可到达、金额可读。第二优先：桌面双区与小程序分步结构正确。第三优先：颜色、字体、线条、照片比例与参考一致。不能为像素对齐隐藏应收、预约时间或错误提示。
