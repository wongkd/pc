## 2. 本轮固定的方向

- 电脑：React / TypeScript / Vite；六个入口，待办列表与处理区并排。
- 微信：原生小程序，WXML / WXSS / TypeScript；四个底部入口，独立详情页，底部主动作。不用 web-view 包装网页。
- 两端共用一套后端业务、身份权限、单据和实物记录；共用接口契约与测试样本，分别实现 UI。
- 保留奶油白、森林绿、衬线标题、细线和设备照片；补齐真实业务，不能把示例订单或勾选框当业务实现。
- 首版包含销售、库存、采购到货、交付、基本退货退款、售后、回收置换、二手件再次装机、基础账本。
- 不自动接入支付，不把人工登记称为平台到账；不做完整离线记账、多门店运营、原生 App 或手机 H5。

## 3. 文件职责与运行方式

本目录只有 Markdown 方案和两张参考图，无需安装依赖，无可执行产品。参考图由用户临时附件复制到本目录，避免附件失效；用途仅为本项目设计对照，图内设备素材的商用授权仍需核实。

如需查看历史网页原型，沿用其 README 中的本地预览命令；该原型不是小程序预览，不据此宣称微信验证通过。

所有拟建目录、接口、组件、测试均是后续任务。当前已完成：本地现状核对、需求澄清、方案分解和文档一致性检查。未完成：业务开发、建小程序项目、接口联调、数据库迁移、真机测试、发布。

## 4. 使用方式

实施开始后从 T00 逐个领取任务，每次只执行一张任务卡。前置任务未完成时，不跳过业务规则先伪造页面成功。复杂的库存、收付款、置换和迁移任务按规定复核后才能进入下一步。

后续新任务可直接使用[统一任务提示词](05-implementation-tasks.md#统一任务提示词)。第一轮应只做 T00：核对可追踪代码基线、登记平台条件和本地验证命令；本次规划没有授权初始化 Git、发布或操作生产数据。
