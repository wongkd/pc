## 二、什么时候做什么

| 阶段 | 现在是否开始 | 交付 | 进入下一阶段的门槛 |
|---|---|---|---|
| P0 网页前端接真 | **现在立刻开始** | 今天、盘点、隔离、采购、折抵、附件、导航全部可操作 | 前端 test/build；真实本地 Worker 浏览器验收；不再把 demo 当营业数据 |
| P1 后端最后收口 | **现在开始，与前端分通道** | B30、B36、附件读模型、R13 收敛 | 后端全量测试、契约门禁、迁移连续、HTTP 验收全绿 |
| P2 ERP 总集成 | P0/P1 主要卡完成后 | 核心营业流程串起来，清理新增 lint，异常/权限/幂等回归 | 形成明确的测试候选版本 |
| P3 测试后端部署 | **P2 后开始，不直接上生产** | 先决定 Workers/D1 继续使用还是 CloudBase 迁移；建立独立测试环境、空库迁移演练、权限/secret/对象存储/回退 | 测试环境和生产物理隔离，迁移与回退演练有证据 |
| P4 小程序真实数据汇合 | 四屏视觉 MP00–MP15 可在 P0/P1 时并行；真实数据从 P3 测试环境可用后开始 | MP17–MP25 身份与公开内容，随后报价/订单/售后/回收 | 顾客身份与服务端归属守卫完成；顾客 DTO 不泄露成本、供应商、SN、内部备注 |
| P5 支付与上线 | 最后做 | MP56–MP64、微信支付、开发者工具、iOS/Android、候选发布 | 主体/备案/商户/域名当时事实复核；真实回调、对账、恢复、回退均通过 |

结论：**前端今天就做；后端先部署到独立测试环境，不直接部署生产；小程序第一批真实数据在 P3 测试后端可用且顾客身份完成后汇合。**

## 三、对话框编排

最多同时保留三条通道：

1. 后端通道：BE-01 → BE-02 → BE-03 → BE-04，严格串行。
2. 前端通道：FE-01 → FE-02 → FE-03 → FE-04 → FE-05 → FE-06 → FE-07，默认串行；一张完成验收再开下一张。
3. 核查通道：OPS-01 可与开发并行，但只读，不部署、不改远端。

`contracts/v1`、生成物、`backend/migrations`、`backend/src/index.ts` 接线是单点区。任何时候只允许一个对话框修改；发现 mtime 在开工后变化就停手交接。

## 五、小程序怎么接上 ERP 数据

小程序不直接读 ERP 页面数据，也不复用员工接口。汇合顺序是：

1. MP00–MP15：先把四屏视觉做对；可从现在开始，但不算数据接通。
2. MP16–MP19：隔离演示/真实环境，完成顾客身份与归属。
3. MP20–MP25：ERP 发布公开商品、案例、门店内容，小程序首次接真实公开数据。
4. MP29–MP35：接顾客专属报价与确认。
5. MP36–MP55：接本人订单、装机档案、售后、回收与意向。
6. MP56–MP59：最后接真实支付；必须有服务端回调、金额核验、幂等和主动查询。

每张现成提示词位于 `docs/plans/2026-09-22-customer-miniprogram-reset/tasks/MP00.md` 到 `MP64.md`。默认从 MP00 串行执行；真实数据首次汇合点是 MP25，不是 MP00。

## 六、部署放行线

只有以下条件同时满足，才进入“测试环境部署”对话框：

- BE-01～BE-04 与 FE-01～FE-07 已完成或明确降级；
- 契约、生成物、迁移、后端测试、前端 test/build 全部按当前源码重跑；
- 生产与测试隔离、权限种子、secret、对象存储、备份与回退已核实；
- 已拍板继续 Workers/D1 还是迁移 CloudBase，不在部署过程中临时换数据库；
- 用户再次明确授权具体环境与具体部署动作。

生产上线还要额外完成远端迁移演练、真实对象存储、微信开发者工具、iOS/Android、平台主体/备案/支付条件和恢复演练。
