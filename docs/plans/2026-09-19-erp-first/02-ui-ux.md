# UI/UX 设计规格

日期：2026-09-19。状态：待原型验证的设计提案；不是新界面已实现或已获用户批准。
入口：[规划总览](README.md)。

## 1. 设计目标

关键词：现代、轻盈、层次明确、办事快。用户已否定当前 ERP 视觉，本提案取消“继承奶油白与森林绿”的前提。
以 [七图分析](05-reference-analysis.md) 中图 2 下、图 3 上、图 7 上建立新设计：浅灰白工作区、石墨黑文字和主动作、适量冷蓝强调、柔和圆角面板、清晰无衬线排版。
保留可靠业务代码不代表保留旧外观；旧页面截图只证明历史状态，不作为新稿必须像素对齐的基准。
统一的特色是“看到卡点，就能在旁边处理”：缺件旁可进入采购，待收金额旁可登记核实收款，待交付旁可打开交付核对。
页面先回答现在发生了什么、为什么受阻、下一步做什么，再展示明细与历史。

本轮看过 V01/V02 的 1366×768 历史截图：今天页的大设备图、日期和摘要占用较多空间，关键动作靠近首屏底部；库存页的表格和对齐可沿用。
这只是旧图评估，不代表本轮新页面浏览器验收。

## 2. 导航与整体布局

建议从原六项顶栏升级为约 200px 的左侧业务导航。参考图 2 下的图标+文字和图 7 上的二级关系，六个常用业务可稳定定位，顶部留给搜索和当前单据。
侧栏六项：工作台、销售、库存、维修售后、回收置换、收支。销售内含报价/订单/客户/配置模板；库存内含商品/实物/采购/供应商/盘点；设置置底。
子页面使用内容区二级标签或面包屑，不默认展开层层树菜单。
这覆盖旧六导航布局提案，但旧路径和已有权限在真正替换时保留映射；不先改源码凑入口。

- 顶部工具区 56px：面包屑、全局搜索、门店与账号；“新建”只在合适页显示，避免重复按钮。
- 页面标题区约 64–80px：标题、数量/说明和一个主要动作；不铺大欢迎语。
- 主内容边距 24px，1366 下可减至 20px；表格可充分利用宽屏，不全页限制成窄海报。
- 全局搜索命中客户、单号、型号、SN，分组显示并标识类型；局部筛选保留在列表上方。
- 通过 URL 保存标签、筛选、选中单据；从详情返回恢复滚动位置与查询条件。
- 业务动作权限由服务端判定；成本隐藏开关只解决现场展示，不能替代成本权限。

## 3. 四个必须一起定版的核心页面

### 3.1 工作台：待办优先

```text
业务导航 │ 工作台                         全局搜索 / 账号
         │ 今日交付 4   缺件 3   待收款 2   异常 1
         │ 待办列表 320px          │ 当前单据处理区
         │ 今天 / 逾期 / 我的      │ 客户 · 设备 · 承诺时间
         │ 搜索、筛选              │ 已收定金 / 缺显卡 / 明日交付
         │ 单号、客户、设备        │ 需处理：显卡缺 1 件
         │ 卡点、时限、应收        │ 配置/缺件/进度       金额摘要
         │                        │ 处理记录          [创建采购单]
```

统计是筛选入口，点击能看到对应事项；不把销售额大屏当默认首页。
默认按逾期、今日承诺、异常优先排序，再按期限；“我的/全店”切换符合权限。
每条待办都有对象、卡点、期限和主动作；同一单多个卡点合并成一个主待办，指标可以交叉且标明口径。首页右侧可切“当前订单处理/今日交付预约”，不让日历占据全屏。
照片默认 48–64px 缩略图或小型设备摘要，可点开放大；售后外观核对时才放大。
无待办是“今日事项已处理”，不补虚构数字；断网、加载失败不能呈现零待办。

### 3.2 报价编辑：像配配置一样自然

```text
业务导航 │ 新建报价                      草稿保存状态
         │ 客户 [搜索/快捷建档]  用途  预算（可空）
         │ 配置模板 [选择]    [添加配件] [添加服务]
         │ 配置明细约 70%                 │ 结算摘要约 30%
         │ 分类 / 型号 / 来源 / 数量      │ 商品合计
         │ 单价 / 小计 / 库存提示 / 质保  │ 服务、优惠、总额
         │ 新品、二手、客供逐行可辨       │ 预计毛利（需权限）
         │                              │ 定金、有效期、交付
         │ [保存草稿] [打印配件单]        │ [预览并发出报价]
```

选配件用可搜索选择面板，展示型号、售价、可用数量和来源；新品/二手/客供不能混成自由文本。
允许未建档的临时报价行；转成实际销售前映射商品或快捷建档，不能为报价把老板挡在长建档表单外，也不能让未匹配行静默扣库存。
支持模板起单、复制历史报价、键盘 Tab 连续填单；不每加一件就跳一个完整页面。
二手选择要能看具体实物和检测/质保，草稿选择不等于预留。
客供件售价为零，装机/检测服务费另列。库存不足提示可继续报价，但不得把提示当成采购成功。
有权限时显示预计毛利与成本完整性；顾客预算可空，不影响金额，不替代成交价。
复杂编辑用独立整页，报价列表用侧抽屉快速看摘要；弹窗只承载简短确认。

保存状态可见：未保存→保存中→已保存；失败保留所有输入并提供重试。退出有未保存修改时提示。
发出前预览顾客版与版本变化，内部成本/供应商/备注彻底不进入对外数据和打印内容。
修改已发单生成新版本，展示差异和确认状态；已确认后不能原地改价格。
打印配件单与顾客专属报价保留各自用途；旧打印入口继续可用，不能为新页面重写顺手抹掉。报价摘要同时容纳自取/送货、运费和逐行质保/延保，不能只设计商品金额。

### 3.3 订单详情：一处完成履约

```text
业务导航 │ 订单 SO-…  客户 / 约定交期      [更多]
         │ 配置确认 → 备货 → 装机检测 → 交付
         │ 已收款状态   缺件提示   逾期提示（各自独立）
         │ 内容约 2/3                   │ 操作区约 1/3
         │ 配置与实物 / 采购到货         │ 总额、已收、待收
         │ 检测记录 / 交付附件           │ 当前卡点
         │ 时间线 / 收退款记录           │ 下一步与前置条件
         │                             │ [当前主动作]
```

客户、配置、货、钱、历史不拆成互不关联的多张页面。
首屏显式展示“缺什么”“谁处理”“承诺何时交付”；历史和附件在下方或二级标签。
主动作随可信阶段变化：核实收款→处理缺件/预留→开始装机→完成检测→办理交付。
无法执行时写具体原因及解决入口，例如“尾款待收 ¥800，先登记收款”，不能只给灰按钮。
收款/退款/交付确认区复述客户、订单、金额或实物影响；普通编辑不反复确认。
执行后更新金额、状态、任务数量与时间线；结果未知时显示“正在核实”，提供查询结果，防止重复动作。
进度条只解释流程，不允许点击阶段跳过扣库或检测。

### 3.4 库存：找得到，也知道能不能卖

商品型号列表默认表格；点击型号看逐件库存或数量明细。可用、预留、待处理、在途、客户保管分别呈现。
主要列为型号、管理方式、可用/预留/待处理、库位、售价；成本只按授权出现，长参数放次行。
实物详情包含 SN、来源、成色、检测、成本、质保、当前占用订单和完整流水；成本缺失标“待核实”。
采购到货在采购单上处理；盘点在盘点单上处理，库存页以查看、查找和有依据的动作入口为主。
条码枪按键盘输入考虑：搜索框接收 SN，Enter 打开唯一匹配，多结果显示选择列表。
搜索无结果时区分型号不存在、暂无实物、筛选过窄；保留关键词并给出对应操作。
“现买现入”提供简化入口，一次填写供应商称呼、商品、成本、实到和 SN，后台生成关联采购/入库记录，不强迫先跳多个模块。

### 3.5 首版必补的服务和回收页面

- **维修工作区：** 待检测/待确认/维修中/返厂/待取机列表；详情聚合故障、设备外观附件、检测报价、客户确认、换件与归还。预约视图借图 5 上的时间线、图 7 下的周排期，但默认仍是任务列表。
- **回收拆件工作区：** 先显示接收整机、验机、最终收购价与结算方式；下一步是拆件清单，逐件列检测、分摊成本、整备和可售条件。不能放“整机上架转卖”主动作。
- **置换结算：** 新机成交与旧机收购并列，结算区分原价、已收、有效折抵、应补/应退；抵用额度另列使用记录和未用部分，估价不能伪装已结算。
- **售后质保：** 按当前设备配件逐行显示新品/二手/客供和对应质保，原销售快照与更换后配置可追溯；不能只显示一个整机到期日。

以上页面与四屏共享组件，但在完整首版前须独立走通任务，不接受仅给菜单或占位图。

## 4. 视觉系统提案

| 项目 | 规格 |
|---|---|
| 整体 | 雾灰白背景、白色面板、石墨黑文字/主按钮，冷蓝选中态；用留白、圆角与极轻阴影区分层次 |
| 色彩起点 | 背景 #F4F5F7、面板 #FFFFFF、正文 #20242B、次要 #626A76、强调 #496EDB；这是新提案值，需原型对比度测试 |
| 语义 | 绿色=可操作/完成，琥珀=缺件/待核实，红色=失败/异常；同时有文字或图标 |
| 字体 | 标题、正文统一中文无衬线（微软雅黑/苹方），依字重与字号分层，去除旧宋体式标题和大日期；不依赖外部字体请求 |
| 字号 | 标题 26–30px，正文 14–15px，次要 12–13px；金额与编号使用等宽数字 |
| 间距 | 4/8/12/16/24/32px；表单分组依任务关系，不给每个字段单独套卡片 |
| 圆角 | 输入/按钮 8–10px，主面板 14–18px，状态标签可胶囊；表格仍用正常行，不能每行做巨大药丸 |
| 密度 | 标准列表行 52–60px；工作台多信息待办可约 112–124px；紧凑表格约 44px |
| 操作 | 鼠标常用控件 36–40px，触控操作区至少 44px；全页一个视觉最强主动作 |
| 动效 | 仅状态反馈与面板过渡，约 120–180ms；无持续漂浮、入场排队、长距离滑动；支持减少动态效果 |

适用场景优先：不把营销首页的大标题、大图、玻璃效果放进订单表格。
新 ERP 在独立作用域建立设计令牌与组件，业务工具/逻辑按需复用，不能用覆盖旧 CSS 的方式勉强换肤。旧打印页隔离保护。
先做完整浅色工作稿；若需要比较，以图 6 上结构做一屏深色备选，不能把混合参考图误记为用户已经选择暗色或紫色。

## 5. 统一交互与状态

- 列表：搜索、状态筛选、日期、分页、数量、重置筛选；刷新后保留合理上下文。
- 抽屉：快速查看/选择对象；长编辑与完整详情有独立 URL。关闭恢复触发按钮焦点，不叠抽屉。
- 表单：必要字段清晰，错误在字段旁，失败不清空；提交中防重复。扫码和键盘可完成主要流程。
- Toast：辅助确认，不承担唯一错误或收款结果；关键结果保留在单据上。
- 表格：金额右对齐、数字等宽、合计清楚；长型号可换行，完整金额不得只靠悬浮提示查看。
- 空态：首次无数据、筛选无结果、无权限三种不同文案；不以“暂无数据”掩盖加载失败。
- 并发：收到版本冲突保留本地修改，展示服务端更新，选择重载/重新编辑；不能静默覆盖他人。
- 网络：写操作超时为结果未知；已保存草稿与未核实业务动作明确区分，刷新后能继续查询。
- 现场给客户看：一键顾客预览或隐藏成本；真正对外分享使用服务端脱敏读模型。

## 6. 必须用任务验证美观好用

| 任务 | 原型/实现验收目标（尚未实测） |
|---|---|
| 老板打开工作台 | 5 秒内说出最紧急事项及卡点；无额外滚动找到下一步 |
| 找客户/订单/SN | 熟悉系统后 10 秒内进入正确详情 |
| 复用模板报价 | 示例 8 件配置，约 2 分钟完成编辑并到顾客预览 |
| 处理一张订单 | 不重复填写客户/配置；能从同一详情进入收款、缺件、检测和交付 |
| 判断一件二手显卡能否出售 | 看清可售状态、占用单、质保和检测，不仅看到“库存 1” |
| 异常恢复 | 网络失败保留输入；重复点击不重复收款；版本冲突不丢改动 |

固定样本：长型号/长姓名、8–15 行配置、六位金额、零金额客供、未知成本、部分到货、已收款缺件、退款中。
视觉检查 1366×768、1440×900、1920×1080；补 1024×768 折叠导航和平板触控。
手机宽度约 390px 检查窄屏提示、可读摘要与无横向破版，不扩成第二套完整手机 ERP；顾客操作由小程序承接。
检查 125% 缩放、完整键盘路径、可见焦点、表单标签和对比度；钱与主要按钮不能被固定底栏遮挡。
原型评审通过后建立四屏截图基准，后续模块复用；不能只凭 DOM 断言声称美观已验收。
