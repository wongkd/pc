## 三个核心决定

1. **ERP 先可独立使用。** 首阶段用经过核实的线下收款登记完成交易，不依赖微信登录、支付和订阅消息；顾客小程序保留现有成果，后接同一业务服务。
2. **先验证核心操作体验，再逐条打通真实业务。** 先评审工作台、报价编辑、订单处理、库存四屏的全新设计，再补维修、回收拆件与置换的任务原型；不能只画首页，不能用占位页面数量衡量完成度。
3. **重做产品组织，复用可靠基础。** 保留报价打印、模板/商品能力、库存与幂等基础；重整导航、业务详情和表单。新旧通过适配逐步替换，不清空仓库或数据库。

## 交付分层

| 层次 | 交付边界 |
|---|---|
| A：体验定版 | 核心四屏与异常态可操作；只用虚构样本，不代表真实收款或库存 |
| B：销售闭环内部验收 | 客户→报价→确认→收款登记→预留/采购→入库→装机检测→尾款→交付→基础对账；含零售、取消与基本退款退货 |
| C：完整首版 ERP | 维修售后、回收拆件与成本分摊、置换/抵用额度、盘点调整、基础经营统计与权限补齐 |
| D：顾客小程序 | 接入顾客报价确认、自助下单、真实支付与进度查询；不复制一套业务规则 |

B 和 C 都属于首版范围，分批开发不等于把维修回收降为可选。完整首版试营业需 B+C 达标，并完成隔离环境、迁移核对、恢复演练与真实业务验收。
