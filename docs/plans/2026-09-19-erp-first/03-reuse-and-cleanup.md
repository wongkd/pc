## 3. 实施架构

```text
ERP 页面 / 顾客小程序
        ↓ 各自的读模型与权限边界
HTTP 入口 → 业务动作 → 幂等/版本/断言 → D1 与事件流水
        ↓
对外顾客 DTO / 对内订单处理 DTO（由同一事实生成）
```

新前端页面按 `features/sales`、`inventory`、`service`、`recovery`、`finance` 逐域建立；公共表格/表单/状态组件只在真实复用后提取。
旧 `App.tsx` 和后端 `index.ts` 随业务切片拆分，不夹带整库重构。
读模型应包含金额摘要、履约卡点、允许动作及不可执行原因；最终动作仍由服务端再校验。
计划中的客户表、设备关系、采购、服务、转换、抵用流水须先过契约与迁移设计；本轮不创建业务表。
照片/凭据需独立存储策略、权限和备份映射；不将生产凭据写入演示资源目录。

## 4. 清理分级

用户已允许去掉无效文件，实施时不必为每个已证实的临时文件重新请示；但必须核实用途与引用。

| 分类 | 范围 | 本轮/后续处理 |
|---|---|---|
| 保留 | 源码、迁移、契约、真实数据、备份、历史验收 | 作为基础/证据，不能仅因旧或体积大删除 |
| 退出当前指令入口 | 旧双端店员 ERP 推进顺序、旧 Q01 单一路线、旧视觉作为最终标准的说法 | 当前入口改指 ERP 规划；原文加被覆盖说明，历史证据不覆盖 |
| 待替换后删除 | 重复旧壳/导航、占位组件、旧店员小程序页面 | 新路由和权限验证后，检查 import、深链、app.json、测试、模板和资源引用再删 |
| 可删除候选 | 未引用、可重建的临时预览和重复输出 | 每个候选列路径、引用检索结果、用途判断、恢复方式；不能直接删除整个隐藏目录 |
| 新增长期参考 | 本轮七张用户图片、需求映射、新规划 | 有索引、来源、用途与状态，避免变成无主文件 |

本轮已有大量用户未提交变化，因此先完成文档入口治理和复用清单；没有确认到新的可直接删除业务文件。
旧小程序页仍可能注册并共享函数，旧壳/演示页面仍有路由，不把它们误判为无引用垃圾。
`.wrangler`、`backups`、`node_modules`、同步目录不在本轮删除范围；其中可能有持久化数据或恢复依赖。

## 5. 清理执行卡的固定步骤

1. 记录本次范围及已有 Git 状态，不把用户原有删除算本轮清理。
2. `rg` 查引用、路径配置、路由、脚本和测试；动态引用单独核对。
3. 确认替代实现已可用，检查真实文件的绝对路径位于本工作区内。
4. 文档先退出当前索引或归档，业务代码只删除本卡明确清单；数据与备份不动。
5. 同步修复引用与必要检查；保存路径、原因、结果和恢复办法。

回滚依赖任务快照或独立差异，不使用 reset/clean 覆盖用户工作。提交、部署和远端迁移均不是本轮授权范围。
