## 3. 下一张卡 E01 的具体边界

目标：把七张图里的设计语言转成“装一下机”真实中文业务页面，让用户看见并操作新风格。

- 文件范围：新的 `docs/design/<日期>-erp-core/v1/`，独立样式、数据、预览脚本与 README；不改营业页面或业务数据库。
- 样本：一张待尾款交付、一张已收定金但缺显卡、一张新旧客供混装报价、一张回收拆件库存摘要；全部明确虚构。
- 实际交互：侧栏与页面切换、任务筛选/选单、报价模板与配件增改/金额预览、订单缺件/收款/交付核对面板、库存搜索与实物展开。
- 状态：加载、空、失败保留输入、结果待核实、无权成本、版本已更新、长型号/大金额；无后端按钮只展示预览及说明，不能伪造收款或交付成功。
- 视觉：以图 2 下/7 上/3 上为参考组合；新字体、卡片、表格、侧栏与操作面板统一设计，不复刻旧米黄宋体界面。
- 验证：1366×768、1440×900、1920×1080 截图；1024 和 390 窄屏检查；键盘、125% 缩放、固定操作区不遮挡。
- 评审结果：用户能评价完整中文界面和业务操作；有问题先改此原型，再把选定组件落到 React。不得把本规划提案记成已选定成品。

## 4. 业务验收样本

| 场景 | 必须成立 |
|---|---|
| 8 件配置按客户预算调整 | 预算不算收款；单价/来源/质保清楚；改后新版本、旧版本可查 |
| 未付订单选中最后一块二手显卡 | 仅报价不预留；真实收款后两个订单竞争只有一个预留成功 |
| 收 15% 定金后采购，5 件只到 3 件 | 钱已收、在途剩 2、实到按检测结果入可用或待处理 |
| 全新+二手+客供混装 | 新品/二手各自质保；客供件不记自有成本；交付只扣店有实物一次 |
| 配置改了但检测已通过 | 相关检测按配置版本失效，重新检查后才能交付 |
| 尾款成功但交付超时 | 查询交付结果，不再收尾款；刷新后还能恢复未知动作 |
| 自取改送货，驾车 12km | 显示超免费范围；未配置阶梯时要求核实运费，不能虚构自动价 |
| 回收整机 1,500 元拆出多件 | 成本/损耗总额为 1,500 加可归属整备；整机与部件不能同时可售 |
| 拆出显卡装进另一个客户整机 | 原回收→拆件→检测→报价→预留→交付→售后来源和成本连续 |
| 回收抵用分两单使用 | 累计不超额、剩余可追溯、无自动过期；找零按已明确语义处理 |
| 置换：新机 6,000、旧机 1,500、已付 900 | 有效折抵 1,500，剩余应收 3,600；没有虚构 1,500 现金收付 |
| 外店机器上门维修/本店二手件保内换件 | 预约和客户设备成立；方案确认、实际成本、新旧实物与质保可追溯 |
| 取消、部分退货、现金退款、撤销折抵 | 各对象独立记录；不因退款凭空恢复库存；旧件已使用时不能强行还原 |
| 同名客户、无权查看、会话失效 | 不跨客户/门店泄漏；成本从 API 中排除；失败输入保留 |

## 5. 工程门槛与停止条件

按改动范围执行 [工程指南](../../engineering/README.md)：文档链接；网页 test 后 build 串行；后端 D1 本地测试；契约生成/一致性；原型浏览器与实际截图。
库存/资金必须覆盖并发、重复请求、半途失败与回查；不为纯配色写镜像测试。

出现以下情况停止对应写入/发布，不用伪造数据继续：

- 请求指向生产且环境未隔离；迁移需要破坏旧表或覆盖客户/资金资料。
- 单据金额、库存数或成本无法解释；重复动作导致多记；顾客拿到内部资料。
- 本地/服务端冲突尚未解决却会覆盖数据；业务“找零”、退款执行或预留期限缺必要规则。
- 新 UI 只能看首页、无法完成实际任务；关键操作被遮挡；没有看到截图就声称验收通过。

本卡结束要写结果入口、实跑命令、证据、未验证范围、当前断点与下一动作。提交/部署/远端迁移不默认执行。
