# 05 · 收款、采购、装机与交付

日期：2026-09-19。状态：依赖 04；必须拆子卡串行。对应 E06–E09。入口：[分发说明](README.md)。
目标：缺件装机、零售、混装三类销售闭环可核账；资金与库存动作由服务端确认。

## 文件边界

复用 operations.ts、inventory.ts、请求层 requestId/结果未知、旧 OrdersPages 字段；以领域新增服务，不照搬任意改状态下拉框。
本卡拆前后端销售单、采购、收款、交付、退款域。路由和迁移由集成人员串行登记。
不接微信支付、不部署、不触生产收退款；全部使用隔离 D1 与虚构凭据。

## 每次只执行一个子卡

| 子卡 | 可运行成果 | 放行证据 |
|---|---|---|
| 05a / E06 | 销售单、线下收款核实、预留与缺件 | 未付款不预留采购；重复收款只记一次；抢最后实物仅一单预留成功，失败单收款仍留账 |
| 05b / E07 | 缺件采购、快捷供应商、分批到货与退供 | 5 件仅到 3 件，在途剩 2；拒收不进可用；来源成本可查 |
| 05c / E08 | 装机检测、尾款、交付、零售 | 检测绑定配置版本；尾款与交付独立；交付一次扣库，客供不扣店有货；零售可跳过不适用装机步骤 |
| 05d / E09 | 取消、部分退货、退款、基础销售账 | 退款不自动恢复库存；退货先待检；撤销用冲正留痕；原价与成本快照不变 |

05a 通过才做 05b，依次推进。每卡都有 UI、HTTP、领域逻辑、验证，不只铺菜单。

## 状态与对账

单据读模型分别表达钱、货、履约阶段、卡点、可信主动作；不要从“缺件”推测付款状态。
requestId 贯穿每次写入与回查；超时显示待核实，刷新可恢复查询；重复请求不多收款/扣库。
按订单展示应收、已核实现金收款、待核实动作、有效折抵、退款、剩余应收；折抵来源未接时不得虚构现金。
预留天数、到期提醒/续期、退款扣费规则在执行前处理未决项，不把历史建议写成自动法律结论。

## 必测

并发抢货、重复提交、半途失败、尾款成功但交付超时、配置变更使检测失效、部分到货、客供混装、退货退款分离。
同订单重复核实不重复现金账；取消后正确释放；跨实例/事务边界不能只用单进程假锁测试。
本域 D1 测试、契约一致性、前端 test/build 串行，订单关键状态截图。
