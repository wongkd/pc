# 03 · 商品、实物与客户

日期：2026-09-19。状态：依赖 01/02；现可核字段。对应 E04。入口：[分发说明](README.md)。
目标：报价能找到正确客户和具体货，库存能区分货权、可售性、成本及来源。

## 文件与复用

复用 `backend/src/domains/inventory.ts`、迁移 0007、T05a 本地测试；不建立第二套库存余额。
参考 `frontend/src/features/workbench/WorkbenchInventoryPage.tsx`、旧 ProductManagementPage/SerialNumberPage。
新增页面按商品/库存/客户域组织；后端 index 与迁移编号交集成人员，契约变化交 01。

## 子卡（串行）

03a 商品/实物 HTTP 接线：读列表、详情与权限，数量/SN 管理分别建模，搜索型号/SN/来源/库位。
03b 客户模型：按 01 兼容方案实现客户建档、同名区分、归属；旧报价无 customerId 的适配不丢历史记录。
03c 期初与快捷入库：导入先预检，成本可待核实；“现买现入”由采购/实到关联产生，不静默改可用数量。
03c 若采购基础尚未具备，只提供草稿/预检，真实入账交 05，不伪造采购成功。

## 输入输出边界

商品返回售价、分类、管理方式；实物返回货权、来源链、检测/可售状态、可用/预留/待处理/在途/客户保管。
成本只对授权员工返回；未知成本 null，客供成本不当作本店零成本货。
客户读模型由权限限定；选客户后报价只关联稳定 ID，不按姓名匹配。
默认参考售价不覆盖历史报价价格；加入草稿不预留实物。

## 验收样本

同型号两块二手显卡可售状态不同；无 SN 内存按数量管理；客供固态不可售；待检测回收主板不进入可用库存。
SN Enter 唯一命中开详情；零结果保留关键词；成本无权时 API 不返回字段；跨客户读取拒绝。
库存写动作有幂等/并发/失败回查测试；页面有失败重试；金额整数分。
