## 2. 必须覆盖的需求

| 编号 | 需求与来源 | ERP 落点 / 验收 |
|---|---|---|
| R01 | 网页内部 ERP，小程序顾客下单；本轮先 ERP（S1 §2、S5） | ERP 可独立完成店内业务，小程序后接统一业务层 |
| R02 | 销售、回收置换、维修三条业务线（S1 §8.1） | 销售/零售、服务、回收拆件与结算都进入完整首版，不只做销售 |
| R03 | 顾客心理预算指导配置；预算不是付款（S1 §8.5） | 报价编辑中预算可填写、可对照，不进入实收、应收或优惠公式 |
| R04 | 老板出专属报价，顾客确认后下单；每件列单价（S1 §8.4–8.5、S2） | ERP 管理配置、版本、顾客预览与专属入口；微信入口以后接，不假装现已能分享下单 |
| R05 | 顾客可反复要求修改，老板执行；确认后锁价格/配置（S2 §2–3） | 新版本、差异、重新确认、旧版本留痕；反馈来源与原因作为建议字段 |
| R06 | 报价有效期 24 小时，手动续期；到期提醒（S2 R2） | 报价列表到期筛选、续期动作；提前多久提醒及续多久仍待定 |
| R07 | 全款或 15% 定金+尾款；未付款不预留不采购（S1 §8.5、S2 R12–R16） | 报价条款快照、核实收款、预留/缺件、采购；前端点成功不能当钱已到账 |
| R08 | 预留有时限，到期释放并提醒（S2 R14） | 定时任务、释放流水、订单异常；具体天数待定，7 天不是已确认值 |
| R09 | 自取/送货；湛江全市、驾车距离、10km 内免费、外部阶梯收费（S1 §8.5） | 报价和订单记录方式、地址、驾车距离、费用及承诺时间；档位未定不可自动报虚构运费 |
| R10 | 全新整机/本店新配件 1 年，二手 3 个月，客供件本身不保；可购延保（S1 §8.5） | 每行来源和质保快照、延保单独收费/期限；混装不能整机一刀切判保 |
| R11 | 回收旧整机拆件入库，卖零件或装机，不整机转卖（S1 §8.5） | 首版必须做拆件转换、成本分摊、损耗、逐件检测和再销售；不能沿用“首版关闭拆机” |
| R12 | 回收可选抵用或实际付款；抵用可拆分、可找零、无有效期（S1 §8.1、8.5） | 回收结算、抵用发行/使用/剩余/冲销记录；“找零”是现金结清还是剩余额度的语义单列待确认，不擅改为一次性券 |
| R13 | 新品+回收二手+客供可混装，来源/成本/归属贯通（S3 §5、§7） | 回收→拆件→检测→指定实物入报价→收款后预留→交付→后续维修，成本不归零、不重复采购 |
| R14 | 外店设备可维修；到店/上门预约，检测确认再修（S1 §8.1、S3 §5） | 预约、接机、客户保管、检测报价、方案确认、返厂、换件、复测返还 |
| R15 | 新品/二手/客户财产区分，数量/SN 管理（S3 §7） | 自有可用/预留/待处理/在途、客户保管；扫码找设备；无 SN 件不虚构 SN |
| R16 | 少重复录入，模板、临时报价、现买现入、快捷零售（S3 §8–9） | 原型有临时行及成交映射、快捷供应商建档；零售不强迫走装机全流程 |
| R17 | 收款、退款、采购、回收付款、折抵、实际成本分别追踪（S3 §11、S4 §7） | 原单可追溯、金额整数分、冲正留痕；实收不等于销售额、毛利不等于净利润 |
| R18 | 导出/打印、权限、导入预检、期初实盘、恢复和异常（S3 §6、§12–15） | 完整首版放行条件；历史单据不能为换 UI 被删除 |
| R19 | 定金不退/全款退款扣 10% 是原文经营意图（S1 §8.5） | 规划保留需求记录；退单页区分原条款、实际情况、拟扣费用与核实后退款，不擅自自动扣费或宣称适用所有情况 |

## 3. 明确覆盖的旧口径

| 旧口径 | 当前处理 |
|---|---|
| S1 §8.3 建议“一次性抵用” | 被 §8.5 用户确认的可拆分/找零/无有效期覆盖；结算细节仍需澄清 |
| S3/S4 成交即预留 | 被 S2 的真实收定金后预留覆盖；报价、确认和付款是不同分界 |
| S4 整机拆件首版默认关闭 | 被 S1 §8.5 回收拆件不转卖覆盖，拆件是首版必做 |
| 旧双端 ERP、店员小程序 | 被顾客小程序覆盖；退出旧页要先查引用 |
| 旧 A+B 视觉与 V01/V02 验收通过 | 用户本轮明确不满意；只保留历史证据，不限制新的 UI 设计 |
| 旧交接称报价编辑器纯离线、没有云保存 | 源码存在 fetchQuote/saveQuote/createOrder；已在复用清单纠正，接口实效需隔离验证 |
| 只完成销售就称首版营业可用 | S3 要求五条业务路径；B 仅内部验收，B+C 完成才进入完整首版试营业 |

## 4. 尚需处理但不阻塞设计的问题

预留天数、提醒提前量、续期时长、10km 外配送档位、延保定价/期限、抵用找零结算语义、店员授权范围。
原型用“待设置”或明确虚构样例表达，不把未确认数值写死到业务代码。
仅在实施到相关动作前确认必要规则；不重新询问已明确的单店范围、回收拆件方向或顾客端分工。
