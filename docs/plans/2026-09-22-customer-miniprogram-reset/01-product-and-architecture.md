# 产品范围与落地结构

日期：2026-09-22。性质：实施规划，非已实现功能。本轮只交付规划与任务包。

## 1. 已确认的目标

用户确认：**清爽版的布局与图片 + 字体微调版的细字体**。底部固定首页、商城、社区、我的。
四屏必须逐屏还原，不能只复用颜色；新增二级页继承同一套规范，但不能宣称它们有原图可对。
网页 ERP 服务店员，小程序服务顾客；保留原生 TypeScript / WXML / WXSS，不换框架。

## 2. 功能与页面

| 页面/入口 | 首版结果 | 数据与动作边界 |
|---|---|---|
| 首页 | 门店栏、品牌主视觉、四服务入口、底部推荐横幅 | 门店内容有维护入口；装机/回收/维修进入意向表单 |
| 商城 | 整机、配件、我的报价；主推横幅、两列推荐 | 默认整机。保留图中混合推荐，分类筛选区与推荐区分开；不擅自改为报价工作台 |
| 商品详情 / 选配置 | 对外图片、规格、价格、新旧/成色/质保披露、咨询 | “选配置”选公开方案后带方案编号进入装机意向，不直接改 ERP 报价，不承诺自动兼容检测 |
| 社区 | 装机案例、电脑知识、门店公告；列表与正文 | 只由商家发布；无顾客发帖、评论、点赞计数或私聊系统 |
| 我的 | 头像、装机档案、报价/订单/预约/回收数字、四行记录、联系门店、设置/二维码 | 登录后真实计数；未登录显示“登录后查看”，不能伪装成 0 条 |
| 报价列表 / 详情 / 确认 | 专属报价、当前版本、金额与有效期、确认结果 | 归属与分享授权在服务端；确认不等于支付，不锁库存 |
| 订单列表 / 详情 | 真实金额、已收/待付/退款、顾客可见时间线 | 复用 ERP 业务事实；不暴露采购/成本/SN/内部备注 |
| 装机 / 回收 / 维修意向 | 保存输入、提交、待门店确认、记录详情 | 仅建立意向，不直接建销售单、收购实物或扣库存；门店处理后关联真实单据 |
| 售后 / 回收进度 | 自己的工单、检测报价、处理阶段、联系门店 | 进度查询优先；需要顾客决定的事项先联系门店，首版不擅加 B22/B28 自助确认权限 |
| 装机档案 | 本人已交付设备、配置与质保快照、相关订单/售后 | 无订单时空态；不能把未交付或虚构设备算档案 |
| 门店与联系 | 真实地址、营业时间、电话/导航/客服可用状态 | 实际信息缺失时诚实说明；效果图“广州天河旗舰店”不是已确认门店地址 |
| 设置 / 二维码 | 授权与隐私说明、退出、联系门店申请账号处理；门店公开入口码 | 不显示 OpenID/员工身份；效果图二维码语义暂定为门店公开码，需在该卡核对可用能力 |
| 支付 | 服务端计算定金/全款、拉起支付、服务端确认到账、ERP 可追溯 | 支付配置与资质核实后才启用；未接通明确显示待接入，不算完整交易交付 |

首版不增加购物车、积分会员、优惠券、物流平台、社交社区、多门店、店员小程序。
图中的米色卡是“装机档案”入口，不解释成付费会员。

## 4. 最小架构

```text
miniprogram/
  pages/{home,shop,community,mine}/       四个主包 Tab，沿用原路径
  packages/customer/<page>/             顾客二级页（每张卡只添加自己的页）
  components/{customer-nav,customer-image,customer-state}/
  custom-tab-bar/                        受控底栏，统一选中态与安全区
  styles/customer-tokens.wxss            独立顾客视觉令牌
  features/customer/{fixtures,view-models,routes,...}.ts
  services/customer/                    组合既有请求核心，不复制重试/幂等实现
  store/customer-session.ts             复用 session.ts，顾客键与员工身份隔离
  typings/customer-view.ts              仅页面 ViewModel；API 类型来自生成契约
  assets/customer/                      小图标/品牌资源；大图按包预算处理
```

以上新增路径是计划，不代表当前文件已存在。各页面保留自己的 WXSS；仅确实复用的样式进入令牌/组件。
所有注册、app 配置、全局样式、路由表、共享数据形状的编辑串行。默认一次只执行一张卡。
每个新分包页面随本卡注册，不能提前造几十个空页面后声称功能完成。

服务端延续 Workers/D1；`backend/src/routes/customer-*.ts` 仅认领自己的顾客路径，复用领域规则。
接口路径、权限、对象、版本、错误码必须在对应契约卡冻结后再写实现，本文不虚构现有接口。
云服务迁移属于独立基础设施任务；这里通过环境/传输适配隔离，不顺手重写后端。

## 5. 谁维护小程序里的内容

| 内容 | ERP 内维护位置（计划） | 小程序发布规则 |
|---|---|---|
| 门店、首页图、主推横幅 | 设置里的“顾客展示”小面板 | 草稿/已发布分离，缺图不能静默替换原版画面 |
| 商品/整机方案 | 现有商品页面上的“对外展示”编辑 | 单独公开价、图片、规格、上下架；不直接发布库存原始记录 |
| 案例/知识/公告 | 同一顾客展示模块的文章编辑 | 标题、正文、类型、图片、日期、发布状态；下架立即对外失效 |
| 意向 | ERP “顾客意向”列表 | 店员处理后关联报价/回收/维修单；关联操作核对同一顾客与门店 |

这些是配套小任务，不能遗漏后让用户长期手改 JSON。草稿、未上架、内部附件不出现在公开 API。

## 6. 数据规则

- 公开内容允许匿名；专属报价、订单、档案、意向、售后与回收都按服务端顾客归属过滤。
- 不凭顾客自填手机号认领 ERP 客户。旧客户绑定使用经验证的身份/明确的门店认领流程，契约卡先确定。
- 分享令牌是访问凭证的一部分，不等于顾客身份；防转发越权、猜 ID、跨店、撤销、过期、旧版本和重复确认。
- 金额整数分；未知价不是 0。确认/下单/支付前服务端重读报价版本与应付金额。
- 未付款不预留、不采购；收款成功后若库存冲突，保留真实收款并进入门店处理，不把钱“回滚成没收到”。
- 图片标明示意/实拍；顾客附件默认私有，仅本人及获授权店员可读，不能借公开内容上传接口绕过权限。
- 拒绝授权仍可浏览公开内容；登录/网络失败保留安全草稿，切换身份时不带出上一顾客数据。
- 回收维修只读进度不是全部业务闭环；ERP 的收款、检测、回收取得所有权和交付规则继续生效。

## 7. 交付层级

1. **四屏视觉版**：MP00–MP15。可在明确演示环境中看图验收，不能当营业版。
2. **顾客业务版**：MP16 起的内容、登录、报价、订单、预约与进度。真实接口验收单列。
3. **完整交易版**：支付服务端确认、异常恢复与 ERP 闭环通过。
4. **可发布候选版**：开发者工具、iOS/Android、权限/隐私/域名/素材与包体检查齐备；发布仍需实际授权。

依赖行政或第三方配置时继续完成独立页面与本地测试；把阻塞卡标清，不能宣布整个产品完成。
