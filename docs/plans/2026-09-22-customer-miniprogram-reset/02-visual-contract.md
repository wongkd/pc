# 四屏还原规范

日期：2026-09-22。用户已确认组合基准；本文件是实现约束，不是新一轮设计提案。

## 1. 唯一基准与优先级

- 布局、照片、猫、图标位置：[清爽版](../../design/2026-09-22-customer-ip/four-tab-board-clean.png)。
- 字形和字重：[字体微调版](../../design/2026-09-22-customer-ip/four-tab-board-font-only.png)。
- 两图照片存在生成式重绘差别：**非文字区域以清爽版为准**。
- `home-visual-baseline.png`、最初 `four-tab-board.png`、ERP Core V2、旧奶油绿样式不再用于本任务裁决。

严禁新增渐变、彩色业务卡、厚投影、大胶囊导航、满屏猫贴纸，或把现有粗体当新基准。
禁止整屏截图充当界面；文字、列表、Tab 与按钮必须真实可交互。

## 2. 逐屏固定结构

| 屏 | 从上到下不可换序的内容 | 验收重点 |
|---|---|---|
| 首页 | 门店定位行 → 手写“装一下机”及“不挣钱，交个朋友” → 双猫/白色主机桌面主视觉 → 我要装机/回收置换/预约维修/门店与联系 → 分割线 → 横向推荐 → 底栏 | 首屏主视觉占比、画面裁切、四入口同一行；副句只出现一次 |
| 商城 | 商城标题 → 整机/配件/我的报价 → 纯粹性能主推图+选配置 → 热门推荐 → 两列商品图/标题/规格/价格/黑色动作 → 底栏 | 默认整机；不能改成纵向商品列表、报价列表首页或只两项分类 |
| 社区 | 社区标题 → 装机案例/电脑知识/门店公告 → 第一张大图卡 → 第二张较矮大图卡 → 左图右文的小知识行 → 底栏 | 图文比例和节奏不同，不能统一成同一种大卡；无消息/回复占位块 |
| 我的 | 我的标题/辅助图标 → 头像/昵称 → 米色装机档案卡+猫 → 四项数字 → 分割线 → 报价/订单/预约/售后四行 → 联系门店 → 右下手写短句和猫 → 底栏 | 档案卡、统计行、细线与留白的位置；不是订单后台仪表盘 |

商城图中的首页推荐包含整机和配件，按“推荐区混合陈列、分类结果单独筛选”处理，避免 AI 自行删掉显卡/显示器卡。
图中的示例金额、日期、门店名和记录数只用于固定视觉样本；生产来自真实数据，不能硬编码为事实。

## 3. 初始实现参数（待 MP00 测量修订一次后锁定）

源画板约 1536×1024，四个手机面板各约 355px 宽；这不是 375px 的原生页面截图。
先确定各面板**内容内边界**，去掉背景、外框、投影后归一化。不得将整张图拉到一部手机宽度比较。

| 参数 | 起始建议 | 约束 |
|---|---|---|
| 页面底 / 主文字 / 辅助字 | `#FFFFFF` / `#111111` / 近 `#808080` | 从基准平坦色块取样再锁定，勿采抗锯齿边缘 |
| 细线 / 米色卡 | 近 `#E5E5E5` / 近 `#F8F0DC` | 仅档案卡和金猫出现暖色；不恢复全页奶油底 |
| 内容水平边距 | 约 16–18px（375 视口） | 主视觉可满宽，列表边距统一，不给所有图片加同一外框 |
| 标题 / 正文 / 辅助 / Tab 标签 | 约 21 / 15 / 12–13 / 11–12px | 全为起始值，MP00 按字框测量；真机可读性复核，不凭喜好放大所有字 |
| 字重 | 常规 400，少量重点 500 | 不依赖平台未必支持的 350；原生中文系统无衬线字体，避免默认 700 |
| 图片圆角 / 按钮圆角 | 约 2–4px | 轻微圆角，避免 20px 卡片风格 |
| 触控区域 | 本项目目标 ≥44×44 CSS px | 可以扩大透明点击区域，不能把原图小图标强行画大 |

375 宽时 `rpx = px × 750 / 375`；430 等宽度按 `750 / 实际视口宽度` 换算，不能固定说所有设备 1rpx=0.5px。
固定字号、布局缩放与大字模式分开评估。不得用全局 transform 缩小一整屏来凑截图。

## 4. 素材清单与缺口

当前只有整张画板，没有独立的可交付原始素材。以下必须建立清单、尺寸/裁切、来源、用途与授权核实状态：

| ID | 资源 | 处理要求 |
|---|---|---|
| BRAND | 首页手写字标、副句 | 字标可用清晰透明图；副句用文本；不得随意找一种字体替代手写外形 |
| HERO-H | 首页白色主机桌面 | 保留机箱/显示器构图、光线和留白；无独立原图时标记缺素材 |
| HERO-S / BANNER | 商城主推 / 首页横幅 | 优先无文字图片+原生文字和按钮；图上的字不能再叠一遍 |
| PRODUCT-01…04 | 黑主机、白主机、显卡、显示器 | 不用仓库旧示意图静默替代；确认有足够分辨率再验收 |
| POST-01…03 | 奶油桌面、黑桌面、散热局部 | 各自裁切比例不同，记录焦点位置 |
| CAT-H/S/C/U | 双猫、银猫、金猫角标/档案/页脚 | 锁定已有造型位置和大小；不重新生成一套新 IP |
| AVATAR / ICONS | 头像、四服务、四 Tab 双态、菜单、二维码/设置 | 黑灰线性风格，不使用 Emoji；旧绿系图标需核对后才能复用 |

只有低分辨率画板裁切时可以供内部定位验证，但不得标记高清资产或最终视觉通过。
素材无法按图提供时，记录具体缺图编号；继续做独立卡，不能默默替换图片后宣布还原完成。
AI 位图生成/修改需遵循可用 imagegen 工具；本轮没有裁切、重绘或修改任何原图。

## 5. 微信系统区域差异

效果图是带手机框的概念稿，状态栏、微信胶囊和底部安全区由实际设备影响，不能把图里的“9:41”和电池图标画进页面。
顶部按设备真实安全区与胶囊位置布局；“我的”稿未画微信胶囊，二维码/设置需要避让真实胶囊。
该处在 MP04 留对照图并登记最小位移，其余业务布局不因此重排。
底栏统一四项和黑色选中态；先以原生 custom-tab-bar 组件实现可控间距，不引入第三方 UI 框架。

微信官方组件说明确认自定义导航以 `navigationStyle: custom` 为前提，见
[官方 WeUI Navigation](https://wechat-miniprogram.github.io/weui/docs/navigation.html)。
其余基础库/安全区/Tab 能力在 MP04/MP05 实施时按当前官方文档与开发工具复核；本轮直连微信文档未成功，未据此断言当前平台限制或资质。

## 6. 视觉放行规则

1. MP00 输出参考裁切坐标、归一化参考图、关键位置表；整张原稿永久保留。
2. 固定一组视觉样本：文本、图片、金额、列表顺序与原稿一致；单独标明演示环境，生产不能载入这些样本。
3. 每个 Tab 在 375、390、430 宽度截图；320 检查溢出；同一设备环境比较，状态栏/胶囊可单独遮罩，业务区域不能遮罩差异。
4. 原图与实图做并排、50% 叠加和差异图，记录具体偏差。项目目标：375 下主要对齐线偏差 ≤4px、关键图片比例差 ≤2%、字号偏差 ≤1px；这是本项目阈值，不是平台标准。
5. 字形抗锯齿跨平台不同，不用全图像素相同比例作唯一判定。结构、图像、裁切、字重、留白逐项人工看图。
6. 缺图、错图、模块换序、首屏大幅挤压、粗体回退、底栏不一致任一存在，视觉卡不通过；“功能正常”不抵消视觉失败。
7. 无参考的二级页按本规范实现，标记“延展页验收”，不声称逐像素还原原图。

最终必须有四屏微信工具截图及 iOS/Android 真机证据；浏览器模拟只用于快速排版，不能替代原生验收。
