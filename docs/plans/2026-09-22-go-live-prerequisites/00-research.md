## 0. 结论先行（TL;DR）

**A. 硬前置（必须串行的 5 步，前面没完成后面无法开始）：**
1. **办个体工商户营业执照**（广东免费、粤商通 APP 全程网办，材料齐全最快当天出电子执照）。
2. **微信小程序注册 + 微信认证**（认证需执照，费用 300 元/年，官方口径）。
3. **小程序 ICP 备案**（主体备案，2023-09 起新主体强制；需执照+法人人脸核验，约 1–3 周）。
4. **开通微信支付商户号**（需认证通过 + 法人个人银行卡即可，个体户无需对公账户）。
5. **域名 ICP 备案**（huangqidong.cn 已实名在 Cloudflare，需转入腾讯云做接入备案；需执照 + 国内云资源）。

**B. 可以并行的：**
- 步骤 2、3、4 的「材料准备/提交」可与小程序开发并行排期（备案期间小程序不能正式发布，但可开发、可提审）。
- ERP 网页本身的代码迁移（Cloudflare→CloudBase）可与上述备案步骤并行。
- 微信支付申请可在认证通过后立刻启动，不必等备案完成。

**C. 推翻 / 修正历史裁定的发现（重要）：**
- ❗**「CloudBase 免备案域名」说法是半真半假，不能直接当结论用。**
  - 真：小程序用**微信云开发原生调用**（`wx.cloud.callFunction`）走微信内部通道，**无需配置 request 合法域名、无需备案**。
  - 假：若小程序用 `wx.request` **直连 CloudBase 的默认域名**（`*.app.tcloudbase.com`），该默认域名**未备案、加不进小程序白名单**（腾讯云社区问题 #1219 实证）。真机/体验版会被拦截。
  - 修正：迁到 CloudBase 仍然正确，理由有二——① CloudBase **支持把自有备案域名绑到环境**（Cloudflare 境外做不到）；② 用云开发原生调用可彻底绕开备案。但**不能指望"CloudBase 默认域名天然免备案"**就用 wx.request 直连。
- ✅ 历史裁定「免费环境到期 = 上线后第 15 天」**被官方文档原文证实**（见第 4 节）。
- ⚠️ 微信认证费 300 元/年有官方/多家口径支持；个别第三方文章称"个体户 30 元"与微信官方 300 元冲突，**以微信官方 300 元为准**，30 元说法存疑。

## 3. ICP 备案（小程序备案 vs 域名备案）

**关键区分（务必分清两件事）：**
- **小程序备案（主体备案）**：所有新主体小程序强制，与小程序的"request 合法域名"无关，材料=执照+法人人脸核验。通过微信侧/腾讯云备案小程序提交。
- **域名备案（网站/API 备案）**：小程序里若用 `wx.request` 访问外部域名、或内嵌 web-view，该域名必须已完成 ICP 备案且**主体与小程序一致**。

| 项目 | 内容 | 性质 |
|---|---|---|
| 是否必须通过接入商 | 是。域名备案必须通过服务器接入商（腾讯云）提交，不能直接报工信部 | 事实（腾讯云官方） |
| 小程序备案材料 | 营业执照 + 法人身份证 + 人脸/视频核验（负责人）；无需另购域名 | 事实（腾讯云备案小程序流程） |
| 域名备案材料 | 域名证书（所有人与主体一致）+ 执照 + 法人/负责人身份证 + 视频核验 + 国内云资源（备案授权码/服务器） | 事实（腾讯云官方） |
| 时长 | 腾讯云初审 1–2 工作日 → 短信核验（24h 内）→ 管局审核≤20 工作日；广东等地实际约 5–7 工作日 | 事实（官方流程）+ 推断（广东提速） |
| 域名主体一致 | 域名实名所有人必须与备案主体一致，否则驳回 | 事实（官方） |
| 当前核验方式 | AI 人脸比对 + 视频核验（2026 多地启用，更严） | 事实（第三方综述，官方趋势） |

⚠️ **huangqidong.cn 现状提醒**：域名现由 Cloudflare 管理且未在国内接入商备案。上线小程序/网页需把域名**转入腾讯云做接入备案**（或保持 Cloudflare 仅做 DNS、在国内接入商取得备案号）。具体迁移路径**未核实**，以腾讯云备案控制台实际引导为准。

## 5. 迁移代价提示（Cloudflare Workers + D1 → CloudBase PostgreSQL）

> 要点级，非完整方案。推断为主，落地以实际代码为准。

1. **数据库引擎差异**：D1 是 **SQLite**；CloudBase PostgreSQL 是 **PostgreSQL**。SQLite 特有函数（`datetime()`、`last_insert_rowid()`、部分类型亲和）需改写。
2. **参数占位符**：D1/SQLite 用 `?`；PostgreSQL 用 `$1 $2 ...` 或命名参数。所有 SQL 需改占位符。→ **这是最常见、工作量最大的点**。
3. **事务与并发**：SQLite 单写、PG 多连接；原 Workers 里的 `env.DB.prepare().batch()` 写法要换成 PG 客户端事务。
4. **运行时**：Workers（V8 isolate，无 Node 全套）vs CloudBase 云函数（Node.js）。`fetch`/Web 标准 API 大多通用，但 Node 特有模块（fs、path）在 Workers 不能用、在云函数能用——迁移通常更顺。
5. **HTTP 访问 vs 云开发**：若改为 `wx.cloud.callFunction` 原生调用，前端 ERP（React 网页）**无法**直接用云函数，需另走 HTTP 访问服务（自定义备案域名）——网页端仍需域名备案。
6. **数据迁移**：D1 导出 SQL/CSV → PG 导入；注意自增主键、外键、索引重建。

**推断**：若小程序端改用云开发原生调用，后端迁移工作量中等；若网页 ERP 也要接同一后端，则需备案自定义域名 + HTTP 访问服务，链路更长。具体工时/风险**未核实**，建议先做一张 SQL 清单逐条对比。
