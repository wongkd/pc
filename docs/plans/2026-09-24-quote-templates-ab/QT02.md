## 按顺序实现

1. 复核 `startCreate/freshEditor` 与 `startRevise/editorFromDetail`：新建用默认八槽；已有报价只从服务端数据还原，禁止用八槽覆盖或填补旧单。
2. 将行类型与行构造统一到 QT01；页面不保留第二套空行定义、校验或金额解析。保留标题、版本、条款等页级校验与逻辑。
3. 配置区上方加入“标准独显 / 核显办公 / 旧机升级 / 空白报价”；仅新建显示场景选择。清楚呈现当前场景、兼容性提示及“已保留 X 项原配置”。
4. 每行类别单独显示，名称 placeholder 说明填具体型号；数量、单价、来源、商品/实物/设备选择沿用现有控件。保留可访问 label，现有测试的“第 N 行名称”等定位尽量继续可用。
5. 加入五类快捷追加并保留普通“加一行”；新建行按 preset/manual 区分。重复类别允许独立存在，行 key 不变；不要把新品、二手或客供误合并。
6. 切换遵循总计划的可见保留算法，只移除未动的非目标预置槽；用户手工删除有内容的行时确认，取消不变。不动客户/标题/条款等其他字段。
7. 来源切换清理不适用引用；进入客供强制价 0，离开客供价留空；客供/二手数量 1。全程保持现有服务端校验及引用要求。
8. 让创建、保存、保存并发出统一走校验成功的白名单 payload；校验失败不调用 API、不清输入。详情发出/续期读取的是服务端完整行，复用序列化时必须处理失败，不抛未处理异常或破坏旧 0 元行。
9. 汇总未完成时展示“已填金额合计 / X 项待完善”；全部未填显示“—”，不是 0 元已核价。保持现有优惠、预算、物流、版本、分享、顾客确认与转单流程。
10. 保存失败或结果未知保留表单、当前场景与内容，沿用现有 requestId/结果查询；禁用重复提交的既有行为保持。成功后显示实际服务端结果，不生成虚假成功提示。

## 页面行为验收

- 未填写的新建自动 8 槽，切空白后剩一行；已有填写内容时切空白须保留已填行。已有两行报价编辑仍两行，不出现预置残留。
- 仅填写一行合法商品时，其他未动槽位完全不进入请求；单独填价格/规格的槽位必须明确报错，不可消失。
- 有名无价格时 create/save/issue 都不发送；显式 0 及客供 0 按既有规则通过。
- 场景反复切换：共同字段与实物引用不丢；有内容的非目标行可见保留；不会复制显卡或手工同类行。
- 删除已填行取消不变；确认删除才改合计；未选新场景前不能预先修改清单。
- 来源变化不留下不适用引用；有效新品仍可暂不关联商品；二手及客供缺引用仍被拦。
- 创建失败、保存失败和结果未知都保留输入；原先权限、版本、续期、顾客确认、打印及转销售的用例继续有效。

不要删测试或放宽断言来适配错误行为。旧“结果未知”测试若用有名但没价格的样本，给样本补明确有效价格，继续验证其原本的未知结果行为。
至少增加一次成功请求 payload 精确断言、一次价格缺失零请求断言、一次已填场景切换保护、一次旧单不补模板和一次失败保留输入的页面测试。
