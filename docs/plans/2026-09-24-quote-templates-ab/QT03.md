# QT03 · 正式页面浏览器验收

日期：2026-09-24。前置：QT01/QT02 源码与回执存在，前端 test/build 已通过。
目标：验收本地 React `/sales/quotes` 的 A+B 体验，不用 8844 独立原型代替正式页面。

## 环境与范围

- 先核实网页的实际 `/api` 目标；只使用本机 Worker + 内存 D1。不得向任何远端环境写验收数据。
- 参照根 README 运行 `npm --prefix backend run dev:local` 与 `npm --prefix frontend run dev`。端口以实际日志为准，不盲杀其他会话进程。
- 本机登录与虚构验收数据按已有开发/测试入口建立；不改正式鉴权、不读取或记录密钥、不沿用真实客户数据。
- 可修 QT02 允许范围内的真实问题；不修改后端、契约、迁移或部署配置。
- 证据输出到 `docs/verification/2026-09-24-quote-templates-ab/`，浏览器截图不包含凭据。

## 最小验收链

1. 正式页面新建，检查默认八类、数量 1、型号/价格留空；试 Tab 连续输入与主要按钮。
2. 核显七类、升级五类、空白一行；在填写型号/价格前后分别切换，确认数量、引用和金额不丢。
3. 快捷加显示器和两行内存；不同输入独立保留，切场景不合并；删除有内容行的取消/确认行为正确。
4. 仅填价格、仅填规格、有名无价格、非法数量时，提示对应行且不提交；未动空槽不进入载荷。
5. 填一行合法示例商品并创建草稿；实际读回详情确认只保存该行、金额正确。再编辑不会重新塞入七条空槽，原报价版本正常。
6. 一份已有多行报价编辑后保存，核对原有商品/数量/单价与引用；客供和二手在本机可用测试资料下核对来源切换及缺引用提示。
7. 通过可控的本地断网或开发测试故障，验证保存失败/重试保留输入。不可通过“关掉服务器后随便报错”冒充结果未知；未知结果仍以已有请求层专项测试作为独立证据，若未浏览器制造就明确未实测。
8. 查看一份报价打印/预览，确认只包含实际商品行，不显示空槽、内部模板提示；不进行真实发送、成交、收款或库存操作。
9. 实看桌面与 390 窄屏；按布局需要补 320 检查。页面不整页横向溢出，内部表格滚动可接受；控件可操作、错误可见。仅浏览器尺寸模拟，不称手机真机测试。

浏览器工具不可用或登录环境缺失时，能完成的代码检查继续做；将具体未验证项写清楚，保持“待浏览器验收”，不能假写通过。

## 收尾

- 有代码修复时：跑相关定向测试后，串行前端全量 test → build；没有新改动不无故重复已通过检查。
- 文档更新后运行 `node scripts/check-doc-links.mjs`。
- 创建 `QT03.md` 回执：环境、实际路由、操作结果、截图索引、命令结果、遗留/未验证项。
- STATUS 与 NEXT 只更新本功能条目，保留其他会话改动。全部本地门槛通过才写“A+B 本地验收完成”；上线与远端验收另算。
- 不 Git 提交、不推送、不部署、不迁移、不扩展 C/D。完成后给用户结果入口与实际验证边界。
