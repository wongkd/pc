## 按顺序实现

1. 只读现有页面的 `EditLine`、`emptyLine`、`payloadFromEditor`、`validateEditor`、汇总以及 `quote-api.ts` 的 `QuoteLinePayload`，保持同一字段命名与业务规则。
2. 新行类型沿用原编辑行字段，可加仅本地使用的 `category`、`origin`（preset/manual/existing）及初始来源信息；不要往 API 类型加字段。
3. 行工厂产生稳定唯一 key，接收 key 生成器或等价可测试机制。创建时不要让两张报价共享对象引用；渲染时不得重新生成 key。
4. 实现三个场景和空白模式；默认行及来源严格按总计划。复用共同槽位，保留全部业务值，已填/手工行不丢，重复类别不合并。
5. 明确“未动的空槽”：名称、规格、引用均空，价格空，数量为默认 1、来源未改变。预置服务费来源本来就是 service，也算空槽；用户改变来源/数量或填了任意业务内容则应判为部分填写。
6. 有名的非客供行价格必填；空名但已填其他内容的行报错，不能仅 `filter(name)` 丢掉。数量必须正整数，不能四舍五入或取 `|| 1` 掩盖错误。
7. 非客供金额接受非负数字且最多两位小数，空串、非法、负数、非有限值须报错；使用整数分与安全整数检查，避免超大金额/数量乘法溢出。明确输入 0 有效。
8. 保持客供客户/设备校验、二手实物校验、新品转单前商品映射规则。创建行、校验和序列化不进行网络或存储写入。
9. 暴露序列化的成功/失败结果（判别联合或等价形式）；只有通过校验的行能生成 `QuoteLinePayload[]`，不能在失败路径用 `?? 0` 伪造价格。输出按原协议白名单构造，排除类别和场景元数据。
10. 汇总返回整数分和待完善行数，采用与校验一致的有效行定义；不承担预算、优惠或物流金额规则。

建议接口职责：创建预设行、应用场景、是否有业务填写、校验单行、校验并生成行载荷、统计行金额；名称可按现有风格调整，不引入类层次或通用表单框架。

## 必须覆盖的行为测试

- 8 / 7 / 5 类和空白一行正确，数量 1；名字/价格/引用不预填，服务来源正确。
- 重复创建对象/key 不共享；CPU 值在换场景后不变；同场景重复应用不重复造行。
- 独显→核显仅移除未动显卡；已填或仅填价格的显卡保留；核显→独显不复制保留行。
- 手工添加行、同类重复行保留；手工同类别存在时不另造空预置行；空白模式保留已填行。
- 单独规格、金额、引用、修改数量/来源均报缺项，不能被过滤掉；完全空槽不提交。
- 有名空价格被拦；显式 0 可提交；1299.00 → 129900 分；非法数量/金额/溢出被拦。
- 客供价为 0，必须有客户与来源设备；二手缺实物被拦；新品报价无商品引用仍允许。
- 有效行之外的内容不计入汇总；输出 payload 无 `key/category/origin/scenario` 等本地字段。
