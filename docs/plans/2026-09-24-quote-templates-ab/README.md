## 已确认范围与实施口径

用户明确确认的是 **A 常用配件预置 + B 按场景生成**。以下细节作为本期的实现与验收约束：

| 场景 | 默认类别顺序 | 默认来源 |
|---|---|---|
| 标准独显主机（默认） | CPU、散热器、主板、内存、显卡、固态硬盘、电源、机箱 | 新品 |
| 核显办公 | CPU、散热器、主板、内存、固态硬盘、电源、机箱 | 新品 |
| 旧机升级 | CPU、主板、内存、固态硬盘、装机服务 | 配件为新品；装机服务为服务费 |
| 空白报价 | 一条无类别空行 | 新品 |

- 所有预置行：名称、规格、价格和引用留空，数量 1。标签写“CPU”等类别，不能把标签塞进商品名称。
- 快捷追加：显示器、键鼠套装、机箱风扇、机械硬盘、装机服务；保留“加一行”，允许重复类别。
- 数量遵循商品售卖单位；一套双条内存默认数量 1，不擅自变成 2。
- 进入新建直接出现 8 类；不先弹强制选择框。场景条位于配置区上方，使用现有 ERP 风格。
- 核显场景提示确认 CPU 图形输出；升级场景提示核对原机与兼容性，不自动宣称兼容。
- 类别和场景只存在当前新建表单，不写 localStorage，不存服务端。成功保存后再次编辑，只显示已保存商品行，不补空槽或猜类别；既有报价不自动套模板。
- 空白报价也是“场景选择”，保护已填行。它不是一键清空全部数据。

## 切换与移除：本期采用可见保留

为让低档模型能实现并验证，本期不复制原型中的隐藏暂存数组：**切换只删除未填写的预置槽；所有已填写行与手动添加行留在清单中。**

1. 目标场景的共同预置类别复用原行和 key，保留名称、价格、数量、来源及引用。
2. 目标新增的预置类别生成空行；已经有相同类别的手工行时不再额外补同类空槽，但已有重复行不合并。
3. 目标不包含的空预置行可移除；已填写行、部分填写行和手动添加行一律保留并参与后续校验。
4. 顶部明确提示“已保留 X 项原配置，请核对”；保留行显示“原配置保留”。用户可手动删除。
5. 删除有填写内容的行要明确确认；取消保留原值，确认才移除。最后一行的现有限制保留。
6. 核显切回独显不得复制已有显卡行；重复点击当前场景不得新增行。切换不修改标题、客户、预算、优惠、条款或物流。
7. 配件/外设使用快捷追加按钮，不做“取消勾选即删已填行”。不需要隐藏数据、撤销栈或跨会话恢复。

行顺序：按目标场景类别顺序放置复用/新增行，同类别多行保持原相对次序；其余保留行追加在末尾并维持原顺序。
进入空白模式先保留所有已填或手工行，仅在没有剩余行时补一条无类别预置空行；这条自动空行不算手工添加，切回其他场景时可移除。

原型证明方案方向；此处的可见保留规则是正式接入时的具体保护方式，防止报价金额被隐藏行悄悄改变。

## 空行与价格：明确的三种状态

| 状态 | 表单与提交行为 |
|---|---|
| 未动的空槽 / 空白行 | 只含默认数量/来源、无业务输入：不计价，不提交；整单无有效行则提示至少填写一项 |
| 部分填写 | 只填规格、价格、引用、修改数量/来源等均不能静默丢弃；提示该行缺少的名称、价格、数量或引用，保留输入 |
| 可提交行 | 名称已填、数量合法；非客供价格必须显式填写。已有新品/二手/客供的引用规则保持 |

单价为空不等于 0：新建、保存、保存并发出均在请求前校验。手动明确输入 `0` 继续遵循现有非负金额规则，不新增最低价或收费政策；历史读回的 0 仍是明确数值。
客供价固定 0，必须有客户及来源设备；二手必须选具体实物；新品商品引用仍保持“报价可暂缺，成交前必选”的现有规则。
来源切换清掉不适用的引用，避免切回后自动复用过期实物/设备；进入客供价为 0，离开客供价格留空待填。不要删除客户、设备等实际记录。
合计只累加有名称、合法数量和合法价格的行；有未完成行时标记“已填金额合计 / X 项待完善”，不能显示整单已核价。预算不计入合计，金额仍以整数分提交。
“待完善”只统计已经开始填写却不合法的行；未动的空槽可另显示“X 个空槽不提交”，不能要求把全部预置配件填满才能保存。
