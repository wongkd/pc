## D01 / D02：B39 报损、B40 改价

- B39 仅处理门店自有、可用库存；数量正整数，逐件固定1，事务内校验余额、状态、权限与版本。客供、送修、暂存、已售、预留、隔离件不可直接报损。
- 原因“其他”必填说明；记录数量、成本口径、依据、操作者、时间。B39 来源为 `damage_writeoff`；盘点差异用 B16，回收拆件损耗用既有 `scrap`，隔离判定用 B19，不互相替代。
- 老板确认录入即生效；误报追加关联纠错事件。丢失后找回须先检测，不能直接恢复可售；已销毁或有后续业务时禁止机械反冲。纠错能力未交付前不放行 B39。
- B40 记录旧价、新价、原因、备注、操作者和版本；金额整数分且不为负；零挂牌价须明确理由及二次确认。成本、已有草稿行价、已发出报价和成交单均不自动变化；草稿显式选用新价，已发出报价变价须新版本及顾客重新确认。
- 店员可报告问题，首版不做店员审批流；销售结算加减价另立动作。**B16、B30、商品通用编辑不得作为 B39/B40 绕行入口。**

## D03：已付款采购如何冲销后取消

源码核查：`backend/src/domains/finance.ts` 的 B34 用于纠正误录，新增等额反向分录；`purchase.ts` 在有净付款时拒绝取消。已有反冲后取消的测试只证明算账路径，**不证明供应商真实退款接通**；旧文档“没有付款反冲动作”的描述在此纠正。

| 情况 | 冻结处理 |
|---|---|
| 误录、实际没付钱 | 老板用 B34 纠正，关联原笔、原因和凭据；真实付款不能谎报为误录 |
| 实际付款后供应商退钱 | 独立供应商退款动作；核实到账后记录，关联采购、原付款及凭据；不复用误录反冲 |
| 多笔付款、分次/部分退款 | 每笔正整数分，累计不超原付款剩余可退额；原笔保留；原笔和退款各计算一次 |
| 退款失败/处理中/未知 | 不先减少净付款；核对原请求，不能换请求重复入账 |
| 净付款归零 | 仅取消未到数量，事务内复查；并发付款/取消按前置条件决胜 |
| 部分到货仍有净付款 | 首版不支持按未到部分分摊后取消，保留单据；不伪造全额退钱再付款；已到货退供独立处理 |
| 留存抵下次货、拒退、手续费 | 不能视作现金已到账；供应商贷项和差额核销首发暂缓，保留未结项及凭据，不能反冲凑零 |

守恒：`ordered = received + rejected + cancelled + pending`。退款不增加库存；功能未完成的真实退款不能标成功或据此取消，线下事实保留凭据，接通后防重复关联补录。

## D04：回收报价后能否重新议价

报价自发出起有效24小时。仅老板能撤回未接受报价，必须填原因，保留旧价及检测依据，旧版本失效、新版本重新计时。过期不得接受或取得所有权，也不代表顾客放弃设备。

客户已接受但未取得所有权时，须双方取消接受后重开；依据为顾客端确认、签字件或可核验聊天附件引用，仅员工备注“客户同意”不足。撤回与接受并发按版本原子校验。

已取得所有权、付款、折抵、拆件或整备后，不靠重议价修改成本；转独立资金与资产更正流程。新动作未交付前保持暂缓；“归还重开”仅适用于设备确已交还、原单已结清的情况，不能账面假归还。

## D05：配送阶梯

| 驾车距离 d | 费用（普通送达，不含上门安装） |
|---|---:|
| 自提或 `0 ≤ d ≤ 10km` | 0元 |
| `10 < d ≤ 20km` | 30元 |
| `20 < d ≤ 30km` | 50元 |
| 超30km、无路线、地图失败、跨水路、额外停车/搬运 | 人工报价，付款前确认明细 |

首版员工记录高德驾车推荐路线：门店起点、顾客确认的终点、距离米数、时间和截图，不依赖未接入的地图API。按原始米数比较，不先四舍五入或进位公里；路线/门店地址缺失显示待人工报价，不能默认为免费。

同单同次配送收一次；门店造成分批不重复收费；顾客主动要求多地址/多次配送须另行确认。改地址生成费用新版本，已付款差价独立补退；差价动作未完成前暂停改址发货。普通配送确认后不能单方追加停车等费用。

未出发且服务未发生时退配送费；已发生服务依 D06。退货取件单独认定责任：门店过错/适用质量退货由门店承担，顾客原因按适用规则和事前确认处理，不自动套用配送阶梯扣款。

## D06 / D07：定金、退款、保修

### D06 首版收款及退款

顾客用语统一为“预付款”，现货、订货、装机统一15%；门槛为最终确认应付金额（含已确认配送/服务、扣优惠）×15%，向上取整到分。这是本轮补齐的首版选择；现有 `depositPercent` 字段不因此直接改协议。**法律定金罚则首发暂缓**；历史已明确约定法律定金的订单逐单处理，不追溯改名。

未核实付款不预留、不采购；已核实净收款与同客户同销售单的有效折抵达到门槛才尝试预留，折抵不冒充现金。零价/纯客供单走老板批准的特殊履约流程，未实现前不靠0%绕过。超付列异常款核对，不自动当营业收入。高风险专门订货若15%不足覆盖风险，首版由老板选择不接单，不临时追加未确认的不退条款。

| 取消原因/阶段 | 首版处理 |
|---|---|
| 未采购，无收费服务发生 | 全退已收预付款，无固定手续费 |
| 已采购未装机 | 可退/可转售货物不能按采购全价扣款；有事前告知、可证明的不可回收净损失，由老板核对，依合法结算依据处理 |
| 已装机/有服务 | 仅核实实际完成且事先约定的服务及净损失，扣除已回收价值，不重复收费；争议不自动扣 |
| 门店缺货/取消/过错 | 退回应退已收款；额外补偿由老板依实际责任批准并独立记账，不设自动补偿额或免责上限 |
| 已交付、质量退货、网购无理由 | 先识别适用依据和责任；不把全部组装电脑认作不退的定作商品 |
| 部分退货、现金加折抵 | 按原行价/优惠分摊确定应退；现金和折抵分别处理，不把折抵直接兑换现金；未支持分摊场景暂缓自动处理 |

普通协商取消的本次应退现金，以取消部分可退的原现金净额扣除有合法依据且双方确认的本次扣款确定；不得为负或超过剩余可退现金，也不能与其他退款重复。法定应退款优先，无争议部分及时处理；额外赔偿另记。禁止系统默认“15%一律不退/退款扣10%”。

退款申请、批准、处理中、成功、失败/未知分开。优先原支付路径，特殊改路径核实原付款人及凭据。仅在服务端核实渠道成功或老板核实线下实际支付后标成功；创建申请、客户端回调或释放库存都不等于退款。退款并发和重复通知守住剩余可退额度。

### D07 首版保修承诺

| 类别 | 冻结口径 |
|---|---|
| 全新配件整机 | 本店购买且全部全新配件组装，提供1年基础店保；法定责任、适用厂家保障及本店既有更优承诺不受影响 |
| 新旧混合整机 | 本店售出新件1年、二手件1个日历月基础店保，逐件按来源记录；不可把全机保障压成最短期限 |
| 全二手配件整机 | 本店购买且全部二手配件组装，提供1个日历月基础店保；披露成色/检测/瑕疵；历史已承诺3个月等更优内容继续履行 |
| 客供件 | 不承诺非本店销售硬件的原厂质保；本店安装工艺保修90天，自交付起，覆盖本店接线/固定/工艺问题；本店造成损坏不能以客供免责 |
| 人工/上门 | 保障范围内必要店内维修人工包含；未约定的上门服务先单独报价，依法依约应由门店承担的费用不能转嫁 |
| 排除项 | 正常耗损及与故障有因果关系的人为/进液等需检测依据；不能仅凭拆封、划痕或“二手”拒绝全部保修；争议保留原始记录复核 |
| 延保 | 全二手整机可选总保障3/6个月；按纳保二手硬件净成交额5%（最低99元）/8%（最低159元），比例结果向上取整至整元。[专项文档](d07-warranty.md)为完整规则；费率已采纳且打印展示，独立选择/收费/订单快照流程完成前不得收款 |

维修占时、换件/换机期限按适用规定顺延/重算，不能沿用失效日期拒保。原承诺保留，未知数据不生成确定到期日。单据无纸质发票但有有效购买证据时应核对证据，不机械拒绝。

完整顾客用语以[D07打印文案](d07-warranty.md#打印预览底部文案)为准；基础规则和首期延保费率已采纳。不得将未选择、未付款的服务显示为已购买；不能编造订单到期日。

### 本轮核对依据

15%预付款、配送阶梯及90天工艺保修是门店经营选择；以下用于约束条款边界。

- [《民法典》第586–588条](https://www.court.gov.cn/zixun/xiangqing/233181.html)：法律定金有金额限制和双方违约后果，不能简化为取消即没收。
- [微型计算机商品三包规定](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/zlfzs/art/2023/art_c9589427b6c84652ab2ed362caa8b875.html)：按商品类别处理三包、维修/更换责任和期限。
- [网络购买商品七日无理由退货暂行办法](https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/202101/t20210104_146551.html)：例外范围和商品完好判断不能任意扩大。本轮读到官方搜索正文，直开失败；发布顾客条款前重核全文及当时适用性。

## D08：旧商品页与新库存页的职责边界

`/inventory` 为日常入口；`/inventory/products` 作为“商品目录”二级入口，不独占主菜单，保留旧URL和历史查询。商品目录管型号、规格、追踪方式及新型号初始挂牌价；既有商品调价只能走 B40，暂缓期间通用编辑不得绕过。

库存页管实物、数量、桶态、到货、期初、预留、盘点、待检、整备和流水；型号数不冒充库存，旧SN台账不叠加计库存。有历史库存/单据的商品不删，停用仍可查历史、售后和履行原合同；禁止新普通销售。已有流水的追踪方式不直接切换。旧库存快捷操作在新入口及服务端权限验收后迁走，未接通操作明确暂缓。

## D09：状态机契约口径

状态是业务阶段，已完成资金/库存是不可覆盖事件。以下为业务语义，工程须映射现有契约，不能直接把用词写进枚举。

| 对象 | 冻结转换与例外 |
|---|---|
| Reservation | 生效后消耗/释放/过期。老板手工释放须原因；预留复核期7天，提前24小时提醒；已付款/采购中/装机中不机械自动释放，转老板复核。可每次续7天并留痕，顾客同意取消且无在途写入后才释放，释放不退款 |
| ReturnRecord | 申请→待验收→接受/拒绝；退回先待检，部分接收按行记。未发货可先退；已发货未收回原则待收回，老板凭物流丢失或明确无需返还的依据可批先退，不伪造收货 |
| Offset | 建立→使用→撤销，撤销新增反向事件。交付前撤销重算欠款并阻止余额不足交付；交付后单独撤销首发暂缓，须先做销售/回收联动更正 |
| Operation | 未完成/成功/明确失败分开；outcome_unknown 为不能确认，不是回滚。按2/5/10/20/30秒退避查原请求，2分钟转人工待核对；安全重试只用原键原内容，过期不得换键盲写；持久枚举兼容性由契约实施确定 |
| CashEntry | 记录与核实分离；现金由老板核对，人工登记微信/支付宝/银行须到账证据；在线渠道由服务端通知/查单核实；误录反冲和真退款分别关联原笔，不反冲反冲笔 |
| Product | 在售→停用；仍可查历史、售后及原合同补发（老板关联原单）；不能进入新普通报价 |
| QuoteVersion | 草稿→发出→接受/过期/替代；发出24小时有效、提前2小时提醒，续期24小时留痕并告知。接受后无关联销售/款项可凭双方依据撤销重开；有关联先处理销售及结算，不改旧账 |

报价过期不删除晚到的真实付款：记到账事实并转核对，不抢占已售库存。提醒未接通时列到期队列人工处理，不能显示已自动通知。

## D10：期初成本与流水

| 类型 | 记录与销售边界 |
|---|---|
| known_actual | 实际成本和金额；来源备注可选 |
| assessed_estimate | 估算金额，日期由系统记录；可销售，毛利标估算并在报表分列 |
| unknown | 成本为空而非0；销售须老板逐件/批次批准例外，毛利未知，汇总披露未覆盖数量与收入 |
| zero_cost | 填 0 表示确实零取得成本；可销售，不和未知混用，来源备注可选 |

> 本节原有的全店限时窗口和逐行凭据要求已被下方 2026-09-26 的轻量化决定替代，保留在此供追溯。

老板在正式切换时开启期初窗口并写截止时间，最长7天；第一笔正式经营出入库或截止时间到达即关闭，以先到为准。预览数据不启动正式窗口；不虚构上线日历日期。关闭后漏项走独立补录/调整（首版暂缓），不能重开期初补采购。

每行须批准盘点依据，防同一盘点行重复导入；仅门店自有存量，客供/送修/暂存/未取得回收不入期初。在途采购、未结应付另迁入，期初不自动生成现金/债务；历史销售退货不能再次期初入库。

售前补证、售后纠错均追加调整保留原值；售后关联原销售和成本差，不改旧销售快照。数量件混入未知时平均成本/毛利不能按0计算，估值不能冒充实际；原取得日未知则库龄未知，导入日仅表示系统入账日。

### 2026-09-26 小店轻量化调整（用户确认，替代限时窗口流程）

- 商品档案随时可建，默认库存为 0；登记库存失败时保留商品，用户可以之后继续。
- 店里已有库存按商品登记，不再要求先开启全店 1–7 天窗口；同一商品的现有库存仍只登记一次。之后新进货走采购到货，已有库存事实的数量差异走实盘处理。
- 表单只保留数量、可选成本和备注；成本留空表示未知，填 0 表示确实零成本，正数可标为实际或估算。估算日期自动记录，系统自动生成登记编号并记录操作人和时间。
- 生产当前仍运行旧版窗口流程；本地实现完成并通过验收后，才能另行安排发布。此决定不授权生产建档、库存写入或部署。
