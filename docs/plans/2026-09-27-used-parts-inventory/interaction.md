# 页面、操作与文案规格

日期：2026-09-27。状态：方案建议，未实现。总入口见 [README](README.md)。

## 1. 找配件

1. 打开仓库，选择 CPU 或显卡等分类。
2. 默认看该分类的自有在库；可选“可售”“待检测”等状态，输入型号、规格、内部编号或 SN 查找。
3. 列表直接显示每件配件，点行查看详情；返回时保留筛选和滚动位置。
4. 报价和装机选件沿用同样的分类与单件辨认方式。选入报价不扣库存，也不提前占用；实际预留和交付仍由相应业务动作执行。

“全部配件”下每行标明部件名称；类别页中型号与规格优先，避免每行重复大量分类文字。线材等按数量呈现，不虚构逐件编号；批次收货数量不等于当前剩余数量。

## 2. 登记已有配件

入口：仓库 → 选择 CPU → 登记配件。单页字段示例：

```text
登记 CPU
型号 / 规格    [i5-12400F                ]
来源           店里已有 / 新买到货 / 回收或置换 / 整机拆件
数量           [1]        二手（可切换新品）
检测情况       待检测 / 已检测正常 / 有问题
单件成本       [       ]  不知道可以留空
状况说明       [散片，无维修，触点正常       ]
更多信息       厂家 SN、品牌、来源说明、附件…
                              [保存并继续] [保存]
```

来源对通用入口不预选，避免日常买来的货被记成开店前存量。专用“登记已有配件”快捷入口可预选“店里已有”；来自采购或回收单的入口必须带入原单据。

已选型号可以复用基础资料；没有匹配项时直接用输入建立资料。不要先跳去建商品、再返回重选。

型号候选显示类别与关键规格。不能仅凭“3060”或同一个文本名称自动合并不同显存、接口、品牌版本；不确定时让店员选择候选或保留为新的明确描述。品牌可选，不能据未知信息猜测匹配。

初始登记只需可辨认的型号/规格；暂不清楚的细节写备注，待补充。内部编号由系统生成，扫码是可选提速方式。

“已检测正常”由店员明确选择并保存检测事实；默认“待检测”。“有问题”保留问题说明并进入待处理。三者的服务端流转必须落地后才能开放，不能在前端切标签模拟。

## 3. 一次登记多件

先填共同的类别、型号和来源，再输入数量。主要配件数量大于 1 时展开每件明细，共同成本可批量填写，每件可单独修改。

| 件 | 型号 / 规格 | 成本 | 检测情况 | 状况说明 | SN |
|---|---|---|---|---|---|
| 1 | i5-12400F | 430 | 已检测正常 | 散片 | 选填 |
| 2 | i5-12400F | 460 | 待检测 | 带包装 | 选填 |

支持“再加一种配件”和“复制这件资料”；复制仅带入基础资料，SN 清空，检测和成本是否沿用由明确的批量设置决定。删除某行不影响其他输入。多种配件无需反复关闭重开弹窗。

成功后只清空已成功保存的行。若批量接口按行提交，应显示每行结果、保留未提交行和请求标识；整体事务则整批成功或失败。实施时固定一种明确契约，不能显示整批成功却只保存部分。

## 4. 其他来源

| 场景 | 店员操作 | 库存与金额处理 |
|---|---|---|
| 已买到手的二手配件 | 选“新买到货”，填写来源/卖方、配件明细、实际成本和检测情况 | 复用到货来源；支持直接到货或关联已有采购单，买来二手件必须仍是二手；登记库存不自动记成已付款 |
| 已下单但尚未收到 | 在采购页记录订单，到货后继续登记 | 在途单列，不先计在库 |
| 顾客拿来出售或置换 | 选“回收 / 置换”，带入已填配件信息进入回收单，按检测、议价、确认收购处理 | 未确认收购前属于客户暂存；抵款需选择同一客户的销售单 |
| 整机拆出配件 | 选“整机拆件”，选择源设备后填 CPU、主板、内存等产出 | 源设备出库、产出入库和成本分摊保持关联；不能当无来源配件直接增加库存 |
| 对已有记录核对数量 | 更多 → 盘点库存 | 先记录差异；当前不能通过盘点直接减少账面库存，按既有授权动作处理 |

入口可汇合，来源单据与付款事实仍需准确保留。页面切换传递草稿，不让用户重复填写型号、SN、状况；单据尚未保存前不能丢弃表单。

## 5. 单件详情

- 首屏：类别、型号/规格、内部编号、当前状态、状况说明。
- 按权限显示成本；实际与估算分别标识，缺失成本显示“待确认”。未知成本销售仍受既有守卫，登记成功不代表所有后续销售条件已满足。
- 来源：店里已有 / 采购到货 / 回收 / 拆件，并可回到相关单据。资金记录单独查看。
- 下一动作随状态出现：待检测给“记录检测”；有问题显示问题及适用处理入口；可售可用于报价；已预留显示关联订单；已售从历史记录查看去向。
- 不显示一整排无关按钮；无权操作保留必要状态说明。单件通用检测、整备和售价维护不能假设已有回收专用接口全部支持。

## 6. 引导只在有用的位置出现

| 场景 | 文案或操作 |
|---|---|
| 全店首次进入 | “还没有登记配件”＋“登记第一件配件”；次级入口“登记店里已有的配件” |
| CPU 类别为空 | “还没有登记 CPU”＋“登记 CPU” |
| 搜索为空 | “没有找到符合条件的配件”＋“清除筛选”；保留分类与输入 |
| 已有档案但没有数量 | 在登记中自动复用档案；档案本身不占库存列表一行 |
| 保存成功 | “已登记 2 件 CPU”＋“继续登记 / 查看库存” |
| 只保存了资料 | “资料已保存，库存还没登记。继续登记即可。” |
| 写入超时未知 | “暂未确认是否保存成功，正在查询结果。”；不能直接换请求重复提交 |
| 同型号再次整理出一件 | 页面接入 B47 存量补录并展示近期相似登记，核对后保存；无 SN 时只提示人工复核 |
| SN 命中已有实物 | 显示可查看的既有记录，由店员核对；不生成第二件库存 |
| 无 SN 的相似记录 | 提示近期相似登记供核对；不把相同型号自动判为同一件货 |

## 7. 操作体验

桌面采用窄分类栏、宽列表和侧面详情区；登记使用独立宽面板，长表单的保存区保持可见。手机使用分类条和逐件卡片，登记为单列全宽页面，不压缩成密集多列表格。

键盘可完成型号选择、数量和成本输入、保存并继续；选项有标签，错误靠近字段，关闭未保存表单需保留草稿或提示。加载失败给重试，不把错误当空库存。表单默认值不能覆盖用户已经输入的内容。

界面不出现契约编号、数据库术语、整数分结算、幂等键、正式窗口等内部说明；对用户有影响的权限、保存结果和成本含义用具体中文解释。
