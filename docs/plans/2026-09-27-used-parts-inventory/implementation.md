## 2. 数据与规则调整建议

U01 已按下述“分类和逐件读取”目标完成本地读接口实现。U02 决策已确认并按下述语义落地，当前实现状态与剩余验收边界见 U02 回执。

### 分类和逐件读取

U01 增加按类别、库存桶、成色和关键词筛选的服务端读取：逐件实物与数量型号汇总各自分页，数量模式不伪装为逐件行。查询范围先限定门店与权限；成本缺权限时不返回。实现入口和过滤字段见[U01 回执](../../verification/2026-09-27-U01-inventory-read/README.md)。

分类总数独立于当前页，并明确“件数”口径：自有在库包含可售、预留、待处理；不包含已售、客户暂存和在途。具体分类里同型号多件不能只返回一行后依赖逐行查询，避免请求数量随页面行数增长。

类别先复用现有 category 值，统一显示别名时保留原值映射；例如硬盘下可筛固态/机械，不做无依据的存量字符串覆盖。未知/自定义类别仍可进入“其他”，旧记录必须可找回。

### 型号资料与实物身份

登记时后台复用匹配的型号档案，创建实物；型号资料匹配与重复实物检查是两件事。不同容量、接口或明确不同版本不能自动合并。厂商未知可以空着，不作为创建阻塞。

新主要配件默认逐件；已存在按数量管理的型号不能直接改 trackingMode。首轮允许保留旧数量行，新登记遇到同型号数量档案时显式说明并进入兼容处理，不能自动另造一份同名档案。涉及历史余额到逐件的转换另有审计方案及迁移验证后执行。

### 同型号分批补录

用户已确认采用独立 B47 补录动作，按批次 / 明细 / 实物身份留痕，同一型号可分次登记不同实物；B13 原首批期初守卫保持不变。新买配件继续走到货来源。

客户端首次请求前持久化 `batchRef` 与每行 `lineRef`；未知结果重试沿用相同批次与行引用、相同 requestId 和载荷。已落库请求回读原结果；相同 `batchRef` 换 requestId 被拒绝，不再次增加数量。记录来源、操作者和时间。

SN 等可靠唯一标识命中时阻止重复实物；没有 SN 的相似件只提示人工复核，不承诺自动判重。幂等只能防重复请求，不能保证人工用新草稿重复数同一件货一定被发现。

已补录后再发现数量不对，走正式核对/纠错流程；不把补录变成任意覆盖余额。客户财产不允许登记为存量自有件。

### 二手、检测与定价

采购与存量登记都要支持真实 new/used 字段。逐件实物检测状态独立保存：历史未记录显示 `unrecorded`；新进入实体待检状态为 `pending`；通过与失败都写追加事件。B19 只有通过可进可售且必须有有效证据；失败留在待处理，先经 B48 登记返修完成，再以新 requestId 复检。数量型号没有逐件检测状态，不从库存桶推断。

通用检测入口复用可适用的检查能力，并核对所有来源的权限、状态和版本约束。回收上架中对数据清理的要求应按是否存储数据区分；CPU 等需要明确“不适用”语义，不能为了绕过校验伪记“已清除数据”。

首期库存列表不新增通用改价能力。报价沿用所选实物的真实状况和本次报价价格；若需要维护每件挂牌价，应另落实读取、编辑权限、价格历史及 B40 边界。未知成本与估算成本不混为实际成本，也不自动按 0 计算利润。

### 保存与资金

可以在单个表单内继续复用“保存档案 → 登记库存”两次操作，但必须保存阶段和请求标识，明确部分成功并支持续办。不得宣称前端串联已成为数据库原子事务；如改为聚合命令，要在契约与后端实现中保证其事务边界。

收货和收购不自动写“已付款”。快速到货后若需要登记实际付款，应有可关联的业务凭据和既有权限链；若现有无采购单路径无法闭环，应在同一界面后台生成可关联的采购单并处理部分成功，不让店员另起一套账。

## 5. 核心验收场景

1. 无型号档案：选 CPU，输入 i5-12400F，成本留空；资料与一件二手实物建立，状态正确，编号自动生成。
2. 同型号两件：成本 430/460、检测不同、SN 不同或均为空；两个实物可辨认，各自成本和来源准确。
3. 同型号第二批存量：昨天登记一件，今天又整理出一件；不需重复建型号；重试同一保存只有一件新增。
4. 新买二手显卡到货：保存后仍是二手；重复到货请求不增加第二次；没有实际付款记录时不显示已付款。
5. 待检测、有故障、已检测正常三种路径；从列表到报价/交付均不能绕过库存可用状态。
6. 型号超过 100 个，翻页后类别统计、SN 搜索与新型号选择正确；不依赖一次加载全部数据。
7. 商品资料成功而入库失败、入库成功但响应丢失；保留输入，查询结果和续办不重复建档或加库存。
8. 同型号不同显存/容量、同名不同品牌、旧数量库存兼容；不误合并或擅自改管理方式。
9. 客户回收未成交、整机拆件、销售交付、退供和售后引用仍可追溯；价格与成本按角色隔离。
10. 桌面和 390px 窄屏实看列表、登记多件、错误与空态；键盘保存并继续、触控与返回草稿可用。

实施时针对上述真实业务风险选测试；网页 test/build 串行，契约和迁移有改动再跑对应门禁。本轮规划只做文档链接检查，不把历史测试、源码阅读或静态原型计作业务验收。
