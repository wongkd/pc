## 1. 店员围绕“哪类配件、哪一件货”工作

仓库第一层是 CPU、显卡、主板、内存、硬盘等配件类别。进入类别后直接看在库配件；每件保留型号、规格、状况、成本、来源和内部编号。

例如两颗 i5-12400F：一颗成本 430 元，另一颗成本 460 元；一颗已检测，另一颗待检测。两颗都放在 CPU 下，默认显示为两件独立库存。型号可用于搜索和筛选，不能把两件货的状况、成本及来源合成一个值。

品牌作为选填属性，需要时补充；型号/规格用于辨认货物，仍需填写。不能把所有 CPU 都建成一个商品，也不能为每颗相同型号的 CPU 重复建一个商品档案。后台继续复用型号档案和实物记录，店员无需先进入另一页面维护档案。

已确认的主营方向取代旧版“分类、品牌、商品名称、SKU、参考售价、管理方式”作为首次登记主线的安排。历史方案和发布回执保留追溯。

## 2. 仓库首页

保留导航名“仓库”，默认展示自有在库配件。顶部只保留搜索、主按钮“登记配件”和“更多”。

```text
仓库                    搜索型号、规格或编号      [登记配件] [更多]

全部配件   CPU   显卡   主板   内存   硬盘   散热器   电源   机箱   更多

全部在库   可售   已预留   待检测   待处理

配件 / 型号与规格     状况说明        库存状态     成本      编号
CPU · i5-12400F      正常，无维修      可售         ¥430      …001
CPU · i5-12400F      待测             待检测       ¥460      …002
显卡 · RTX 3060 12G  风扇异响         待处理       ¥680      …003
```

上例为方案示意数据，不是门店库存或验收证据。

- 分类为常驻一级筛选。桌面可采用左侧窄分类栏，右侧库存列表；窄屏用可横向滚动的分类条。
- 列表默认逐件呈现主要二手配件，不必先展开某个型号才能找货。同型号合并查看是辅助选项。
- 成本按权限返回与显示；未知成本写“待确认”。列表不把商品参考售价当作每件二手货的售价。
- 型号与规格保持清晰；内部编号作为辅助辨认信息。点一件货打开详情，查看来源、成本、检测和销售关联。
- 客户暂存、已售记录、在途等放在更多视图中；不计入自有在库。操作记录、盘点、商品档案和清理工具降到“更多”。
- 状态筛选与分类数量由后台按同一范围统计，不能拿当前页数据当全店统计。
- 删除原“从配件实际来源进入 / 实物收进来，或确认交出去”整块引导区，让配件列表进入首屏。

## 3. 登记配件：一个页面完成

从 CPU 类别点“登记配件”，类别自动带入。登记表单的阅读顺序如下，不拆成多页向导：

| 顺序 | 店员填写什么 | 推荐行为 |
|---|---|---|
| 1 | 配件类别 | CPU、显卡等；带入当前分类，可修改 |
| 2 | 型号 / 规格 | 如 i5-12400F、RTX 3060 12G；可选已有记录，也可直接输入新型号 |
| 3 | 来源 | 店里已有、新买到货、回收 / 置换、整机拆件；通用入口需选择，业务页面进入则自动带入 |
| 4 | 数量与状态 | 默认 1 件、二手；未确认检测结果时默认待检测，不能自动标为可售 |
| 5 | 单件成本与说明 | 不知道可留空；填 0 表示确实零成本。状况说明如维修、暗病、缺配件等 |
| 6 | 更多信息 | 厂家 SN、品牌、来源说明、附件等按需展开；不要求先编 SKU 或建供应商档案 |

保存后显示“已登记 1 件 CPU”以及“继续登记 / 查看这件配件”。只有真实写入成功才显示成功；资料保存但库存失败时提供继续登记，超时未知时先查结果。

具体来源的关联、批量录入、默认值与异常见[交互说明](interaction.md)。

## 4. 二手业务默认值

- CPU、显卡、主板、内存、硬盘、电源等可独立交易或售后的配件默认逐件记录；线材、螺丝等耗材可按数量。已有数量库存不能自动切换为逐件库存。
- 默认二手，保留新品选择；“新品 / 二手”和“已检测 / 待检测 / 有故障”是两组不同信息。
- 数量为 2 或以上时可复制共同型号资料，但为每件生成独立编号，支持不同成本、SN 和状况；复制时不复制 SN。
- 型号不是必选的预置字典。输入能识别配件的型号与规格即可；品牌未知不阻塞，不能为了填满字段编造品牌。
- 不要求录入时设置统一参考售价。报价时对所选实物定价；已有回收上架定价继续按原业务规则。通用单件售价维护与改价另列依赖。
- 来路不明的客户物品不能用“店里已有”登记成自有库存；回收确认、拆件来源链继续保留。
- 分批整理货架时，同型号第二批已有配件应有补录路径。此项需要改后台规则，不能靠反复新建同型号档案绕过。

## 5. 引导与文字

页面标题说清当前位置，按钮说明动作；字段附近只解释会影响填写的规则。业务规则放在对应操作旁，不把技术实现和整段规章常驻首页。

| 现有文字或安排 | 新安排 |
|---|---|
| 实物收进来，或确认交出去 | 删除整个宣传式标题区；保留“仓库”与具体操作 |
| 新增商品 / 登记现有库存并列 | 主入口“登记配件”；商品档案移到更多 |
| 分类 / 商品名称 | 配件类别 / 型号与规格 |
| 管理方式、SKU 占主要位置 | 类别默认逐件或数量；高级设置和自动编号 |
| 自有在库量由可卖、已订和待处理组成 | 首页只显示数量和状态，统计口径放帮助提示 |
| 已取得所有权，实物进入待检 | 回收确认真实成功后显示“已收购，待检测” |
| 所有金额由服务端按整数分结算 | 从业务界面删除 |
| 还没有商品档案 | “还没有登记配件”＋“登记第一件配件” |

不能将含故障、整备等状态的整个“待处理”笼统改名为“待检测”。状态展示需有真实检测/处理依据。

## 6. 视觉与工程范围

采用实用型工作台布局，以分类导航、表格和固定操作区为主。沿用当前主题：白色 `#ffffff`、正文 `#111111`、次要文字 `#666666`、分隔线 `#e5e5e5`、选中浅米色 `#f8f0dc`；警示沿用语义色。

字体继续使用现有 Microsoft YaHei / PingFang SC 字体栈及现有回退字体，4px 圆角、14–16px 正文，触控目标至少 44px。此处按现有设计系统覆盖 ui-design 技能的一般字体与布局建议；不引入远程字体、图片或新的视觉框架。

这轮规划涉及真实业务依赖，不能作为纯改文案任务交付。优先核对二手到货、分批补录、检测状态和分类查询，再落地表单与列表。详见[实施任务](implementation.md)。
