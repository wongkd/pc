# Q01 · ERP 专属报价管理＋顾客我的报价单

日期：2026-09-19。状态：用户已确认方向；任务定义完成，原型未实现。
目标：让老板开一张单、发一个入口，顾客找到自己的配置与付款信息。
入口：本文件；无运行命令，原型建立后在对应 design 目录补充。
本卡不接真实支付、不写业务库、不发布。

## 1. 管理归属

| 对象 | ERP 入口 | 职责 |
|---|---|---|
| 顾客专属报价 | 开单 → 报价详情 | 配置、版本、顾客归属、分享入口、关联订单 |
| 公开商品/套餐 | 商品管理 → 对外展示 | 可见性、介绍、对外售价；本卡不做完整商城 |
| 门店及外部店铺入口 | 设置 → 门店资料 | 地址、营业时间、联系方式、外部链接；本卡只明确归属 |

不要求老板手工录网址或在小程序后台重复上架专属报价。
实际分享形式（卡片/二维码/链接）由后续微信能力核实决定，不承诺任意跳转。

## 2. 老板操作

1. 选择已有客户或快捷填写称呼；输入用途和心理预算。
2. 套用配置模板，调整新品、二手、客供件及服务费用。
3. 每项显示数量/单价/小计，总价与优惠分开；缺件提示不等于采购已发生。
4. 预览顾客版；填写报价有效期、交付预期与方式。
5. 生成演示分享入口；展示复制信息、二维码位置、查看顾客版的操作。
6. 修改生成新版本，旧版本提示已更新；撤回后不可继续支付。
7. 将关联订单、收款与交付作为后续真实数据卡的入口，不伪造成功。

## 3. 顾客操作

从分享入口进对应报价 → 必要时登录再返回原报价 → 看每件配件价格、
总价、质保和交付信息 → 选择定金或全款。

“我的报价单”放在原 shop 入口作为主内容；公开商品入口降级。
tabBar 是否直接改名及图标语义在原型中评审，不把旧商城假定为最终形态。
顾客可以联系门店换配置；本卡不开放顾客直接修改已发报价价格。

## 4. 页面与状态

| 页面 | 必须呈现 |
|---|---|
| ERP 报价列表/详情 | 客户、报价编号、版本、总价、有效期、下一操作 |
| ERP 顾客预览/分享 | 只显示对外信息；演示入口明确标识 |
| 顾客报价列表 | 未登录、没有报价、多张报价、继续查看 |
| 顾客报价详情 | 单价明细、当前应付、支付方式、联系方式 |
| 异常页/反馈 | 加载、失败、过期、撤回、版本变化、无权访问、支付未接通 |

原型使用明确的演示状态选择器，可看各状态；点击付款必须说明尚未接通，
不得把演示按钮变成“真实付款成功”。匿名或其他顾客不可看到报价详情。

## 5. 下一阶段的数据边界

后续契约卡需要明确：顾客身份、报价归属、不可变报价版本、有效期、
分享凭证及撤销、应付金额、支付记录、订单关联与权限过滤。
既有员工绑定逻辑不能直接拿来充当顾客授权。

- 已发报价保留金额快照；付款前核验最新可支付版本与服务端金额。
- 请求幂等，支付通知可重复；前端返回成功不能作为到账依据。
- 未付款不占用库存、不启动采购。付款与库存竞争/缺货处理另设验收用例。
- 服务端不向顾客返回成本、供应商、SN、内部备注或他人资料。

## 6. 可用性目标与验收

- 模板报价争取 2 分钟内完成；找客户/单据争取 10 秒内完成，均为待实测目标。
- 数据只录一次；同一订单处理区集中呈现配置、缺件、收款和交付。
- 失败保留输入；主操作随真实阶段变化，不能靠任意改状态跳过业务动作。
- 桌面检查 1366×768、1440；手机原型检查 375/390，并检查 320/430 溢出。
- 检查键盘、主要触控入口、空态、返回与修改报价后的顾客状态。
- 网页手机原型不算原生小程序或真机验收。

证据放 docs/verification/<日期>-Q01/，运行命令、截图与未验证范围必须登记。
完成后将 STATUS 标为“原型完成”，不能标为“支付/营业功能完成”。
