# 顾客端小程序重规划：装一下机手绘 IP 版

日期：2026-09-22。状态：规划完成，待视觉确认与分卡实施。

本规划覆盖顾客端小程序从当前演示壳到可接入 ERP 的全部剩余工作。网页 ERP 仍是店员工作台；小程序只服务顾客，不复制库存、采购、成本和内部审批。

## 一、视觉基准

基准图：本轮生成的「装一下机」首页 IP 稿（银渐层 + 金渐层）。品牌副句固定为 **「不挣钱，交个朋友」**，只出现一次，位于品牌标题下方；右侧辅助文案保留「热爱，让电脑有可能 :)」。

- 黑色简约线稿、近白纸张底、单一暖黄色强调色。
- 原创粗手写中文标题：字形有力度、短句优先、留白充足；不复制任何现有品牌字标。
- 银渐层是主 IP，金渐层是陪伴 IP；两只猫的脸型、花纹、项圈/配饰必须稳定。
- 页面以任务入口为主，不做满屏海报；图片、案例和文案都服务于「装机 / 回收 / 维修 / 联系」。
- 禁止出现成本、供应商、内部备注、SN、员工视角、伪造支付成功和未接通动作。

## 二、顾客端信息架构

底部四项固定为：**首页 / 商城 / 社区 / 我的**。

| 区域 | 首版内容 | 真实动作 |
|---|---|---|
| 首页 | 四个入口、案例、门店信息、客服入口 | 跳转对应流程或联系门店 |
| 商城 | 我的报价单优先；公开整机/配件作为辅助浏览 | 查看、筛选、进入详情；不把浏览当下单 |
| 社区 | 商家发布的装机案例、知识和公告 | 只读；通过客服咨询 |
| 我的 | 报价、订单、预约、回收、售后、账号与授权 | 查看个人记录和待处理事项 |

## 三、页面清单

### P0 首页与公共页面

- 首页：四入口、案例横幅、营业状态、地址/电话、客服按钮。
- 门店详情：地址、营业时间、地图/导航、客服消息、异常与空态。
- 登录/身份确认：微信登录态、手机号能力按正式主体复核；拒绝授权时保留返回原页面。
- 公共加载、失败、无网络、无数据、无权、过期和重试组件。

### P1 报价与销售

- 我的报价列表：未登录、无报价、单报价、多报价、已更新、已撤回、已过期。
- 顾客报价详情：配置明细、数量、售价、小计、服务费、优惠、总价、交付方式、有效期、门店联系方式。
- 报价确认：确认当前版本并记录来源；顾客不能直接改价。
- 支付前确认：定金/全款由服务端计算应付金额；未接通支付时明确显示“演示/待接入”，不得伪造成功。
- 订单详情：状态时间线、配置摘要、收款状态、预计交付、客服入口。

### P2 三项服务引导

- 我要装机：预算、用途、偏好、交付方式、联系方式，提交为“咨询/预约意向”，不伪造报价或采购成功。
- 回收置换：设备照片/描述、品牌型号、故障和期望，提交检测预约；估价由店员验机后产生。
- 预约维修：设备、故障描述、照片、可预约时间和取送方式；未诊断前不显示固定价格。

### P3 商城、社区、我的

- 商品/整机详情：只返回顾客可见售价、规格、可售状态和门店说明；隐藏成本、供应商和 SN。
- 社区列表/详情：商家案例、装机知识、公告；无顾客发帖、评论和陌生人聊天。
- 我的：报价、订单、服务预约、回收、售后、收藏/浏览记录、客服、设置。

## 四、业务状态与接口边界

1. 顾客身份、报价归属、分享凭证和撤销/过期校验先于详情读取；匿名用户不能猜测或枚举他人报价。
2. 顾客端只消费服务端过滤后的顾客 DTO；前端不负责删除敏感字段。
3. 报价金额采用不可变版本快照；每次确认/支付前服务端重新核验版本、有效期、应付金额和幂等键。
4. 未付款不锁库存、不触发采购；库存竞争和缺货由 ERP/后端规则处理。
5. 预约、回收、维修是意向/待处理状态，必须展示“等待门店确认”；不能写成已接单、已估价或已完成。
6. 微信支付、订阅消息、手机号授权、地图导航和客服能力在接入时按当前平台文档复核；规划不把历史平台陈述当永久事实。

## 五、实施分卡（串行边界）

| 卡 | 交付 | 依赖 | 放行条件 |
|---|---|---|---|
| M00 | 视觉令牌、猫 IP 资产规格、页面状态表 | 视觉基准 | 375/390 截图评审通过 |
| M01 | 公共壳、tabBar、导航、加载/错误/空态 | M00 | 页面检查、类型检查通过 |
| M02 | 顾客身份与报价归属契约、分享凭证校验 | 后端身份基础 | 跨客户读取/撤回/过期测试通过 |
| M03 | 我的报价列表与详情 | M02 | 8 种报价状态截图与接口验收通过 |
| M04 | 报价确认、定金/全款意向、支付占位 | M03 | 金额快照、幂等、未接通提示通过 |
| M05 | 订单与进度时间线 | M04 + ERP 销售闭环 | 顾客 DTO 不含内部字段 |
| M06 | 我要装机 / 回收置换 / 预约维修表单 | M01 | 输入保留、失败重试、待店员确认状态通过 |
| M07 | 商城公开商品与整机详情 | M01 + 商品读模型 | 敏感字段服务端过滤、库存只读 |
| M08 | 社区案例/公告只读流 | M01 | 无发帖/评论入口，图片失败有兜底 |
| M09 | 我的聚合页、客服、门店详情 | M03–M08 | 所有入口可回到原状态 |
| M10 | 真实接口联调与隔离环境验收 | M02–M09 | 本地、测试、生产配置明确分离 |

契约、`backend/src/index.ts` 接线、迁移和生成物属于共享单点区；由单一会话串行修改，按“契约 → 生成 → 两端同步 → 门禁”收尾。

## 六、验收矩阵

- 视觉：375、390、430 宽度；长文案、空态、键盘、触控、深色系统状态栏不破版。
- 业务：匿名/已授权/错误身份；有效、过期、撤回、已更新、无权报价；部分付款和重复提交。
- 隐私：接口响应中不存在成本、供应商、SN、内部备注和他人资料。
- 失败：断网、超时、4xx、5xx、图片失败、重复点击、返回后恢复输入。
- 端到端：ERP 发报价 → 顾客查看/确认 → ERP 看到状态 → 收款/订单进度 → 顾客查看更新。
- 证据分层：浏览器/CLI 只代表本地检查；微信开发者工具、iOS/Android 真机、生产支付和审核分别记录。

## 七、当前明确不做

顾客社区发帖与评论、顾客间聊天、顾客自行改报价、自动估价、未核实支付成功、完整离线交易、多门店运营、店员小程序。

下一步从 **M00 视觉令牌与 IP 资产规格** 开始；视觉基准确认后再进入 M01，不先改动契约和生产代码。
