# 电脑店轻量 ERP 完整产品方案

> 文档用途：作为 PC 报价系统升级为电脑店轻量 ERP 的总产品基线，并作为后续 AI 模型逐阶段开发的唯一上层依据。
>
> 当前阶段：产品方案，不修改前端、后端或数据库业务代码。
>
> 编制日期：2026-07-20

---

## 0. 文档使用规则

### 0.1 后续模型必须遵守

1. 每次只执行本文一个阶段或一张任务卡，不得跨阶段开发。
2. 开始前先读取本文、`电脑配置单网页TODO.md`、相关代码和最近变更记录。
3. 改动超过 2 个文件时，先向用户说明文件范围和影响。
4. 数据库变更必须新增迁移文件，不允许直接覆盖或破坏现有 `schema.sql` 和线上数据。
5. 所有新增业务表必须包含门店隔离字段、创建时间、更新时间；关键单据还需操作人和审计记录。
6. 不允许删除现有报价、在线查价、AI 标准化、模板、打印、PNG、PDF、HTML 导出能力。
7. 每阶段必须完成类型检查、构建、相关单元测试和业务验收后才能进入下一阶段。
8. 未通过验收时只修复本阶段问题，不得开始下一个阶段。
9. 部署前必须备份当前代码、D1 数据库和线上版本信息。
10. 所有金额以“分”为数据库存储单位，前端展示为人民币元，禁止使用浮点数直接累计财务金额。

### 0.2 项目定位

本项目不是制造业 ERP，而是面向单店或小团队电脑店的轻量经营系统：

> 报价获客 + 销售订单 + 采购入库 + 库存与 SN + 装机交付 + 售后维修 + 收支毛利

### 0.3 已确认经营规则

| 编号 | 经营规则 | 产品结论 |
|---|---|---|
| R1 | 经常先接单再采购 | 订单允许库存不足，缺口自动进入采购需求 |
| R2 | 商品需要记录 SN | 商品可配置 SN 管理；高价值商品默认启用 |
| R3 | 允许负库存 | 允许，但必须关联订单、记录原因、预警并可追溯 |
| R4 | 客户预订后锁货 | 订单确认后锁定现货，取消或交付时释放 |
| R5 | 存在客户自带配件装机 | 客供件单独管理，不计自有库存和采购成本 |
| R6 | 不区分散片、盒装、国行等渠道 | 不作为 SKU 拆分条件；允许在备注中记录 |
| R7 | 商品种类和库存规模后补 | 架构先支持，后续补充数据量用于索引和性能验收 |

待用户补充：商品 SKU 数量、在库件数、每日订单量、使用员工人数、是否多仓库或多门店。

## 1. 产品目标与成功标准

### 1.1 目标

1. 报价确认后可以直接转订单，无需重复录入客户和配置。
2. 一眼知道哪些货有库存、被谁锁定、哪些在途、哪些缺货。
3. 每件高价值硬件可通过 SN 追踪采购、装机、销售和售后全过程。
4. 每张订单可以得到实际收入、实际成本、欠款和毛利。
5. 客户自带配件可以进入装机清单，但不会污染店内库存和毛利。
6. 所有库存变化都有单据和流水，不能无痕修改库存。

### 1.2 核心指标

- 报价转订单重复录入字段：0 个。
- 库存流水可追溯率：100%。
- 启用 SN 的商品，交付前 SN 完整率：100%。
- 订单缺货识别准确率：100%。
- 历史订单金额和成本不受商品后续改价影响。
- 任一负库存都能定位关联订单、操作者和原因。

### 1.3 非目标

一期不做：制造 BOM、生产排程、车间工序、完整财务总账、税务申报、工资人事、多公司、多币种、复杂审批流、商城、会员营销。

## 2. 用户角色与权限

### 2.1 角色

| 角色 | 主要权限 |
|---|---|
| 店主/管理员 | 全部数据；成员权限；查看成本和毛利；批准库存调整、负库存和反审核 |
| 销售 | 客户、报价、订单、预订锁货、收款登记；默认不看采购成本 |
| 采购/仓管 | 供应商、采购、入库、出库、SN、盘点；不可修改成交价 |
| 装机/售后 | 查看分配任务、领料、客供件登记、SN 绑定、检测、交付和售后记录 |

小团队允许一名员工拥有多个角色。

### 2.2 敏感操作

以下操作必须记录原因、操作人、操作时间、修改前值和修改后值：

- 低于最低售价成交。
- 允许负库存出库。
- 手工库存调整。
- 删除或作废单据。
- 订单取消与解除锁货。
- 更换已绑定 SN。
- 收款撤销、退款和欠款核销。
- 已确认单据反审核。

## 4. 核心业务闭环

### 4.1 主流程

客户建档 → 创建报价 → 保存报价版本 → 客户确认 → 转销售订单 → 登记定金 → 锁定现货 → 形成缺货需求 → 采购下单 → 到货验收与 SN 入库 → 装机领料 → 客供件登记 → 装机检测 → 尾款/欠款 → 交付出库 → 售后追踪。

### 4.2 三条独立状态轴

订单不能只用一个状态字段，应分为：

**交易状态**：草稿、待确认、已确认、已取消、已关闭。

**履约状态**：待锁货、待采购、待到货、待装机、装机中、待交付、已交付。

**收款状态**：未收款、部分收款、已收款、部分退款、已退款、欠款。

三个状态相互关联但不能混用。例如订单可以是“已确认 + 待到货 + 部分收款”。

## 5. 商品档案设计

### 5.1 商品与 SKU 定义

- 商品档案表示可采购和销售的具体 SKU。
- 容量、颜色、套装数量、明确型号不同，应建立不同 SKU。
- 散片、盒装、国行等渠道属性按已确认规则不拆 SKU，可写入采购备注。
- 商品停用后不可新增业务，但历史单据必须正常显示。

### 5.2 商品字段

| 字段 | 类型/示例 | 规则 |
|---|---|---|
| id | 内部 ID | 系统生成 |
| store_id | 门店 ID | 必填，数据隔离 |
| sku_code | `GPU-MSI-5070-12G` | 门店内唯一，不自动重复使用 |
| name | 微星 RTX 5070 12G | 必填 |
| short_name | RTX 5070 | 列表和打印可选 |
| category_id | 显卡 | 必填 |
| brand | 微星 | 可选 |
| model | 具体厂家型号 | 建议填写 |
| specifications | JSON/文本 | 容量、频率、接口等关键规格 |
| unit | 个、条、套、台 | 必填 |
| barcode | 条码 | 可选，后续扫码使用 |
| sn_required | true/false | 是否逐件管理 SN |
| warranty_months | 36 | 默认质保月数 |
| reference_price_cents | 电商参考价 | 来自现有在线查价 |
| default_sale_price_cents | 默认销售价 | 报价默认带入 |
| min_sale_price_cents | 最低售价 | 低于时提示或审批 |
| latest_purchase_price_cents | 最近采购价 | 入库后更新 |
| average_cost_cents | 移动平均成本 | 系统计算，不手改 |
| safety_stock | 安全库存 | 可为 0 |
| image_url | 商品图片 | 可选 |
| search_keyword | 在线查价关键词 | 可选 |
| status | active/inactive | 在售/停用 |
| remark | 备注 | 不参与库存计算 |
| created_at/updated_at | 时间 | 必填 |

### 5.3 现有硬件库迁移

现有字段映射：

- `category` → 商品分类。
- `description` → 商品名称。
- `price` → 初始默认销售价或电商参考价，由迁移界面让用户选择，禁止直接同时作为成本。
- `image` → 商品图片。
- `sourcePlatform`、`lastRefreshed` → 查价来源和更新时间。

迁移过程不删除旧 `hardware` 数据。先复制到新商品表，核对后再切换读取来源。

## 6. 库存模型与计算规则

### 6.1 库存四个核心数量

| 数量 | 定义 |
|---|---|
| on_hand 实际库存 | 已验收入库且尚未出库的店内自有商品 |
| reserved 锁定库存 | 已被确认订单预订、尚未出库的数量 |
| available 可用库存 | `on_hand - reserved` |
| inbound 在途库存 | 已下采购单但尚未完成入库的数量 |

补充指标：

- 订单缺口 `shortage = max(order_required - allocated, 0)`。
- 预计可用 `projected_available = on_hand + inbound - reserved`。
- 负库存缺口 `negative_gap = max(-on_hand, 0)`。

### 6.2 允许负库存的规则

1. 允许订单确认时库存不足，也允许授权后负库存出库。
2. 负库存必须关联销售订单或售后换件单，禁止无来源负数。
3. 出现负库存时必须填写原因，记录操作人并生成高优先级异常。
4. 负库存不等于采购在途，两个数字必须分开显示。
5. 后续采购入库优先回补已关联订单和负库存缺口。
6. 报表中负库存商品的库存金额不得显示为正常正资产。
7. 不允许通过直接改商品数量消除负库存，只能通过入库、退货或库存调整单。

### 6.3 锁货规则

1. 报价不锁货。
2. 报价转订单并确认后锁货。
3. 有现货时按订单数量锁定；不足部分形成缺货需求。
4. 订单取消时释放尚未出库的锁定数量。
5. 实际出库时同时减少 `on_hand` 和 `reserved`。
6. 锁货可设置有效期，但到期只提醒，不自动释放，避免误卖。
7. 同一商品被多订单争抢时按订单确认时间先后分配，管理员可手动调整并留痕。

### 6.4 库存账本

库存余额可以缓存，但库存流水是事实来源。每次变化必须产生不可删除的流水：

| 字段 | 说明 |
|---|---|
| movement_no | 流水号，唯一 |
| product_id | 商品 |
| sn_id | SN 商品可填 |
| movement_type | 采购入库、销售出库、退货、盘点、报损、调整等 |
| quantity_delta | 数量变化，入库为正，出库为负 |
| before_quantity | 变化前 |
| after_quantity | 变化后 |
| unit_cost_cents | 本次成本 |
| source_type/source_id | 关联单据类型和 ID |
| operator_id | 操作人 |
| reason | 调整和负库存必填 |
| occurred_at | 业务发生时间 |
| created_at | 系统记录时间 |

### 6.5 成本规则

一期采用移动加权平均成本：

`新平均成本 = (原库存金额 + 本次入库金额 + 分摊费用) / 入库后正库存数量`

约束：

- 金额用整数分计算，最终四舍五入到分。
- SN 商品同时保存单件实际采购成本。
- 订单毛利优先使用实际出库 SN 成本；非 SN 商品使用出库时平均成本快照。
- 历史订单成本必须固化，后续采购价变化不得回写。
- 负库存出库时先记录预计成本；后续回补时计算成本差异并标记已调整。

## 7. SN 生命周期

### 7.1 默认启用建议

默认启用：CPU、主板、显卡、显示器、笔记本、品牌整机、高价值固态硬盘。

默认关闭：线材、风扇、硅脂、螺丝、低价值键鼠配件。

管理员可以在商品档案调整。

### 7.2 SN 状态

待入库 → 在库可用 → 已锁定 → 已领料 → 已销售/已交付 → 售后中 → 已退回供应商/已报废。

### 7.3 规则

1. 同一门店内 SN 必须唯一。
2. SN 商品采购入库数量必须等于录入的有效 SN 数量。
3. 销售出库和装机领料必须选择具体 SN。
4. 最迟交付前必须补齐 SN；未补齐不得确认交付。
5. 已交付 SN 不允许直接换绑，只能通过退货、换件或冲销流程。
6. SN 可反查采购单、供应商、成本、订单、客户、交付时间和售后记录。
7. 输入时自动去空格、统一英文大小写；原始值可保留用于审计。

## 8. 客户自带配件规则

### 8.1 数据属性

客户自带件不是商品库存，也不是采购资产。它属于某客户和某个装机/售后任务。

字段包括：

- 客户、关联订单/装机任务。
- 配件类别、品牌、型号、SN。
- 数量、外观照片、已有损伤。
- 客户声明的问题或状态。
- 接收时间、接收人。
- 检测结果、是否兼容。
- 责任声明、客户确认。
- 退还/交付时间和接收确认。

### 8.2 规则

1. 不增加 `on_hand`、不进入可售库存、不计算采购成本。
2. 可出现在装机配置单中，并明确标记“客户自带”。
3. 客供件的安装服务费可以计入订单收入。
4. 客供件故障不能默认计入门店商品质保。
5. 未退还的客供件必须出现在每日待办和交付校验中。

## 9. 采购流程

### 9.1 流程

订单缺口/库存预警 → 采购需求 → 合并或拆分采购单 → 提交供应商 → 部分/全部到货 → 验收 → 录入 SN → 入库 → 分配订单 → 完成采购。

### 9.2 采购状态

草稿、已下单、部分到货、全部到货、已完成、已取消。

付款状态另行维护：未付款、部分付款、已付款、已退款。

### 9.3 采购单字段

单号、供应商、采购日期、预计到货日、商品、数量、采购单价、税费、运费、其他费用、已到货数量、未到货数量、关联订单、备注、状态、创建人、审核人。

### 9.4 部分到货

采购 10 件、到货 6 件时：

- 只对 6 件生成入库和 SN。
- `inbound` 从 10 减为 4。
- 采购单状态为“部分到货”。
- 已到货商品优先分配关联订单。
- 剩余 4 件继续显示在途，不允许提前计入实际库存。

### 9.5 验收要求

- 数量、外观、型号、SN 和采购价格可核对。
- 不合格商品不入可用库存，应进入拒收或待处理状态。
- 完成入库后更新最近采购价和平均成本。

## 10. 销售、领料与出库流程

### 10.1 报价转订单

1. 复制客户和报价明细快照。
2. 固化成交价、数量、条款和报价版本。
3. 生成订单单号。
4. 不回写原报价；后续修改生成订单变更记录。
5. 确认订单后执行锁货和缺口计算。

### 10.2 装机领料

- 领料将商品从“已锁定”推进为“已领料”，但是否立即扣实际库存由统一规则决定。
- 一期推荐：领料即生成内部出库占用，交付前可退料；交付时确认最终销售成本。
- SN 商品必须选择具体 SN。
- 退料恢复库存和锁定关系，并记录流水。

### 10.3 销售出库

1. 校验订单未取消。
2. 校验商品数量和 SN。
3. 校验客供件是否已处理。
4. 正常商品减少 `on_hand`，同时减少 `reserved`。
5. 若不足且有负库存权限，要求填写原因后出库。
6. 保存实际成本快照和毛利。
7. 生成销售出库单和库存流水。
8. 重复提交必须幂等，不能重复扣库存。

### 10.4 退货、换件、报损

- 销售退货：验收后决定返可售、待检测或报损。
- 采购退货：减少库存并关联供应商和原采购批次。
- 售后换件：旧 SN 进入售后状态，新 SN 关联原订单和售后工单。
- 报损：必须选择原因和责任人，不可直接删除库存。

## 11. 库存盘点

流程：创建盘点单 → 冻结盘点范围快照 → 输入实盘数量/SN → 计算差异 → 填写原因 → 审核确认 → 生成盘盈盘亏流水。

规则：

1. 盘点草稿不改变库存。
2. 确认后不可删除，只能通过反向调整纠错。
3. SN 商品逐件核对，识别系统有实物无、实物有系统无和 SN 状态错误。
4. 盘点期间仍允许业务发生时，需要记录快照时间并提示重新核对差异。

## 14. 分阶段开发路线

### 阶段 0：备份与基线

**目标**：确保现有报价系统可恢复。

任务：代码打标签、导出 D1、记录线上前后端版本、运行现有测试和构建、建立迁移目录。

验收：备份文件可读取；当前构建和测试结果已记录；没有业务改动。

### 阶段 1：应用壳与导航

**目标**：建立 ERP 左侧导航和路由，但现有报价页行为不变。

页面：经营概览占位、报价工作台、商品占位等。

禁止：改报价数据、打印样式、查价逻辑。

验收：登录后可导航；原报价功能完整；刷新路由不白屏。

### 阶段 2：门店、成员与权限底座

**目标**：所有新业务数据具备门店隔离和角色权限。

验收：不同门店数据不可互见；无权限接口返回 403；敏感按钮不显示且后端仍校验。

### 阶段 3：商品主数据

**目标**：新建商品档案、分类、价格字段和停用状态。

验收：SKU 唯一；金额以分存储；停用商品不能新选但历史可见；商品 CRUD 有测试。

### 阶段 4：旧硬件库迁移

**目标**：复制旧硬件库到商品档案，保留在线查价。

验收：数量核对一致；旧数据不删除；价格用途由用户确认；查价结果只更新参考价，不自动改成本。

### 阶段 5：库存账本与初始化

**目标**：建立余额、流水、库存初始化和调整单。

验收：任何数量变化都有流水；余额等于流水汇总；重复请求不重复入账；负库存有原因和预警。

### 阶段 6：SN 管理

**目标**：SN 入库、状态流转、搜索和唯一性。

验收：重复 SN 被拒绝；数量与 SN 数一致；可从 SN 反查完整来源；已交付 SN 不可直接修改。

### 阶段 7：客户、供应商与采购

**目标**：完成采购需求、采购单、部分到货和入库。

验收：在途计算正确；部分到货只增加实到数量；平均成本正确；SN 商品必须录入 SN。

### 阶段 8：多报价与销售订单

**目标**：报价列表、版本、转订单、三状态轴和价格快照。

验收：可保存多份报价；报价转单不重复录入；商品后续改价不影响历史订单；取消订单释放锁货。

### 阶段 9：锁货、缺货与负库存

**目标**：订单确认后锁货，不足生成采购需求，授权支持负库存。

验收：可用库存公式正确；并发锁货不超卖；订单取消释放；负库存全部可追溯。

### 阶段 10：装机、客供件与交付

**目标**：领料、客供件、SN 绑定、测试和交付出库。

验收：客供件不改变库存；未处理客供件不能交付；SN 缺失不能交付；重复交付不重复扣库存。

### 阶段 11：收付款与毛利

**目标**：定金、尾款、欠款、退款和实际毛利。

验收：支付合计和订单应收一致；部分收款状态正确；退款有原收款关系；毛利使用成本快照。

### 阶段 12：售后、盘点与经营看板

**目标**：售后工单、换件、盘点和经营异常闭环。

验收：售后可按 SN 追溯；换件产生正确流水；盘点确认才改变库存；首页指标可追溯到底层单据。

## 15. 详细验收用例

### 15.1 先接单后采购

前置：商品 A 实际库存 0，在途 0。

操作：创建数量 2 的订单并确认。

预期：锁定 0、缺口 2、生成采购需求 2；订单履约状态为待采购；不静默伪造库存。

### 15.2 预订锁货

前置：商品 B 实际 5、已锁定 1。

操作：确认需要 3 件的新订单。

预期：实际 5、锁定 4、可用 1；取消订单后锁定恢复为 1、可用恢复为 4。

### 15.3 部分缺货

前置：商品 C 实际 2、可用 2；订单需要 5。

预期：锁定 2、缺口 3、采购建议 3；不能显示为全部有货。

### 15.4 采购部分到货

前置：采购商品 C 3 件。

操作：到货 2 件。

预期：实际增加 2、在途剩 1、采购单部分到货；2 件优先分配原订单。

### 15.5 SN 入库

操作：SN 商品采购入库数量 3，只录入 2 个 SN。

预期：拒绝完成入库并明确提示差 1 个；录入重复 SN 也拒绝。

### 15.6 负库存出库

前置：商品 D 实际 0，订单需要 1。

操作：管理员选择负库存出库并填写原因。

预期：实际 -1；生成出库流水和负库存异常；关联订单、操作者和原因可查；后续入库 1 后回补到 0。

### 15.7 客户自带件

操作：登记客户自带显卡及 SN，加入装机任务并交付。

预期：配置单标记客供；自有库存和采购成本不变；装机记录可查；交付时记录已返还客户。

### 15.8 重复提交

操作：由于网络重试，同一入库或出库请求提交两次。

预期：只生成一张单据和一组流水，库存只变化一次。

### 15.9 历史价格

操作：订单完成后修改商品默认售价和最新采购价。

预期：已完成订单成交价、成本和毛利不变化。

### 15.10 盘点差异

前置：系统库存 10，实盘 8。

操作：盘点草稿填 8，随后审核。

预期：草稿阶段库存不变；审核后生成 -2 盘亏流水；盘点单不可物理删除。

## 19. 关键产品决策摘要

1. 报价不占库存，订单确认才锁货。
2. 实际库存、锁定、可用和在途必须分开。
3. 允许负库存，但必须有订单、原因、权限、流水和预警。
4. 采购到货多少就入库多少，不提前入账。
5. 高价值商品按数量 + SN 管理，普通商品按数量管理。
6. 客户自带件只进入装机和责任追踪，不进入可售库存和成本。
7. 库存余额可以缓存，库存流水不可删除且是事实依据。
8. 报价转订单保存快照，历史金额和成本不可被后续改价影响。
9. 交易、履约、收款使用三条独立状态轴。
10. 先完成数据底座，再做漂亮仪表盘；报表必须能追溯到底层单据。
