## 四个版本怎么选

| 版本 | 新建流程 | 主要提效 | 适用情况 | 实施复杂度 |
|---|---|---|---|---|
| A 常用配件预置 | 新建即列 8 类 → 填型号和价格 → 核对 | 8 行不再逐条创建，相对现有单空行少点 7 次“加一行” | 每单配置各不相同 | 低 |
| B 场景模板 | 选独显 / 核显 / 升级 → 勾选外设和服务 → 填配件 | 减少重复整理清单，降低漏项概率 | 不同类型装机混合接单 | 低—中 |
| C 店内配置模板 | 选常用完整配置 → 换件 → 核价 → 关联可售商品 | 减少型号、规格、数量的重复输入 | 经常重复销售几套配置 | 中—高 |
| D 整单粘贴 | 粘贴四列 → 识别预览 → 修错 → 导入待核对行 | 减少从 Excel / 文字逐格复制 | 已有完整配置清单 | 中—高 |

复杂度为相对设计判断，不是工时承诺。效率只按减少的操作解释，尚无用户计时或使用数据。

用户已确认首期采用 **A + B**：默认进入“标准独显主机”，场景入口置于配置清单上方，无需强制先弹模板选择窗口；保留“空白报价”。
C/D 保留为后续候选，不纳入本期实施。

## 默认配件与交互规则

- 基础 8 类：CPU、散热器、主板、内存、显卡、固态硬盘、电源、机箱。
- 快捷追加：显示器、键鼠套装、机箱风扇、机械硬盘、装机服务；允许同类别多行。
- 型号与价格留空，数量默认 1。内存按实际售卖单位计算：双条套装数量 1 表示 1 套，不擅自填 2。
- 核显办公去掉独显行，但必须人工确认 CPU 图形输出；散热器允许删除或填写原装散热。
- 旧机升级从 CPU / 主板 / 内存 / 固态 / 服务开始，可增删。原机器配件需要写入报价时按客供件处理。
- 来源在具体行设置；二手与客供保持独立引用规则。服务费另列，客供件本身不计价。
- 类别标签与商品名分开：空类别槽不成为正式行；部分填写的行必须提示补全或明确排除，不能静默变成 0 元商品。
- 场景切换保留共同配件，隐藏项可恢复；正式接入需对移除的已填行显示差异并提供撤销。
- A/B/C/D 原型各自保留页内状态；刷新即重置。C/D 替换已有输入时有确认，不会静默覆盖。

## 正式接入的范围与约束

### 首期 A + B

前置：用户已选定 A+B，实施前复核新建、保存、发出流程及当前行校验。仅预置编辑器本地的类别槽位，不为了模板创建虚构商品。

建议范围：将预设与新建初始化拆成独立纯逻辑，编辑器增加预设条、追加配件入口、空行与待核价提示；现有来源和引用规则保留。
UI 类别只用于新建引导时可以不改协议；若要求草稿恢复后仍保留未填槽位、跨端类别分组或模板持久化，就需要单独设计契约，不能把类别塞入商品名来冒充。

验收：默认行 / 空白入口正确；可删加与重复类别；数量及金额正确；切换不丢用户输入；保存/发出不含空槽或未确认的 0 元；已存在报价不被自动套模板；原版本、打印、客供和二手规则不变。

风险与停线：如需修改契约、迁移、入口单点区，先核实文件时间戳并单独排期；不在首期顺带改库存或转单业务。价格缺失不能靠当前空值转零的序列化兜底。

### 后续 C

正式模板支持命名、收藏、保存当前配置为模板、停用和门店共享；按门店隔离，并确定谁可编辑。新品保存商品引用与名称快照，套用时核对有效性与当前可用量；停售或失效条目标明待替换。
模板只包含配置和约定的通用条款，不含上次客户、订单身份、付款、确认状态、二手实物或客供设备引用。
价格默认留空或通过单独可见动作重取；沿用参考价须逐单核价。模板更新不反向修改已经存在的报价版本。
需对新旧模板数据兼容、权限及持久化做专卡，不能把旧编辑器模板无校验直接套入新单。

### 后续 D

原型支持四列 TSV / 竖线文本、可选表头、空单价、非法数量与金额拦截、80 行上限；自由格式微信文本与图片识别未实现。
正式版需要重复商品处理、候选匹配、单位/套装核对、来源确认。解析不确定时保留原文和错误行；人工确认后只生成待核对报价行，不自动发出、成交或采购。
