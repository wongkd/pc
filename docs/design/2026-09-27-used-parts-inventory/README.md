## 四条流怎么点

底部演示条上有四个按钮，各自对应方案里必须走通的一条流。点完按提示操作即可：

| 按钮 | 走通的是 | 要看的点 |
|---|---|---|
| 流程① 登记第一颗 CPU | 没有型号档案时直接登记 | 类别带入、成本留空写法、保存后是**待检测**而不是可售 |
| 流程② 同型号第二件 | 同型号两件各自独立 | 成本/检测/SN 分开；保存前先出现「近期同型号登记」核对 |
| 流程③ 第二批补录 | 分批整理货架 | 入口在单件详情里的「同型号再登记一件」，不是新建同名档案 |
| 流程④ 二手显卡到货 | 来源「新买到货」 | 保存后**仍然是二手**；到货不等于已付款 |

另外两个按钮演示真实世界最常见的两种失败形态：**保存结果未知**（先查结果，不要换请求号重发）、
**只存了资料没入库**（资料不重复建，继续登记库存）。最后一个按钮是重置，一个是对照旧文案。

## 已经落进原型的口径

- 库存状态由**检测事实 + 占用**推导，不单独录入：待检测 / 已检测正常 / 有问题 → 待检测 / 可售 / 待处理；
  有预留则是已预留。故障件不会被笼统叫成「待检测」。
- 「新品 / 二手」与「待检测 / 已检测正常 / 有问题」是两组互不相干的信息。
- 成本留空 = 待确认，填 0 = 确实零成本；两者不混。
- 分类数量与状态数量按**同一范围**统计（搜索词 + 对方条件），不拿当前页数据当全店统计。
- 成本按权限返回：关掉成本显示后，列表那一列和行里的金额都不出现，而不是被前端藏起来。
- 客户暂存与在途走「更多」视图，不计入自有在库。
- 词表：配件类别 / 型号与规格 / 登记配件 / 状况说明；不出现契约编号、整数分、幂等键这类实现说明。

## 与现有实现的关系

正式仓库页是 [WorkbenchInventoryPage.tsx](../../../frontend/src/features/workbench/WorkbenchInventoryPage.tsx)，
它的现状是：列表按**商品**分组展开、首次登记主线是「分类 / 品牌 / 商品名称 / SKU / 参考售价 / 管理方式」、
`EMPTY_PRODUCT` 与 `newOpeningLine` 的默认值是**按数量 + 新品**、搜索只带型号/编号/SKU、成本列由响应决定。
原型改的正是这些：以类别为第一层、逐件默认二手、登记一页完成。

原型**没有**动：契约、迁移、`backend/src/index.ts` 接线、任何接口。
