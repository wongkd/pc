## 过程中真正修掉的问题

1. **流程② 走不到核对面板**（真缺陷，不是断言问题）：场景没有带入来源，点保存先被「请先选来源」拦住，
   表现为「保存没反应」。这正是不做交互断言只看截图会漏掉的那类断链。已修：场景按「同型号再登记」路径带入来源。
2. 遮罩穿透判断写错（点卡片内部会被当成点遮罩）。已修。
3. 两个演示标志位互踩，导致「结果未知」面板设完就被清掉。已修。
4. 窄屏演示条占掉小半屏。已修：窄屏改单行横向滚动。

## 没有验证的（别当成已通过）

- **没有**接正式 ERP，**没有**读写任何真实库存、成本、客户数据；原型的数字全部是 `data.js` 里的虚构示例。
- **没有**改契约、迁移、`backend/src/index.ts` 接线或任何接口 —— 后端读取能力、分批补录、检测状态流转都还没实现。
- **没有**验证并发、幂等、权限、追溯；原型的「保存」只是内存里加一条。
- **没有**在微信真机上跑；本原型是内部 ERP 的网页形态，不是小程序。
- 窄屏只实看 390px 一档；桌面只实看 1440px。中间宽度按断点（860 / 560）推断，未逐档截图。
- 键盘可达性只做了基础处理（按钮语义、`aria-pressed`、Esc 关闭），**没有**跑完整的键盘走查。
