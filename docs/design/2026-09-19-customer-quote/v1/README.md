# Q01 · 顾客打开专属报价链接（原型 v1）

日期：2026-09-19。状态：**本地原型可点开；不含真实数据、不接支付、未发布**。
任务定义：[Q01 卡片](../../../plans/2026-09-19-quote-flow/README.md)。
本目录只放原型与它的自动验收产物，不是生产代码，没有接线到 `frontend/` 或 `miniprogram/`。

## 这一段做了什么

门店发一个专属入口 → 顾客打开 → 看到每件配件的单价、数量、小计 → 看到应付总额、预算对照和两种付款方式。
外加环绕这条链路的门槛与异常状态，共 10 个，可在演示控制台逐条切换；顾客预算另有独立档位可切。

ERP 侧（开单、预览顾客版、生成与管理入口）不在本刀范围，另开子卡。

```powershell
# 评审控制台（左控制台 + 右手机框）

# → http://127.0.0.1:8819/index.html

# 顾客视角：直接打开链接（控制台隐藏，整屏就是顾客看到的那一页）
```

## 虚构样单

周先生 · 视频剪辑与游戏。配件 10 项（含一件本店二手件、一件顾客自带件）+ 服务 2 项。

| 项目 | 金额 |
|---|---|
| 配件合计 | ¥8,799.00 |
| 服务与调试 | ¥350.00 |
| 门店优惠 | −¥500.00 |
| **应付总额** | **¥8,649.00** |
| 定金 15% | ¥1,297.35 |
| 交付时尾款 | ¥7,351.65 |
| 顾客预算（演示档一） | ¥12,000.00 → 比预算低 ¥3,351.00（占 72.1%） |
| 顾客预算（演示档二） | ¥8,000.00 → 超出预算 ¥649.00（占 108.1%） |

金额全部按整数「分」存储，格式化走纯字符串运算（不用 `toLocaleString`）——
小程序 JSCore 对该方法支持不完整，原型先按同一口径写，避免两端漂移。

**预算不参与任何金额计算**：它只做对照，差额一律按「应付 − 预算」算，正数即超预算。
把预算并进应付或优惠，等于让顾客以为这是门店给的口径。

## 这一版刻意做成这样

- 明细每行都写「单价 × 数量」和小计；客供件单价写 `¥0.00`，不写成空白，避免误解成漏算。
- 二手件与客供件带来源标签，并各自标注「质保 3 个月」「不提供质保」。
- **未登录、无权访问、链接失效、加载中、加载失败、已撤回六个状态不出现任何金额、配件名与预算**，
  这条在验收里是硬断言，不是靠前端隐藏。
- 预算对照条紧跟在「应付总额」下面（同一个决策动作），措辞只陈述事实：
  够用写「比预算低 ¥X」，超了写「超出预算 ¥X」并转警示色。
  **不写「省下 ¥X，还可以再配一件」** —— 那等于当着顾客的面暗示还有余量可花，会把一次确认变成一轮加价。
- 超预算不劝退、不催付、不隐藏明细；顾客是减配还是照付，选择权在他。
- 点付款只弹「支付尚未接通」，不产生成功态、不写任何数据；「已下定金」是演示状态，页内明确标注不是真实到账。
- 版本已更新时禁止付款，必须先看最新版 —— 对应「付款前核验最新可支付版本」。
- 写「定金」，不写「订金」。
