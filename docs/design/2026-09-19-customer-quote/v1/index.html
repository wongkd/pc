Q01 流程原型 · v1

顾客打开专属报价链接

只演示一段：门店发出专属入口 → 顾客打开 → 看到每件配件的单价明细与付款选项。 不接真实支付、不写业务库、不发布。资料全部虚构。

专属分享链接

门店生成后发给顾客的入口。真实的分享形式（微信卡片 / 二维码 / 链接）待微信能力核实， 本原型不承诺任意跳转，也不在这里伪造二维码。

演示状态

切换后手机页面立即呈现该状态；状态也会写进链接的 state 参数，便于逐条走查。

顾客预算

预算 = 顾客咨询时说的心理预算，是配置单的输入参数，不是一个付款动作。 两档都要走查：够用时怎么显示，超了又怎么显示。

本原型的硬边界

  • 未登录、无权访问、链接失效、加载中、加载失败、已撤回六态，不出现任何金额、明细与预算。
  • 预算只做对照，不参与金额计算，也不暗示「还有余量可以加配置」。
  • 点付款只说明「尚未接通」，不产生付款成功，不写任何业务数据。
  • 顾客侧不出现成本、供应商、内部备注与 SN。
  • 报价不锁定库存；未付款不排产、不触发采购。
  • 报价单写「定金」，不写「订金」。

本刀没做的部分

  • ERP 侧的开单、预览顾客版、生成入口与管理（下一张子卡）。
  • 「我的报价单」列表、多张报价、历史报价。
  • 真实支付、微信登录、订单与售后。
专属报价单 示意标题栏

手机框只是网页原型，不等于微信真机验收；示意标题栏不是微信系统栏。
