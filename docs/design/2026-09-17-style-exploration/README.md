## 三个方向

| 方向 | 视觉语言 | 适用与取舍 |
| --- | --- | --- |
| A：苹果式轻质感 | 浅灰白、深色文字、蓝色主操作、精细硬件摄影、清楚的空间层级；导航少量半透明 | 优先推荐作为操作结构基础，适合网页与手机统一观感。玻璃只作为局部点缀，金额、库存和任务保持实底。 |
| B：OCE 灵感生活方式 | 奶油白、森林绿、鼠尾草色、自然光摄影、偏编辑式排版 | 亲和、有门店气质，适合常用配置、客户报价与展示页面。工作页控制场景图面积，避免挤压任务。 |
| C：MUJI 灵感朴素工具 | 暖白、墨灰、细分隔线、极少量深红强调、朴素材质产品图 | 耐看，适合库存、单据、账本等高频页面。依靠字重、间距、图像质量和状态对比建立层级。 |

建议：以 A 的信息和操作结构为主，采用偏暖的中性底色。可借鉴 C 的克制，不同时混用三套按钮、圆角和导航。B 的场景摄影更适合客户报价与配置模板。

## 多端分工

### 界面文案原则（本轮用户明确要求）

不放无用宣传词、口号或装饰性欢迎语。界面优先显示任务、数据、状态、操作及必要的解释。例如使用“今日待办”“缺货订单”“查看交付”，移除“今天，井井有条”“把生意，理清楚”“手边的事，随时处理”等表述。技术实现说明不放进日常工作页面。

| 终端 | 优先场景 | 界面策略 |
| --- | --- | --- |
| 桌面网页 | 配置报价、批量录入、库存表格、账目核对、打印 | 六项侧栏、键盘搜索、较高信息密度；优先验证 1366×768。 |
| 微信小程序 | 扫码查件、入库、设备拍照、查单、更新进度 | 四项底栏：今天、开单、库存、更多。售后、回收置换、账本通过更多及首页快捷动作进入。复杂表单分步呈现。 |
| App | 延续手机工作流；原生能力按实际需求取舍 | 复用品牌、术语、业务规则和数据服务，遵循平台导航、安全区和系统控件习惯。 |

三个终端共享业务模型、权限与数据来源；不把桌面网页直接等比例缩小成小程序。现有 React 网页并不表示小程序或 App 已可直接交付。后续技术方案应独立评估扫码、拍照、文件导出、打印、登录及网络条件。

手机版首版需确认的关键流程：扫码或手输查件、拍照保存、查看任务与更新进度、快速开单、收款登记。库存和金额相关动作以服务端确认结果为准。

## 应补齐的图像资源

1. **真实商品图**：CPU、显卡、主板、内存、SSD、机箱、电源、散热器等。统一画幅、背景、缩略图比例；具体型号用对应实物或有授权的厂商图片。
2. **配置模板图**：办公、游戏、设计、静音等整机图。可以用生成图表达氛围，但必须避免误导用户认为图中就是实售配置。
3. **二手与售后照片**：拍摄具体设备的正反面、SN、外观瑕疵、检测与附件，绑定实物编号。不能用生成图代替成色或故障证据。
4. **少量品牌插画**：登录、引导、空列表、无搜索结果、完成状态；统一材质、光线与色彩。
5. **图标系统**：统一线宽与尺寸的矢量功能图标，状态同时有中文文字，不用 emoji 充当正式导航图标。

图像主要用于识别设备、解释状态和建立门店气质；经营页仍应让用户先看到任务和下一步操作。后续资产应集中管理，并记录用途、来源、授权、尺寸、替代文本和版本；本目录的概念图不直接当作生产素材。

## 选定风格后的原型验收

先做今天、报价开单、库存选件、手机扫码任务四个关键页面，再形成正式设计规范。统一检查中文字号、金额对齐、状态文本、键盘与触控、空数据、加载、失败重试以及长内容；微信胶囊和系统安全区在真实运行环境中验证。
