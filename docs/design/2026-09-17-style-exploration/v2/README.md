# 第二轮：三种独立界面结构

日期：2026-09-17。状态：可操作的视觉提案，待选择，不是最终产品 UI。

> 后续方向：[A+B 融合版](../v3/README.md) 保留 B 的视觉并加入 A 的订单处理；针对 B 手机操作不顺手的反馈重新设计手机入口。本目录保留原始提案作为对照。

第一轮共用同一布局，主要改变颜色、圆角与分隔线，未满足用户要求。本轮分别编写三份独立 HTML / CSS，只共享设备示意图、矢量图标和基础样式。

## 区别

| 维度 | A：苹果 | B：OCE | C：MUJI |
| --- | --- | --- | --- |
| 导航 | 窄侧栏、分组控件 | 顶部横向导航 | 编号目录 |
| 主体 | 任务列表与订单详情并列 | 大设备图、小设备图与时间待办构成不对称布局 | 经营表格与右侧核对单 |
| 图片 | 识别任务、查看选中设备 | 页面主要内容，按设备找订单 | 设备资料附件，主表保留较高信息密度 |
| 排版 | 中文无衬线、圆角、分组层级 | 中文衬线标题、宽留白、平面色块、产品标签 | 对齐、细线、较小圆角、等列单据 |
| 操作 | 选择任务 → 查看右侧详情 → 勾选交付检查 | 筛选阶段 → 选中设备 → 展开设备资料 | 按事项筛选 → 勾选记录 → 打开单据 |
| 手机 | 分组任务列表、全屏详情 | 横向设备卡片、设备详情页 | 双行台账、勾选、单据对话框 |

共同使用陈先生装机、林女士缺件、周先生维修等虚构示例。库存、金额、照片不代表真实门店或当前生产数据。

## 已实现的原型操作

- A：任务选择、名称/单号搜索、交付/缺货/维修筛选、检查项数量更新、手机详情返回。
- B：设备阶段筛选、设备详情展开与关闭。
- C：事项筛选、逐条/可见行全选、选择计数、单据对话框。
- 三版未实现的业务动作会说明是操作预览，不伪造入库、收款、交机成功。

## 文案与设计边界

- 不放欢迎语、宣传口号、装饰性文案；只保留对象、状态、金额和必要的操作解释。
- 这是根据 Apple、OCE、MUJI 气质做的设计提案，不是三个品牌的官方界面。
- 当前只完成首页代表页面及局部交互。最终 UI 还需覆盖开单、选件、售后、回收置换、账本及异常状态。
- 小程序与 App 在本轮体现为手机交互布局；没有创建或编译实际小程序 / App。
- 不修改现有业务源码，不部署、不提交 Git。此前确认当前目录没有 Git 仓库；本轮仅增加独立设计资料。
