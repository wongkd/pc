## 4. 数据架构：为什么不存在"同步"

```
「装一下机」小程序  ─┐
                    ├─→ 同一个后端服务 ─→ 同一个数据库
网页端 ERP        ─┘   （统一鉴权）      （唯一数据源）
```

- 顾客在小程序下单 = **直接写进那个库**，店员打开网页端就看到这条订单。没有"回流"。
- 店员改了库存，顾客打开小程序看到的就是新数字。没有"同步"。
- 只有一份数据，就不存在两边对不上。

**现状提醒**：现在两端跑的都是**演示数据**（写在代码里的假数据），尚未接真实后端，
所以在小程序里操作、网页端没反应是**正常的**——不是架构问题，是最后一段线没接。

## 6. 两条必须守住的边界

**① 成本、供应商、SN 串号绝不能出现在顾客端。**
库存"有没有货"可以给顾客看，进价和供应商不行。必须**服务端按角色过滤字段**，
不能靠前端隐藏（前端隐藏等于把账本摊在柜台上，抓包即可见）。

**② 顾客下单是否立即锁库存，必须走已有的约束方案。**
禁止自己写"先查数量够不够 → 够就减 1"。在 D1 上条件 UPDATE 影响 0 行**不报错**，
会静默产生半截账。已有方案：部分唯一索引 + `assertion_guards` 守卫 + `RAISE(ABORT)`。

  ⇒ 与重新注册（0 元 + 30 元/年）相比不划算，**直接放弃**。

## 8. 业务流程（2026-09-19 02:06 栋哥口述，已梳理）

> 本节是**业务事实**，由栋哥口述记录，不是推断。据此与现有模块对照，输出「已有 / 还缺 / 不需要」。

### 8.1 三条业务线

栋哥原话要点：沟通完成 → 他上**专属链接** → 顾客下单 → 自取或送货；
回收置换 = 上门或到店验机估价 → 给**代金券**（店内消费）或**直接提现**；
报价渠道不限（电话 / 在线 / 到店），发配置单或约到店都行；顾客可先打预算款再装机。

| 线 | 步骤 | 谁做 | 记什么 |
|---|---|---|---|
| **A 销售**（新机 / 二手装机 / 配件） | 沟通需求 → 出配置单 → 上架专属链接 → 顾客付款（可先打预算款）→ 装机（可能进货）→ 交付（自取 / 送货）→ 售后 | 沟通与上架：栋哥；下单付款：顾客 | 配置单、顾客、金额、定金与尾款、交付方式、SN |
| **B 回收置换** | 顾客提交闲置 → 上门或到店验机 → 估价 → 顾客选**代金券 / 提现** → 结算 | 验机估价：栋哥 | 机器、成色、估价、结算方式与去向（转卖 / 拆件） |
| **C 服务**（维修 / 装机服务） | 报修（电话 / 在线）→ 预约（上门 / 到店）→ 检测报价 → 维修 → 交付收款 | 检测报价：栋哥 | 故障、检测结果、报价、工时、更换件 |

### 8.2 与现有模块对照

现有模块：报价 / 订单 / 采购 / 库存 SN / 装机交付 / 售后 / 收支毛利。

| 能力 | 判定 | 说明 |
|---|---|---|
| 配置单与报价 | ✅ 已有 | 系统老本行 |
| 订单 | ✅ 已有 | 需补「定金 / 尾款」两段收款 |
| 采购 / 进货 | ✅ 已有 | |
| 库存与 SN | ✅ 已有 | ⚠️ 客供件不得进自家库存；新品与二手须两套口径 |
| 装机交付 | ✅ 已有 | 需补**交付方式**（自取 / 送货）与配送地址 |
| 售后 | ✅ 已有 | 保修口径待栋哥定 |
| 收支毛利 | ✅ 已有 | 回收是**唯一反向**业务，付款方向相反 |
| 专属链接（顾客看到自己的报价并下单） | ❌ **还缺** | 见 §8.4，是顾客端最重要的一块 |
| 在线收款（微信支付） | ❌ **还缺** | 个体户可开，费率约 0.6% |
| 在线付款给顾客（提现） | ⚠️ **个体户做不了** | 见 §8.3 |
| 代金券 | ⚠️ 待定形态 | 若是「回收抵价额度」属营销券；若可充值 / 有余额则踩预付卡监管 |
| 预约时间选择 | ❌ 还缺 | 上门维修与到店都要约时间 |
| 顾客自助提交闲置 | ❌ 还缺 | 只能登记，估价必须当面 |

### 8.3 ⚠️ 硬伤：提现走不通，必须改线下

**事实**（多来源交叉，取保守口径）：微信支付「商家转账到零钱」（原企业付款到零钱，
即商家主动打钱给用户）**仅支持企业主体申请，个体工商户不支持**。

- 微信支付商户平台功能入口要求：主体须为企业营业执照，**不支持小微商户和个体工商户**
  （乐檬零售帮助中心整理的操作步骤，附微信开放社区参考链接）
- 第三方开通服务商经验帖同样写明：「公司才能申请，个体工商户目前不支持」
- 另需人工审核场景（要有已认证的公众号 / 小程序供审核人进入查看）
- 关于「入驻满 90 天 + 连续交易 30 天」：一说为 2022 年前的旧规、现已取消，
  一说仍存在 —— **口径冲突，按保守处理**，且这条对个体户无意义（主体就不符合）

**结论**：回收给顾客「直接提现」在小程序内做不了。

**替代方案（建议）**：线下微信转账或现金给顾客，小程序只记录「应付款 / 已结算」。
这样账照记、钱照给，不碰资金结算能力，也就不需要那个资质。
⇒ 顾客端在回收流程里只写「估价已完成，结算方式：店内抵用 / 线下转账」，
**不得**做成"余额"或"钱包提现"。

**代金券也要小心**：若做成可充值、有余额、可跨次使用的「钱包」，会被认定为储值 / 预付卡
（官方运营专员答复：涉及账户充值需补【商家自营 - 预付卡销售 - 发行方】类目，
需《单用途预付卡》备案或《支付业务许可证》）。
⇒ 只做**一次性抵用额度**（回收时生成、指定用途、用完即止），不碰"余额"概念。

### 8.4 「专属链接」的产品含义（重要）

栋哥的流程里，顾客下单的入口是**他给这个顾客单独上的链接**，不是公开商品列表。
⇒ 顾客端的重心应从「公开商城」移到「**我的报价单**」：顾客登录后看到属于自己的配置单
与价格，直接付款。公开商城（配件陈列）是次要的。

这一条还没做成，属于下一步的页面设计依据。

#### ⚠️ 术语澄清（重要，别按字面理解）

**「预算款」不是付款动作，是「顾客的心理预算金额」。**
栋哥原话：*"预算款是客户想装多少钱的机子的意思，我根据它的预算出配置单。"*
⇒ 上一版把「先打预算款」理解成「先付定金」是**错的**，实际是「顾客先说预算，栋哥据此配单」。
系统设计时：预算 = 配置单的**输入参数**，不是收款科目。

### 8.6 商业建议与风险提示（本节为建议，非栋哥原话）

#### ① 定金 15% —— 方向对，但可能盖不住损失

- ✅ **无意中踩对了法律线**：民法典规定定金不得超过主合同标的额的 **20%**，超出的部分不适用定金罚则。15% 在安全区内。
- ⚠️ **必须写「定金」不能写「订金」**：「订金」在法律上视为预付款，**是要退的**。
  下单页、配置单、收据上一律用「定金」，并配「定金不退」的明示确认（勾选），不能只口头说。
- ⚠️ **15% 对「专门订货」的单子可能不够**：一台 5000 的机器，定金 750；若你已采购并拆封
  主板 / CPU（拆封后很难按原价退），顾客反悔时损失远超 750。
  ⇒ 建议分档：**现货通用件 15% 即可；需专门订货或拆封即贬值的件，提到 30%–50%**。
  或更直接：**定金 = 该单已发生的采购成本**，付定金才启动采购。

#### ② 全款退款固定扣 10% —— 建议改成按阶段

固定比例的风险：货还没拆、工还没做，也扣 10%，属于没有实际损失却扣款，容易被认定不合理。
建议分三档：

| 阶段 | 建议扣减 |
|---|---|
| 未采购、未拆封 | 全额退（或仅扣极少量手续费） |
| 已采购、未装机 | 扣**实际采购损失** + 已发生工费 |
| 已装机 | 扣 10%（整机拆装后更难二次销售，10% 合理） |

#### ③ 自带件「不质保」—— 建议换一种说法，反而是加分项

建议表述：**「自带件本身不在保修范围；本店安装工艺保修 X 天」**。
成本几乎为零（装错了本来就该返工），但顾客感受从「一概不管」变成「手艺我负责」，是廉价信任点。

#### ④ 二手保 3 个月 + 延保 —— 定价要先算，别拍脑袋

- 3 个月合理：二手件故障集中在早期失效期，3 个月正好覆盖。
- 延保建议按**售价比例**定价（如二手件售价的 10%–15%），不要一口价。
  定价前先估：该品类一年内故障率 × 平均维修成本。低于这个数就是亏钱卖保险。

#### ⑤ 代金券可找零 + 无期 —— 财务上是长期挂账，要留痕

- 「可找零」意味着存在余额概念。⇒ 界面上**不要出现「余额」「钱包」「充值」字样**，
  只叫「抵用额度」，且不提供任何充值入口 —— 避免被认定为预付卡（见 §8.3）。
- 无有效期对顾客友好，但对你是一笔长期负债。⇒ 每次使用都要留痕，定期对账。

#### ⑥ 回收拆件不转卖 —— 决定了成本分摊怎么做（系统必须解决）

不转卖 ⇒ 整机收进来，拆成零件入库。**核心难题：收购价怎么摊到每个零件？**
推荐做法：拆件时按**各零件的市场估价占比**分摊整机收购价；拆不出可用件的部分记为损耗。
⇒ 这直接决定毛利算得准不准，是「二手回收最复杂」的根因，系统设计必须覆盖。

#### ⑦ 10 公里免费 —— 边界要定死

- 「10 公里」是**直线距离还是驾车距离**？从**门店**算起还是从出发地算起？
- 10 公里外怎么收：每公里 X 元，还是阶梯（10–20km 收 30，20–30km 收 50）？
⇒ 建议**按驾车距离 + 阶梯收费**，明写在下单页，避免现场扯皮。

#### ⑧ 流程上最关键的一句话：**你不亏的关键不是定金比例，是「什么时候采购」**

只要**采购动作发生在收定金之后**，最坏情况就是「顾客跑单、你白拿 15% 定金」——
此时你没有任何成本支出，这 15% 是**零成本纯利**，不是亏损。
反过来，只要采购发生在定金之前，定金比例定到 50% 也可能亏。

⇒ 所以规则应该是：**没付定金的订单，不锁库存、不触发采购。**
专属链接做成**支付链接**：顾客点开就是「付定金 ¥XXX 确认下单」，付了钱才启动采购。
这一条是系统层面的硬要求，比调比例重要得多。

### 8.7 定金：怎么从「防亏」变成「赚钱」（02:27 栋哥追问）

#### 核心认知：跑单的定金，在未采购时是纯利，不是赔偿

同样一单 5000 元的机器，定金 750（15%）：

| 顾客跑单时你做到哪一步 | 你的结果 |
|---|---|
| 还没采购 | **+750 纯利**（零成本收入，纯赚） |
| 已采购、可退货 | 750 覆盖退货运费与折价后，大概率还有剩 |
| 已拆封、不可退 | 才真正亏 —— 这**才是**要防的情形 |

⇒ 结论：**把「已拆封不可退」这一步尽量往后推**，是比调比例更有效的风控。
现货单尽量用可退的通用件；只有确认收款后才拆封、才专门订货。

#### 四条能把定金变成利润的做法

| # | 做法 | 为什么赚钱 |
|---|---|---|
| 1 | **定金 = 采购启动金**（没付不采购） | 永不压货、永不垫资。库存周转加快本身就是利润 |
| 2 | **分档比例**：现货 15% / 需订货 30% / 定制或高价单 30%–50% 或按实际采购额收 | 高风险单由顾客承担风险，低风险单保持竞争力不影响成交 |
| 3 | **付全款立减 2%–3%**（或定金抵 1.2 倍尾款） | 一部分顾客会选全款 → 你提前拿到全部现金、省掉尾款催收与跑单风险；省下的成本 > 那 2% |
| 4 | **定金写成「方案设计费 + 采购启动金」** | 你按预算配单、询价比价的劳动本身有价值。顾客反悔，你至少为这部分劳动拿到了报酬，名正言顺 |

#### 一句话总结

> **别把定金当成"押金"，把它当成"客户筛选器 + 采购开关 + 现金流工具"。**
> 付定金的才是真客户（筛掉随口问问的）；收了定金才采购（零库存风险）；
> 引导一部分人付全款（提前回款）。这三件事加起来，比把比例从 15% 调到 30% 有用得多。
